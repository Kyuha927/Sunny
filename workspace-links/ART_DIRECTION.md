# 🎨 Pixel Agents RPG — 아트 디렉션 및 스타일 가이드

> 모든 시각 자료(에셋) 제작 시 단일 진실 공급원(SSOT)으로 사용됩니다. 모든 스프라이트, 타일, UI 요소는 이 규격을 반드시 준수해야 합니다.

---

## 1. Core Visual Identity & Vision

| 속성 | 규격 |
|---|---|
| **비전 (Vision)** | 서버 기반 멀티플레이어 룸(Room) 생태계와 연계되는 자동 바탕화면 익스텐션 |
| **최적화 (Optimization)** | **초경량 필수**. 백그라운드 플로팅 시 시스템 리소스 점유율 최소화 |
| **장르 (Genre)** | 16-bit 탑다운 액션 RPG (젤다의 전설: 신들의 트라이포스 × 파이널 판타지 VI 오버월드 느낌) |
| **시점 (Perspective)** | 약 60° 탑다운 직각 시점 (기존 JIK-A-4 에셋 앵글과 일치) |
| **분위기 (Mood)** | 영웅적이고 따뜻하며 약간의 유머가 섞인 톤 (다크 판타지 지양) |
| **세계관 은유** | VS Code(코드 편집기) = 던전 요새, 에이전트 = 영웅, 버그 = 몬스터 |

> **핵심 설계 철학**: "작은 용량으로도 최고의 디자인과 모션을 뽑아낸다." 
> 새로운 프레임을 무분별하게 추가하여 용량과 리소스를 낭비하지 않고, 기존 사이드카 JSON의 타이밍 조절(`frameDurationSec`)과 코드 기반 보간(`bob`, `sway`, `offset`)을 극대화하여 모션의 질감과 타격감을 살립니다.

## 2. 기술적 제약 사항 (절대 규칙)

### 2.1 스프라이트 그리드 제약

| 에셋 유형 | 셀 크기 (px) | 시트 레이아웃 | 비고 |
|---|---|---|---|
| **캐릭터** | 16×32 | 112×96 (가로 7프레임 × 세로 3방향) | 0행=down, 1행=up, 2행=right; left는 코드에서 런타임 좌우반전 |
| **바닥 타일** | 16×16 | 112×16 (7가지 패턴) | 그레이스케일, 런타임에서 컬러 색조 적용 |
| **벽 타일** | 16×32 | 64×128 (4×4 비트마스크 그리드) | 16가지 형태를 가진 오토타일(Auto-tile) 시스템 |
| **가구 장식** | 가변 | 개별 PNG + manifest.json | 최대 2×2 타일 (보스급 몬스터 제외) |
| **말풍선** | 11×13 | JSON 픽셀 데이터 포맷 | 권한 요청(permission), 대기(waiting) 알림용 |

### 2.2 캐릭터 세부 프레임 슬롯 (7프레임 × 3방향)

| 슬롯 인덱스 | RPG 모션 의미 | 포즈 세부 묘사 |
|---|---|---|
| `0` | 순찰(Patrol) 스텝 A | 무기를 허리춤에 차거나 든 채, 앞발을 내딛는 동작 |
| `1` | 기본 대기(Neutral) | 무기를 든 상태로 균형 잡힌 기본 서있기 (대기/휴식 모션 베이스) |
| `2` | 순찰(Patrol) 스텝 C | 프레임 0과 반대 발을 내딛는 동작 |
| `3` | 공격/캐스팅 A | 무기를 들어 올리거나 마법 영창을 시작하는 준비 동작 |
| `4` | 공격/캐스팅 B | 무기를 휘두른 직후이거나 마법 폭발 이펙트 프레임 |
| `5` | 정찰/스캔 A | 지도나 두루마리를 펼치고 들여다보는 동작 |
| `6` | 정찰/스캔 B | 돋보기를 들거나 탐색을 계속하며 흔들거리는 동작 |

### 2.3 픽셀 아트 렌더링 규칙 (협상 불가)

1. **1px 검은색 외곽선** — 가독성과 배경 구분을 위해 모든 스프라이트에 필수 (단, 그림자는 예외)
2. **캐릭터당 색상 4개 제한** — 외곽선(검정), 피부색, 주색상(갑옷 등), 부색상(무기/포인트 색)
3. **단일 영역당 3색상 제한** — 몸통, 외곽선, 포인트 수식어 하나로 구성
4. **최소 형태 크기 2px** — 직업 특징을 나타내는 주요 요소는 단일 픽셀로 표현하지 않음
5. **실루엣 테스트 필수** — 검은색으로 실루엣만 칠해도 어떤 직업인지 구별 가능해야 함
6. **고대비 무기 식별** — 무기 파트는 몸체와 명도(Luminance) 차이가 40% 이상 나도록 구성
7. **비대칭 금지** — 코드에서 우측을 좌우 반전해 좌측으로 쓰므로, 짝짝이 장비나 확연한 비대칭 디자인 지양
8. **안티 앨리어싱 금지** — 절대적인 계단현상(하드 엣지)만 사용. Nearest-neighbor 스케일링 전제

## 3. 색상 시스템 (Color System)

### 3.1 글로벌 던전 환경 팔레트 (CSS 변수)

| 토큰 | Hex 코드 | 용도 |
|---|---|---|
| `--pixel-bg` | `#1a1412` | 어둡고 따뜻한 던전 석재 바닥 배경 |
| `--pixel-surface` | `#3a302a` | 중첩된 패널이나 돌출된 표면 색상 |
| `--pixel-border` | `#594a42` | 횃불에 비친 듯한 밝은 테두리 및 그림자 |
| `--pixel-accent` | `#eab308` | 마법적인 호박색/황금색 하이라이트 지점 |
| `--pixel-green` | `#4ade80` | 신비로운 숲이나 독/치유 계열 초록 |

### 3.2 영웅 직업군(Class) 팔레트

| 직업군 | 베이스 이미지 | 분위기 / 톤 | 주색상 | 부색상 | 틴트(조명 보정) |
|---|---|---|---|---|---|
| **기사 (Knight)** | `char_0` | 강철 파랑, 안정감 | `#4A7CB5` | `#C0C8D8` | `#C0D8FF` |
| **마법사 (Mage)** | `char_1` | 보라/바이올렛, 신비 | `#7B4EAF` | `#D4B8E8` | `#E0C0FF` |
| **궁수 (Ranger)** | `char_2` | 짙은 숲 초록, 민첩 | `#3D8B4F` | `#8BC49A` | `#C0FFD0` |
| **사제 (Cleric)** | `char_3` | 황금색/호박색, 성스러움 | `#C49B30` | `#F0D888` | `#FFF0C0` |
| **도적 (Rogue)** | `char_4` | 진홍색/붉은 피, 기습 | `#B04040` | `#D88888` | `#FFC0C0` |
| **기공사 (Artificer)**| `char_5` | 구리/청록, 공학적 | `#4A9B8B` | `#88C4B8` | `#C0FFF0` |

> *참고*: 7번째 이상의 에이전트가 스폰되면 기존 코드의 `hueShift` 시스템에 의해 이 팔레트 색상환이 무작위(45~315도)로 돌아가며 변형됩니다. 기본 이미지가 무지개색을 타지 않게 명확한 톤으로 잡혀있어야 합니다.

## 4. 애니메이션 프로파일 (Sidecar JSON)

> **CRITICAL**: 기존의 `CharacterAnimationProfile` JSON 구조와 데이터 모델을 절대로 수정하지 마세요. 비주얼적인 해석만 바꿉니다.

### 4.1 상태 매핑 (기존 Office → 신규 RPG)

| 기존 모션 식별자 | 기존 오피스에서의 의미 | **RPG에서의 새로운 의미** | 시각적 묘사 가이드 |
|---|---|---|---|
| `idle` | 제자리에 서있기 | **방어 대기 (Guarding/Resting)** | 무기를 거두거나 가드 자세로 숨쉬며 작게 위아래로 흔들리기 |
| `walk` | 사무실 돌아다니기 | **순찰 (Patrolling/Questing)** | 무기를 들고 이동하며, 약간의 흙먼지 연출 가능성 |
| `typing` | 코드 타이핑 진행 중 | **전투/공격/캐스팅 (Attacking)** | 무기를 크게 휘두르거나, 마법 타격 이펙트 집중 발발 |
| `reading` | 파일 읽기 / 검색 중 | **정찰/스캔 (Scouting)** | 지도나 마법 스크롤을 들고 집중해서 살펴보는 모션 |

### 4.2 직업별 모션 개성 파라미터 튜닝 방향

무거운 모션 프레임을 추가하지 않고 JSON 수치만 조절해 극한의 프레임 우려내기를 수행합니다:

- **기사**: `frameDurationSec`(공격)을 0.28 전후로 무겁게. `bobPx`(숨쉬기)는 0.4로 단단하게.
- **마법사**: 타이밍을 0.18로 약간 부유(Float)하게 세팅. `swayPx` 및 `bobPx`를 크게 할당해 공중에 떠 있는 느낌 연출.
- **궁수/도적**: 타이밍을 0.1~0.12로 cực단적으로 빠르게 튕기는 듯한(Snap) 타격감.
- **사제**: 느리고 리드미컬한 `frameDurationSec`(0.30), 부드러운 `sway` 진자 운동.

## 5. 에셋 생성 파이프라인 워크플로우

> `HANDOFF_PIXEL_AGENTS.md` 지침에 따라 엔진과 메커니즘 변경을 금지하고, 파이프라인을 통해서만 아트를 교체합니다.

1. **생성/스케치**: 8배 확대 그리드를 활용해 캐릭터 실루엣 우선 확인.
2. **팔레트 매핑**: 직업별 팔레트(4색) 규정에 맞춰 일괄 색상 치환.
3. **프레임 배치**: 7프레임 112×96 규격의 템플릿 슬롯에 안착.
4. **반전 오류 체크**: 시트를 좌우 반전해보며 부자연스러운 비대칭 요소 즉시 수정.
5. **JSON 파라미터 디버깅**: 코드의 밥/스웨이/오프셋(Bob, Sway, Offset) 보간 수치를 적용해 최적의 모션 도출.

### 5.1 검증 체크리스트 (에셋 저장 전 자체 검사)
- [ ] 1px 검은색 외곽선(그림자 제외)이 모든 외곽에 적용되었는가?
- [ ] 캐릭터당 4색(외곽선 포함) 이하로 컬러를 억제했는가?
- [ ] 단일 색상으로 칠한 실루엣만으로 직업 특징이 구별되는가?
- [ ] 직업 상징 무기/도구의 명도 대비차가 베이스 몸체와 명확한가?
- [ ] 안티 앨리어싱이나 중간 블러 픽셀이 없는가?
- [ ] 정확한 16×32 규격 이내이며 하단 정렬(Bottom-center anchor)이 일치하는가?

## 0) 증상부터 딱 3가지로 분기
아래 중 **어느 쪽**이야?

1) **VS Code 창이 아예 안 뜸** / 잠깐 뜨고 꺼짐  
2) **창은 뜨는데 멈춤(흰 화면/로딩 무한/입력 안됨)**  
3) **특정 기능만 안됨** (터미널/WSL/확장/깃/디버그 등)

일단 공통으로 “가장 자주 해결되는” 순서로 간다.

---

## 1) VS Code 완전 종료 + 재실행 (가장 흔함)
1. `Ctrl + Shift + Esc` → 작업 관리자
2. **Code.exe / Visual Studio Code / Electron** 관련 있으면 전부 “작업 끝내기”
3. 다시 실행

---

## 2) 확장(Extensions) 때문에 죽는지 확인: “확장 없이 실행”
### 방법 A (가장 쉬움)
- **Shift** 누른 채로 VS Code 실행 → “확장 비활성화로 실행” 뜨면 선택

### 방법 B (명령)
PowerShell에서:
```powershell
code --disable-extensions
```
✅ 이 상태에서 정상 뜨면: **확장 문제** 확률 매우 높음  
→ 최근 설치/업데이트한 확장부터 꺼서 범인 찾으면 됨.

---

## 3) 사용자 설정/캐시 깨졌을 때: “User 데이터 임시로 우회”
VS Code 완전 종료 후, PowerShell:
```powershell
$u="$env:APPDATA\Code"
Rename-Item "$u\User" "User.bak_$(Get-Date -Format yyyyMMdd_HHmmss)" -ErrorAction SilentlyContinue
Rename-Item "$u\Cache" "Cache.bak_$(Get-Date -Format yyyyMMdd_HHmmss)" -ErrorAction SilentlyContinue
Rename-Item "$u\CachedData" "CachedData.bak_$(Get-Date -Format yyyyMMdd_HHmmss)" -ErrorAction SilentlyContinue
```
그 다음 VS Code 실행.

(이건 **설정/스니펫/키바인딩** 등을 잠깐 초기화해서 부팅부터 살리는 용도야. 나중에 `User.bak_*`에서 필요한 파일만 복구 가능)

---

## 4) GPU/그래픽 가속 문제(흰 화면/검은 화면/먹통)일 때
PowerShell:
```powershell
code --disable-gpu
```
✅ 이걸로 살아나면: 그래픽 가속/드라이버 충돌 가능성 큼  
→ 이후 설정에서 **GPU 가속 끄기**로 고정.

---

## 5) 업데이트/설치 꼬임: “Repair/재설치” 전에 하는 최소 조치
1) 윈도우 재부팅(진짜로 Electron 프로세스 꼬임 풀림)  
2) VS Code가 **MS Store 버전**이면: Store 업데이트 / “복구(Repair)”  
3) 일반 설치 버전이면: “앱 및 기능”에서 **수정(Repair)** 있으면 먼저

---

## 6) WSL/터미널만 안 되는 경우(별도 분기)
- VS Code는 뜨는데 **WSL 연결이 안 된다 / 터미널이 안 열린다**면:
  - `wsl -l -v` 실행이 되는지
  - 최근 Windows 업데이트 후 WSL이 꼬였는지
  - “Remote - WSL” 확장 문제인지
이건 로그 한 줄만 보면 바로 잡아줄 수 있어.

---

## 4. assistant

좋아. `code --version`은 정상이라 **설치/CLI는 살아있고**, 지금은 **실행만(또는 UI 쪽) 문제가 남아있는 상태**야.

지금 `code --disable-extensions` 치고 나서 보통 3가지 중 하나야:

- A) **창이 정상 뜬다** → 확장 문제 확정  
- B) **아무 반응 없다** → 기존 Code 프로세스/창이 꼬였거나, GPU/유저데이터/백그라운드 락  
- C) **잠깐 뜨고 꺼진다 / 흰화면** → GPU/캐시/유저데이터 쪽 확률 큼

아래를 위에서부터 **그대로** 해봐. (가장 빨리 잡히는 순서)

---

## 1) Code 프로세스 싹 죽이고 다시 띄우기
PowerShell(관리자 아니어도 됨):

```powershell
taskkill /F /IM Code.exe /T
```

그 다음:

```powershell
code --disable-extensions
```

---

## 2) GPU까지 같이 끄고 띄우기 (흰화면/무반응에 특히 잘 먹힘)
```powershell
code --disable-extensions --disable-gpu
```

✅ 이걸로 뜨면: 그래픽 가속/드라이버 이슈 가능성 큼 → 이후 VS Code 설정에서 GPU 가속을 꺼서 고정하면 됨(지금은 일단 살리는 게 우선).

---

## 3) 사용자 데이터/캐시 꼬임 우회 (거의 “최후의 한 방”)
VS Code 완전 종료(위 taskkill 한 뒤)하고 실행:

```powershell
$u="$env:APPDATA\Code"
Rename-Item "$u\User" "User.bak_$(Get-Date -Format yyyyMMdd_HHmmss)" -ErrorAction SilentlyContinue
Rename-Item "$u\Cache" "Cache.bak_$(Get-Date -Format yyyyMMdd_HHmmss)" -ErrorAction SilentlyContinue
Rename-Item "$u\CachedData" "CachedData.bak_$(Get-Date -Format yyyyMMdd_HHmmss)" -ErrorAction SilentlyContinue
code --disable-extensions
```

---

## 4) “왜 안 뜨는지” 로그 바로 뽑기 (여기서 1줄이면 범인 나옴)
```powershell
code --disable-extensions --verbose
```

그리고 아래 폴더에 최신 로그가 생김:
- `%APPDATA%\Code\logs\` (탐색기 주소창에 그대로 붙여넣기)

가장 최신 폴더 들어가서 **`main.log` 마지막 30줄**만 복붙해줘.

## 6. assistant

오케이. 그럼 **확장(Extension) 중 하나가 범인**이야. 다시 켜는 방법은 2가지.

## 1) 그냥 “정상 실행”으로 켜기 (가장 간단)
지금처럼 옵션 없이 실행하면 확장이 다시 켜져:
```powershell
code
```
또는 시작 메뉴에서 **Visual Studio Code** 그냥 실행.

---

## 2) VS Code 안에서 다시 켜기
1. VS Code에서 `Ctrl + Shift + P`
2. `Extensions: Enable All Extensions` 실행  
   - (전체를 한 번에 켜짐)

---

## 범인 찾는 빠른 루트(추천)
전체 켜면 다시 죽을 수 있으니까:

1. `Ctrl + Shift + X` (확장 탭)
2. **최근 설치/업데이트/Enabled** 정렬해서
3. 의심 확장부터 **Disable**  
4. VS Code 재시작해서 확인

---

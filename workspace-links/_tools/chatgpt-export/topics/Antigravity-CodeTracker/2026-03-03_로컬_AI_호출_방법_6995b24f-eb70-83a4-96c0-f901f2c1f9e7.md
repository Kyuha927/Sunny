### 3️⃣ 간단한 음성 → 로컬 AI 호출 코드

```python
import sounddevice as sd
import numpy as np
from faster_whisper import WhisperModel
import subprocess

model = WhisperModel("base")

def record(seconds=5, fs=16000):
    print("🎤 듣는 중...")
    audio = sd.rec(int(seconds * fs), samplerate=fs, channels=1)
    sd.wait()
    return audio.flatten(), fs

def transcribe(audio, fs):
    segments, _ = model.transcribe(audio)
    return " ".join([seg.text for seg in segments])

audio, fs = record()
text = transcribe(audio, fs)

print("인식:", text)

# 로컬 LLM 호출
subprocess.run(["ollama", "run", "llama3", text])
```

말하면 → 텍스트 변환 → 로컬 AI 실행됨.

# 2) PC가 꺼져있을 때 켜기: WOL 세팅 체크리스트
## BIOS/UEFI
- Wake on LAN / PCIe device wake: **Enabled**
- ErP(절전 극대화): **Disabled** (이게 켜져 있으면 WOL 안 되는 경우 많음)

## Windows
- 장치관리자 → 네트워크 어댑터 → 전원관리
  - “이 장치가 컴퓨터를 깨울 수 있음” 체크
- “빠른 시작 켜기”는 WOL 꼬이면 **끄는 편**이 안정적

## 네트워크
- WOL은 보통 **같은 LAN 내부**에서 가장 안정적  
- 외부(밖)에서 켜고 싶으면:
  - Home Assistant를 **VPN(Tailscale 등)** 으로 집에 붙이는 방식 추천 (포트포워딩보다 안전)

# 4) 트리거(“실행”)가 들어오면 자동으로 PC 켜고 OpenClaw 실행
Home Assistant 자동화(Automation)에서 이렇게:
1) **WOL 패킷 보내기**
2) PC가 온라인(핑/포트) 될 때까지 대기
3) PC로 “작업 실행” 명령 전달

PC 쪽은 두 가지 중 하나로 받으면 돼:
- (쉬움) **HTTP 서버(로컬)** 하나 띄워서 `/run` 호출하면 OpenClaw 실행  
- (더 깔끔) **MQTT**로 메시지 받아 실행

# 5) “몇 분 뒤 자동 종료”는 2가지 방식
## A) 타이머로 강제 종료(단순)
- 실행 시작과 동시에 “N분 뒤 shutdown 예약”
- 작업이 빨리 끝나도 PC는 N분 뒤 꺼짐

## B) 작업 완료/유휴 기준 종료(추천, 디버깅 확률↓)
- OpenClaw 실행 스크립트가 끝나면:
  - “완료” 신호를 Home Assistant로 보내고
  - PC는 즉시 종료(또는 2~3분 유예 후 종료)
- 혹은 “큐 비었고 N분 유휴”면 종료

# 6) 보안/오작동 방지(중요)

# 7) 현실적인 “최소 구현” 추천 조합

## PROMPT 2 — (Home Assistant Executor) “큐 + 트리거 + WOL + PC 온라인 대기 + 실행 호출 + 자동 종료”

- **완전 종료(Shutdown) 상태에서 깨우기**: 기종/BIOS/전원옵션에 따라 안 되는 경우 많음

- **현실적인 추천**:  
  - “완전 종료” 대신 **절전/최대절전(hibernate)** 을 기본 상태로 두고 트리거 시 깨우기  
  - 끝나면 다시 절전/최대절전으로 보내기

즉: **데스크탑=Shutdown→WOL이 쉬운 편 / 노트북=Sleep/Hibernate 기준이 더 안정적**.

## 모바일 VS Code는 뭐가 되나? (모바일 vs 데스크탑)
모바일에서 말하는 “VS Code”는 보통 3가지 형태야:

### 1) vscode.dev (브라우저에서 VS Code)
- ✅ 깃허브 리포 열기/수정/커밋(토큰 필요)
- ✅ 가벼운 코드 편집, 검색, 멀티 파일 편집

- ❌ 네 PC 파일시스템 직접 접근 불가(브라우저 샌드박스)

### 2) GitHub Codespaces (브라우저/앱에서 “진짜 리눅스 개발환경”)
- ✅ 터미널, 의존성 설치, 실행, 테스트, 디버깅 가능(대부분)

- ✅ 모바일에서 “실제 개발” 가장 현실적
- ❌ 유료/과금 이슈 + 네 로컬 PC 자원은 안 씀(클라우드 자원)

### 3) 노트북(데스크탑) VS Code + Remote 계열(SSH/WSL/Tunnels)
- ✅ 기능 풀세트(디버거/터미널/확장/테스트)
- ✅ 네 로컬 PC/WSL/서버에 붙어서 “원격 개발” 가능
- ✅ 자동화(OpenClaw/스크립트)랑 결합이 제일 쉬움
- ❌ 모바일만으로는 설정/권한/네트워크가 번거로움

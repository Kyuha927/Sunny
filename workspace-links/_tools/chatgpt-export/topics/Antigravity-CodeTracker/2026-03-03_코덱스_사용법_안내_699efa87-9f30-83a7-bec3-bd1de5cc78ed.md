## 2. assistant

코덱스(코딩 에이전트/코드 생성 모델)를 “잘 쓰는 법”은 한마디로 **프롬프트를 ‘요구사항’이 아니라 ‘작업지시서(작업계약)’로 쓰는 것**이에요. 아래 템플릿 그대로 쓰면 바로 체감 납니다.

---

## 1) 코덱스에 제일 잘 먹는 입력 구조 (복붙 템플릿)

```text
[GOAL]
무엇을 만들/수정할지 1~2문장.

[CONTEXT]
- 프로젝트/언어/프레임워크:
- 현재 상태(파일/모듈/엔트리포인트):
- 제약(버전, 금지사항, 성능/보안, 스타일):

[TASK]
1) 해야 할 일 (구체적으로)
2) 해야 할 일
3) …

[ACCEPTANCE CRITERIA]
- 테스트/실행 커맨드:
- 성공 조건(로그/출력/성능/UX):
- 엣지케이스 2~5개:

[FILES]
- 수정할 파일:
- 새로 만들 파일:

[OUTPUT FORMAT]
- PATCH LIST
- READY-TO-PASTE CONTENT
- CHECKS
```

**포인트:** “뭘”보다 “언제 성공인지(AC)”를 먼저 박아두면 코덱스가 삽질을 덜 해요.

---

## 2) 실패를 확 줄이는 7가지 규칙

### (1) “하나의 엔트리포인트”를 지정
- 예: `./dev` 또는 `.\dev.ps1` 같은 단일 진입점  
- 코덱스가 여기저기 실행 커맨드 만들지 않게 막음

### (2) “금지사항”을 명시
- 예: “새 의존성 추가 금지”, “DB 스키마 변경 금지”, “외부 API 호출 금지”
- 안 적으면 코덱스는 쉽게 새로운 라이브러리부터 들이밉니다.

### (3) “증거”를 요구
- 예: “테스트 통과 로그 마지막 20줄 + git status 첨부”
- 결과를 “말”로만 안 끝내게 함

### (4) 작은 단위로 쪼개서 “패치 1개 = 검증 1개”
- 한 번에 큰 리팩터링 시키면 80% 확률로 디버깅 지옥

### (5) “리그레션 테스트”를 반드시 포함
- “고쳤다”가 아니라 “다시는 안 깨진다”로 고정

### (6) 에러나면 “원인 3개 + 가장 유력 1개 + 다음 행동 1개”
- 코덱스가 재시도 루프에 빠지는 걸 방지

### (7) 출력 형식을 고정
- 너는 이미 선호가 있음: `PATCH LIST / READY-TO-PASTE CONTENT / CHECKS`
- 이거 강제하면 리뷰 시간이 확 줄어요.

## 3) 실전 프롬프트 예시 3개

### A) “버그 수정 + 재발 방지(테스트 포함)”
```text
[GOAL]
로그인 후 간헐적으로 세션이 풀리는 버그를 수정한다.

[CONTEXT]
- Python 3.12.x
- FastAPI + Redis session
- 재현: /login -> /me 호출 시 5~10% 401
- 금지: 의존성 추가 금지, 세션 스키마 변경 금지

[TASK]
1) 원인 후보를 로그/코드 흐름 기준으로 3개 제시하고, 가장 유력한 원인부터 패치한다.
2) 재현 테스트(통합/유닛 중 적절한 것) 1개를 추가한다.
3) 로깅/가드레일을 추가해 재발 시 즉시 탐지되게 한다.

[ACCEPTANCE CRITERIA]
- pytest 통과
- 200회 반복 호출에서도 401이 0회
- 실패 시 어떤 키/TTL이 문제인지 로그로 바로 보일 것

[OUTPUT FORMAT]
PATCH LIST
READY-TO-PASTE CONTENT
CHECKS(실행 커맨드 + 기대 결과)
```

### B) “기능 추가(스펙 고정)”
```text
[GOAL]
설정 파일(.json)에서 feature flag를 읽어 UI 버튼을 토글한다.

[CONTEXT]
- React + Vite
- 금지: 전역 상태 라이브러리 추가 금지

[TASK]
1) config 로더 구현(캐시 포함)
2) 컴포넌트에 적용
3) e2e 대신 unit test 2개

[ACCEPTANCE CRITERIA]
- flag=true면 버튼 보임, false면 숨김
- config 없으면 기본값 false
```

### C) “대규모 변경”을 안전하게
```text
[GOAL]
레거시 모듈 A를 모듈 B로 점진 교체한다(빅뱅 금지).

[TASK]
1) 어댑터 레이어 추가
2) 호출부 1곳만 먼저 전환
3) 메트릭/로그 추가
4) 2단계 롤아웃 플랜 작성
```

## 4) 너(지훈) 케이스에 맞춘 “코덱스 지시” 추천 포맷

```text
[NON-NEGOTIABLES]
- 디버깅 확률을 낮추는 방향(가드레일/로깅/재현/테스트) 우선
- 변경은 작게, 단계적으로
- 새 의존성은 원칙적으로 금지(필요 시 이유+대안 2개)
- 결과는 반드시 증거(테스트 로그/명령어/출력)
```

## 4. assistant

코덱스에 “사용 환경”을 제대로 주면, 삽질/가정이 확 줄어요. 아래 **환경 섹션 템플릿** 그대로 복붙해서 채워 넣으면 됩니다.

```text
[ENVIRONMENT]
- OS: Windows 11 (PowerShell 7.x) / macOS / Ubuntu (버전)
- Shell: powershell / bash / zsh
- Repo root: (예: C:\Users\...\msw2)
- Language & runtime:
  - Python: 3.12.x (필수) / Node: 20.x / Lua: ...
- Package/Build:
  - pip/uv/poetry (무엇 사용)
  - npm/pnpm/yarn (무엇 사용)
- Entry points (단일 진입점):
  - Windows: .\dev.ps1
  - *nix: ./dev
- Test command:
  - (예: .\dev.ps1 test) / (예: pytest -q) / (예: pnpm test)
- Lint/format:
  - (예: ruff/black) / (예: eslint/prettier)
- CI:
  - GitHub Actions / GitLab CI / 없음
- Constraints (금지/제약):
  - 새 의존성 추가 금지 여부
  - 네트워크 호출 금지 여부
  - 파일/폴더 구조 변경 금지 여부
  - 성능/메모리 목표
- Evidence required:
  - git status
  - 실행 로그 마지막 20줄
```

너는 이미 워크플로가 꽤 명확하니까(단일 엔트리포인트/증거 요구/파이썬 3.12 고정), 코덱스에는 이렇게 “고정 규칙”을 같이 붙이는 게 제일 좋아요.

```text
[NON-NEGOTIABLES]
- Python 3.12.x만 허용
- 실행/검증은 반드시 .\dev.ps1 또는 ./dev로만
- 출력은 PATCH LIST / READY-TO-PASTE CONTENT / CHECKS
- 결과에는 증거 포함: git status + (테스트/체크 로그 마지막 20줄)
```

원하면 네 실제 환경 기준으로 내가 위 템플릿을 **한 번에 완성**해줄게.  
지금 기준이 **윈도우 + PowerShell** 맞고, repo는 `msw2`가 메인인 거 맞아? (맞으면 경로/파이썬 위치/엔트리포인트까지 포함해서 “완성본” 만들어줄게.)

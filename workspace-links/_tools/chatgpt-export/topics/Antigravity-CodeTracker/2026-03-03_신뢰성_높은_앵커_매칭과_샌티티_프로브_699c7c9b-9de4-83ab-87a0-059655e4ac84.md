# 왜 앵커가 중요한가
이미지나 텍스트(OCR)만 믿고 클릭/드래그를 실행하면, 해상도·회전·테마·패널 위치 변화 때문에 금방 깨집니다. 그래서 **“빠른 대략 탐색 → 견고한 검증 → 시스템 레벨 대안”**의 3단 분기 구조가 필요합니다.

# 1) 빠른 앵커: 멀티스케일 템플릿 매칭
- **기술**: `cv2.matchTemplate()`를 다중 스케일(피라미드)로 돌리고, **에지 기반(캐니 등)** 전처리 후 **NMS(비최대 억제)** 로 중복 제거.
- **팁**
  - 템플릿은 **여러 버전**을 준비(밝기/테마/DPI/로캘).
  - 스코어는 “탐색 윈도우”로 사용(예: `0.7~0.9`), 확신 낮으면 다음 단계로 승격.
  - 결과 좌표에 **소량의 안전 마진**을 두고 클릭 지점 산출.

```python
import cv2, numpy as np

def multiscale_match(image_bgr, tmpl_bgr, scales=(1.0, 0.9, 0.8, 1.1)):
    img = cv2.Canny(cv2.cvtColor(image_bgr, cv2.COLOR_BGR2GRAY), 50, 150)
    t   = cv2.Canny(cv2.cvtColor(tmpl_bgr,  cv2.COLOR_BGR2GRAY), 50, 150)

    hits = []
    for s in scales:
        ts = cv2.resize(t, None, fx=s, fy=s, interpolation=cv2.INTER_AREA)
        res = cv2.matchTemplate(img, ts, cv2.TM_CCOEFF_NORMED)
        ys, xs = np.where(res >= 0.72)  # 탐색 임계
        for (x, y) in zip(xs, ys):
            hits.append((float(res[y, x]), (x, y, ts.shape[1], ts.shape[0])))

    # 간단 NMS
    hits.sort(key=lambda h: h[0], reverse=True)
    picked = []
    for score, (x, y, w, h) in hits:
        if all( (abs(x-x2)>w*0.5 or abs(y-y2)>h*0.5) for _,(x2,y2,w2,h2) in picked ):
            picked.append((score,(x,y,w,h)))
    return picked  # [(score, (x,y,w,h)), ...]
```

# 2) 견고한 업그레이드: 키포인트 + 기하 검증
- **언제?** 템플릿 매칭 스코어가 애매하거나 회전/부분가림/원근이 있는 경우.
- **기술**: ORB(무료) 또는 SIFT(정밀)로 특징점 매칭 → **RANSAC**으로 호모그래피 추정 → 매칭 사각형이 정상일 때만 채택.
- **포인트**
  - 매칭 수, 인라이어 비율, 사각형 왜곡(면적·각도)으로 **신뢰도 스코어** 산출.
  - 성공 시 호모그래피로 버튼 중심 좌표를 정확히 복원.

# 3) 접근성(Accessibility) 폴백: HWND/UIA가 최종 권위
- **아이디어**: 이미지가 애매하면, **윈도우 핸들(UIA/pywinauto)** 로 해당 컨트롤의 **BoundingRect** 를 가져와 클릭.
- **장점**: 테마·스케일 변화에 둔감, 다국어/OCR 이슈 회피.
- **파이썬 예시(개념)**:
```python
# pip install pywinauto
from pywinauto import Desktop

app = Desktop(backend="uia")
win = app.window(title_re=".*MyApp.*")
ctrl = win.child_window(title="Play", control_type="Button")
rect = ctrl.rectangle()  # (l,t,r,b)
cx, cy = (rect.left+rect.right)//2, (rect.top+rect.bottom)//2
# 이제 (cx, cy)을 클릭 좌표로 사용
```

# 4) “작동 확인용” 미니 프로브 스크립트 추천

- **A. 환경/인코딩 체크**: 콘솔 코드페이지, 폰트, 로캘. (CP949 출력 예외 방지: `PYTHONIOENCODING=utf-8` 권장)
- **B. OpenCV 멀티스케일 매치**: 스코어/좌표/NMS 결과를 표로 출력.
- **C. UIA 탐색**: 타이틀로 HWND 잡고 “Play” 같은 컨트롤 **BoundingRect** 출력.
- 실행 예:  
  `python sanity_probe.py --template t.png --title "MyApp"`

이렇게 하면 “이미지 매칭이 실패인지 / 윈도우 포커스 문제인지 / 인코딩 예외인지”를 **한 번에** 가늠할 수 있어요.

# 5) 안정성 체크리스트
- 화면 캡처 전 **타겟 창을 최상단/포커스** 로(Alt+Tab, Win32 SetForegroundWindow).
- 스케일링(예: 125%)·다크모드·언어별 템플릿 **동봉**.
- 클릭 전 마지막으로 **UIA 폴백 가용성** 확인: 가능하면 UIA가 정답.
- 로그: (원본 캡처, 매칭 스코어, 최종 선택 경로: template/ORB/UIA) 를 **항상 저장**.
- 타임아웃/재시도: 저품질 스코어면 **즉시 승격(템플릿→키포인트→UIA)** 하여 시간 낭비 축소.

# 6) 바로 가져다 쓸 실행 흐름(요약)
1) 스크린샷 → 멀티스케일 템플릿 매칭(에지/NMS)  
2) 스코어 애매 → ORB/SIFT + RANSAC로 승격  
3) 여전히 애매 → **UIA로 해당 컨트롤 Rect 사용(최종 권위)**  
4) 좌표 클릭 → 성공 로깅(증거 캡처 & 경로)

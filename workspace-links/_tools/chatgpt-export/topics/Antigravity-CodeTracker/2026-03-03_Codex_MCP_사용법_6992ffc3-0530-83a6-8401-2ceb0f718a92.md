## 🛠️ 3. MCP 서버 설정

### ✔ 3-1. `config.toml` 직접 등록 (공통 설정)

Codex 확장 및 CLI 공통으로 사용하는 설정 파일입니다.

경로:  
```
~/.codex/config.toml
```

```toml
[mcp_servers.my-server]
command = "npx"
args = ["-y", "@example/mcp-server"]
```

- `mcp_servers.이름` – 서버 식별자  
- `command` – 실행 명령 (보통 `npx`)  
- `args` – 설치/실행 인자 배열 citeturn0search4turn0search27

**참고 예시**  
```toml
[mcp_servers.playwright]
command = "npx"
args = ["-y", "@playwright/mcp"]
```
이렇게 설정하면 Playwright 도구 MCP가 로드됩니다. citeturn0search26

## 1) “리소스/템플릿이 비어있는” 가장 흔한 이유 3가지

### A. 이 MCP 서버는 애초에 **Resources/Templates를 제공하지 않고 Tools만 제공**
MCP 서버 구현에 따라:
- `resources` / `resourceTemplates` 는 **안 내보내고**
- `tools` 만 내보내는 서버가 꽤 많아.

→ 그래서 `list_mcp_resources → []`, `list_mcp_resource_templates → []` 가 **정상**일 수 있어.

### B. 인증은 됐지만 **권한(scope)이 제한**되어 목록 API가 빈 배열로 내려오는 케이스
401/403이 아니라 “[]”로 내려오는 구현도 있어.

### C. Codex 확장(클라이언트)이 **Tools 목록을 UI에 따로 보여주지 않거나**, 특정 명령으로만 노출
리소스/템플릿은 바로 확인되는데, tools는 별도 명령/뷰에서 확인해야 하는 경우가 있어.

---

## 2) 다음 단계: “툴이 있는지”를 확인해야 함 (핵심)
지금 네가 확인한 건 **리소스/템플릿** 뿐이야.  
진짜 중요한 건 **Tools 목록**이야.

Codex에서 아래 중 가능한 걸 순서대로 해봐:

### (1) MCP 서버 정보/툴 목록 보기 명령
Codex 채팅창에 다음을 하나씩 시도:
- `/mcp`
- `/tools`
- `list_mcp_tools` (혹은 비슷한 명령이 있을 수 있음)

> Codex 빌드/버전에 따라 명령 이름이 조금씩 달라서, “툴 목록”을 보여주는 커맨드를 찾아야 해.

### (2) “툴 호출 유도” 테스트
툴 목록이 안 떠도, 아래처럼 **Codex가 tool call을 해야만** MCP가 움직이기도 해.

예시 프롬프트(그대로 붙여넣기):
- **“MSW-MCP에 연결된 tool이 있으면, 가능한 tool 목록을 조회해줘. 조회가 안 되면 서버 메타데이터(버전/기능)를 요청해줘.”**
- **“MSW-MCP 서버에 대해 tools capability가 있는지 확인하고, 있다면 tool 이름을 출력해줘.”**

Codex가 내부적으로 tool-call을 시도하면서 뭔가 반응이 나오면, 도구는 살아있는 거야.

---

## 3) 그래도 tools가 0개면: 서버 측/인증 문제를 의심
이 경우는 크게 두 갈래야:

### A) 서버가 정말 tools/resources/templates를 “아무것도” 노출하지 않는 디자인
(예: 특정 라우팅/엔드포인트에서만 노출, 또는 내부 전용)

### B) Authorization 헤더는 맞는데, **토큰이 만료/폐기/권한 부족**
- 에러가 났다면(401/403/500) Codex 로그나 Output 패널에 흔적이 남는 경우가 많아.
- “[]”만 오면 더 애매해서, 서버 운영팀 문서/권한을 확인해야 해.

## 4) 제일 빠르게 원인 확정하는 방법
너가 지금 Codex에서 확인 가능한 정보는 **딱 2개**만 있으면 돼:

1) `/mcp` 결과 전문(서버가 “connected / error”로 뜨는지)  
2) Codex의 **MCP 로그/Output**에 뜨는 에러 (401/403/404/handshake error 등)

> 토큰/민감정보는 가리고(마스킹) 보내줘.  
> URL은 괜찮지만 Authorization 값은 절대 그대로 붙이지 마.

# MCP 통합 빠른 점검 체크리스트

- **기본 URL & TLS 확인**
  - `mcp.json`의 `url`이 실제 엔드포인트와 정확히 일치하는지(슬래시, 서브패스 포함).
  - HTTPS 필수(자체 서명 인증서면 클라이언트 신뢰 설정 필요).

- **Authorization 헤더 형식 검증**
  - 정확한 스펠링과 공백: `Authorization: Bearer <토큰>`
  - 토큰에 개행/공백 섞여 있지 않은지, 만료 여부.

- **인증된 상태로 “살아있는 리소스”를 직접 확인**
  - 서버가 리소스/템플릿을 안 노출하는 구현도 있으므로, **인증된 API 콜**로 실제 동작 가능한 엔드포인트를 점검:
    ```bash
    curl -i https://your-mcp.example.com/mcp \
      -H "Authorization: Bearer $TOKEN"
    ```
  - 200/401/403/404 응답을 보고 “인증 실패 vs 권한 부족 vs 경로 오류”를 구분.

- **툴/리소스/템플릿 가용성 확인 (서버 구현별 편차 고려)**
  - `list_mcp_tools`, `list_mcp_resources`, `list_mcp_resource_templates`를 각각 호출해 “비어 있음 = 오류”로 단정하지 않기.
  - 최소 1개 이상 **실제 호출**이 가능한지(예: echo, ping, health)로 판단.

- **요청/응답 전체 로깅(토큰만 마스킹)**
  - 디버그 모드에서 **원문 요청/응답 바디**를 남겨야 원인 분석이 가능.
  - 토큰·쿠키·개인정보는 `****` 처리.
  - 로그에 타임스탬프, 소요시간(ms), 재시도 횟수 포함.

- **작게 쪼개 재현**
  - “클라이언트 설정 로딩 → 베어러 토큰 주입 → 핑/헬스 호출 → 단일 툴 한 번 실행 → 파라미터 늘리기” 순서로 한 단계씩.
  - 네트워크 간헐 이슈를 의심하기 전에 **동일 입력으로 반복 호출**해 재현률 확인.

- **에러 메시지 정규화**
  - 서버에서 에러를 `code`, `message`, `hint`(선택) 구조로 고정해, 클라에서 바로 사용자 피드백 가능.
  - 4xx(클라 문제)/5xx(서버 문제) 구분을 지켜서 재시도 정책 설계.

## 자주 터지는 포인트(요약)

- URL 오른쪽 슬래시(`/mcp` vs `/mcp/`) 불일치.
- `Authorization` 오탈자(`Authorisation`, `Bearer:` 등).
- 프록시/방화벽이 TLS를 중간복호화 → 인증서 불신.
- 서버는 “툴만” 공개하는데, 클라가 “리소스/템플릿 없으면 실패”로 처리.
- 재시도 시 토큰 재사용 중 만료 → 중간에만 401 발생.

## 빠른 자가진단 스니펫

- **헤더만 점검**
  ```bash
  curl -sS -D - https://your-mcp.example.com/mcp -o /dev/null \
    -H "Authorization: Bearer $TOKEN"
  ```
- **바디/지연시간 로깅(로컬 프록시 권장)**
  ```bash
  time curl -v https://your-mcp.example.com/mcp \
    -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
    --data '{"op":"ping"}'
  ```

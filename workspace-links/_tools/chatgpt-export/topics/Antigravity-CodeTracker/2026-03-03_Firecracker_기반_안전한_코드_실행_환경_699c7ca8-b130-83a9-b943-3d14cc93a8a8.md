# 무엇을 왜 쓰나?
- **문제**: 컨테이너만으로는 커널-공유 구조라 커널 취약점·syscall 면 공격면이 넓음.
- **해법**: **Firecracker**(서버리스용 초경량 VMM)로 **작업마다 MicroVM**을 띄워 커널을 분리하고, **읽기 전용 바인드 마운트 + 임시 tmpfs**만 허용해 표면을 최소화.

---

# 아키텍처 한 장 요약
- **불변 이미지**: `vmlinux`(미니멀 커널) + `initramfs`(부팅/런처).
- **컨트롤 플레인(호스트)**: vsock/REST로 MicroVM에 “작업 시작/아티팩트 수신/종료”만 명령.
- **파일 경계**  
  - VM 안: `/work`는 **tmpfs(휘발)**—다운로드/빌드/중간산물.  
  - 호스트→VM: **읽기 전용 바인드 마운트 allowlist**(정해둔 도구/SDK만).  
  - 네트워크: **기본 차단**, 필요시 목적지 allowlist.
- **종료 시**: VM 파기(스냅샷 안 씀) → 상태·비밀 남기지 않음.

---

# 최소 실행 흐름(리눅스 호스트)
1) 커널/이미지 준비  
- `vmlinux`(musl/minimal), `initramfs`(busybox+작업 런처, vsock 에이전트).
2) Firecracker 부팅 파라미터
```bash
firecracker --api-sock /tmp/fc.sock
# 별도 프로세스에서:
curl --unix-socket /tmp/fc.sock -i -X PUT 'http://localhost/machine-config' \
  -d '{"vcpu_count":2,"mem_size_mib":1024,"ht_enabled":false}'
curl --unix-socket /tmp/fc.sock -i -X PUT 'http://localhost/boot-source' \
  -d '{"kernel_image_path":"./vmlinux","boot_args":"console=ttyS0 init=/init"}'
curl --unix-socket /tmp/fc.sock -i -X PUT 'http://localhost/drives/rootfs' \
  -d '{"drive_id":"rootfs","path_on_host":"./rootfs.ext4","is_root_device":true,"is_read_only":true}'
```
3) vsock로 작업 지시  
- 호스트가 vsock 서버를 열고, VM의 런처가 접속 → “작업 tar.gz 수신 → `/work`에 풀기 → 빌드/테스트 → 결과만 vsock/호스트로 송신”.

# Windows에서의 선택지
- **WSL2 + Firecracker (가능하면)**: `/dev/kvm` 사용이 핵심. WSL 커널·KVM 잠금/업데이트 정책을 통제할 수 있을 때만 권장.  
- **대안**  
  - **gVisor**: 커널 수준 **syscall 인터포지션**(gofer FS 프록시)로 격리 강화.  
  - **Kata Containers(QEMU 기반)**: **하드웨어 VMM 격리**가 더 강함(대신 무거움).  
→ WSL2에서 KVM 제어가 애매하면 우선 **gVisor** 또는 **Kata**를 기본으로.

---

# 디폴트 보안 설정(그대로 복붙해도 좋은 체크리스트)
- **네트워크**: “기본 차단, 필요시만 허용”  
  - 호스트 `nftables`/eBPF로 VM TAP/브릿지 outbound 드롭, 도메인/포트 allowlist만 열기.
- **파일**:  
  - VM 내부 작업 디렉토리 **tmpfs(휘발)**.  
  - 호스트 바인드 마운트는 **명시 allowlist + 기본 read-only**.  
  - 아티팩트만 vsock로 반출.
- **자원 제한**: cgroup(vCPU, 메모리, I/O) + 프로세스 수/ulimit.  
- **seccomp**: 작업 런처와 유틸에 맞춘 **deny-by-default** 프로파일.  
- **이미지**: 커널·initramfs **불변(해시 고정)**, 서명 검증.  
- **패치**: 호스트 **커널/마이크로코드 최신화**, 하이퍼바이저/펌웨어 정기 업데이트.  
- **관측**: VM별 syslog 파이프/감사 로그, 실패 시 자동 격리/파기.

# 샘플 구조(리포지토리 레이아웃)
```
sandbox/
 ├─ images/
 │   ├─ vmlinux
 │   ├─ initramfs.cpio.gz
 │   └─ rootfs.ext4 (ro)
 ├─ agent/           # VM 내부 런처(초소형, 정적 링크)
 ├─ hostctl/         # 호스트 제어(REST/vsock 브로커)
 ├─ policies/
 │   ├─ mounts.allowlist.json
 │   ├─ seccomp.profile.json
 │   └─ net.allowlist.nft
 └─ examples/
     └─ job_hello.tar.gz
```

# CI에 붙일 때의 팁
- **잡당 VM 1개**: 캐시가 필요하면 원격 캐시를 쓰고, VM은 **완전 휘발**로.  
- **비밀**: vsock 1회용 토큰으로 주입, VM 종료 전 메모리 스크럽.  
- **병렬성**: vCPU/메모리 고정으로 노이즈 줄이고, 실패 시 **전체 VM 재생성**만 허용.

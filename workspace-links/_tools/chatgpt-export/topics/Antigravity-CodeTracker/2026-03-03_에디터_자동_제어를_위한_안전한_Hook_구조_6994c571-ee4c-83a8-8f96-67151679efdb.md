## 1. assistant

Unity 에디터를 “에이전트 친화적”으로 제어하는 초간단 가이드예요—메뉴 호출, 윈도우 열기, 다단계 작업 시퀀싱까지 한 번에 잡습니다.

```csharp
// Assets/Editor/AgentHooks.cs
using UnityEditor;
using UnityEngine;

public static class AgentHooks {
  // 에이전트가 사용할 안전한 진입점: 기존 메뉴 경로 실행
  public static void InvokeConsole() {
    EditorApplication.ExecuteMenuItem("Window/General/Console");
    Debug.Log("AgentHooks: invoked Console menu");
  }

  // 수동 테스트용 커스텀 메뉴
  [MenuItem("Agent/DoThing")]
  public static void DoThing() {
    Debug.Log("Agent DoThing ran (UI)");
  }
}
```

# 배경 요약
- **편법 불필요**: Unity가 공식 지원하는 프리미티브로 에디터 제어가 충분함  
  (메뉴: `MenuItem`, 실행: `EditorApplication.ExecuteMenuItem`, 창/에디터윈도우: `EditorWindow` API).
- **안전 격리**: “에이전트 훅”은 **Editor 전용 어셈블리**에만 두면 빌드(Runtime)에 절대 포함되지 않음.

# 3단계 실험(빠른 검증 루프)
1) **에디터 전용 asmdef 생성 + 메뉴 보이기**  
   - `Assets/Editor` 폴더에 asmdef 하나 생성(Platform → **Editor**만 체크).  
   - 위 스크립트 추가 후 Unity 재컴파일 완료되면 메뉴에 **Agent/DoThing**가 생깁니다. 클릭 시 Console에 로그가 찍히면 성공(메뉴 배선·격리 OK).

2) **헤드리스(배치) 호출로 에이전트 경로 검증**  
   - 셸에서 실행:
     ```
     unity -projectPath /path/to/project -batchmode -quit \
       -executeMethod AgentHooks.InvokeConsole -logFile agent_run.log
     ```
   - `agent_run.log`에 `AgentHooks: invoked Console menu` 로그가 있으면 성공.  
     *(참고: 배치모드에선 UI창이 실제로 열리지 않을 수 있으니, **로그/파일쓰기 같은 비UI 부작용**으로 검증하세요.)*

3) **에디터 코루틴으로 다단계 시퀀싱**  
   - `Unity.EditorCoroutines.Editor` 패키지 사용:
     ```csharp
     using Unity.EditorCoroutines.Editor;
     using System.Collections;

     public static class AgentHooksSeq {
       [MenuItem("Agent/RunSequence")]
       public static void RunSequence() {
         EditorCoroutineUtility.StartCoroutineOwnerless(Sequence());
       }
       public static IEnumerator Sequence() {
         Debug.Log("[Seq] Step1: 자산 준비");
         yield return null; // 한 프레임 양보
         Debug.Log("[Seq] Step2: 수정/검증");
         yield return null;
         Debug.Log("[Seq] Step3: 저장/정리");
       }
     }
     ```
   - 에디터에서 메뉴로 실행 + 위 2단계처럼 `-executeMethod AgentHooksSeq.RunSequence`로도 실행해 **동일하게 동작**하는지 확인(시퀀싱/취소/에디터 한정 실행 보장).

# 핵심 가드레일(필수)
- **Editor 전용 배치**: `Assets/Editor` + asmdef(Platform=Editor).  
- **컴파일 가드**: 필요한 경우 `#if UNITY_EDITOR` / `Application.isEditor`로 이중 안전장치.  
- **명령은 멱등성**: 같은 명령을 여러 번 호출해도 안전하게.  
- **파괴적 액션 보호**: 삭제/대량 수정은 명시적 플래그나 확인 절차 필요.  
- **감사 로그**: 모든 진입점에서 파라미터/결과를 `Debug.Log`로 남겨 추적 가능하게.

# 에이전트가 할 수 있는 것(예시)
- 특정 메뉴/툴 체인 실행(예: 애셋 임포터, 어드레서블 빌드, 분석 창 켜기)
- “열기 → 수정 → 저장” 시퀀스 자동화(씬/프리팹/텍스처 등)
- 프로젝트 상태 점검(가이드라인 체크 → 리포트 파일 생성)

# 바로 써먹는 팁
- **메뉴 경로 발견법**: Unity 상단 메뉴에 마우스를 올리면 경로를 그대로 `ExecuteMenuItem("...")`에 넣으면 됨.  
- **에러 핸들링**: 실패 시 `EditorApplication.isCompiling`/`AssetDatabase.StartAssetEditing()` 상태 등 확인 후 재시도.  
- **비UI 검증**: 배치모드에선 파일 출력(예: `/Temp/agent_out.json`)로 결과를 남기면 CI 연동이 쉬움.

원하면 위 스캐폴드에 **당신 프로젝트 전용 커맨드 세트(예: `Agent/BuildGameplayDB`, `Agent/FixImportSettings`)**를 바로 설계해 드릴게요. 원하는 작업 목록만 던져주시면, 메뉴/배치 호출/로그 규약까지 깔끔한 패턴으로 정리해 드립니다.

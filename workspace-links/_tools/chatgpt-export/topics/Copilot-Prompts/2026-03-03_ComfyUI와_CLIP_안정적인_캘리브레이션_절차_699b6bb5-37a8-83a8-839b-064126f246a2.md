# 1) 배경 한 줄 요약
- **CLIPScore**는 참조 캡션 없이 “텍스트↔이미지 일치도”를 점수화하는 지표예요. 이미지 캡셔닝 평가에서 사람 판단과 높은 상관을 보인 메트릭으로 널리 쓰입니다. citeturn0search0turn0search4turn0search8

# 2) ComfyUI에 점수 노드 붙이기
- 설치 옵션 A: **wu12023/ComfyUI-Image-Evaluation**(CLIP/DINO 점수) 노드 설치 → `custom_nodes`에 클론 후 `pip install -r requirements.txt`, 재시작. citeturn0search1turn0search12turn0search5  
- 설치 옵션 B: **ComfyUI-ClipScore-Nodes**(azure‑dragon‑ai) 사용. 온라인 노드 인덱스에도 등록되어 있어요. citeturn0search2turn0search6turn0search17  
- **OpenCLIP** 체크포인트를 고정 사용(예: LAION ViT‑H/14). 버전/체크포인트가 바뀌면 점수 분포가 흔들릴 수 있어서, 반드시 한 모델로 “핀 고정”하세요. citeturn0search3turn0search14turn0search7

# 3) “프롬프트별” 캘리브레이션 스윕
한 프롬프트마다 50장 정도 생성해 **기준 평균±표준편차**를 잡습니다.
1. **고정값**: seed(필수), subseed, sampler, steps, guidance, 해상도, **OpenCLIP 체크포인트**.  
2. 생성 50장 → 각 이미지에 대해 **CLIPScore(text, image)** 계산 → 그 프롬프트의 **mean, std** 저장.  
3. 이 값이 그 프롬프트의 **베이스라인 분포**입니다. (나중에 z‑score 계산용)

> 팁: 같은 프롬프트여도 모델·체크포인트가 바뀌면 분포가 달라집니다. 따라서 **CLIP 모델 이름/버전 및 체크포인트 해시**를 아티팩트로 항상 기록하세요. citeturn0search3turn0search7

# 4) 게이트(통과 임계) 설정법
두 가지 중 하나로 간단히 결정합니다.
- **z‑score 기준**: (점수−프롬프트별 평균)/표준편차 > 임계치  
  - 원하는 **오탐 비율(FPR)**에 맞춰 컷을 잡기: 예) **z≈1.645(5%)**, **z≈1.96(2.5%)**.  
- **경험적 백분위수**: 프롬프트별 상위 **90~95퍼센타일**을 통과 기준으로.  
가능하면 **라벨 있는 소량 캘리브레이션 세트**로 ROC를 그려 **precision/recall 목표**에 맞는 임계를 택하고 **동결**합니다. (메트릭 자체는 CLIPScore 논문 참고) citeturn0search4

# 5) 운영 체크리스트(재현성/추적성)
- 매 실행마다 **JSONL 아티팩트**에 다음 필드를 남김:  
  `seed, subseed, sampler, steps, guidance, width/height, prompt, nodegraph JSON, 모델 체크포인트/해시, CLIP 모델명/커밋, 점수(raw/z)`  
- **재현성 해시**: `sha256(prompt + seed + nodegraph + model_checkpoint)`를 만들어 이미지·점수 파일명에 포함.  
- **전처리 고정**: OpenCLIP/OpenAI CLIP의 **전처리 파이프라인(리사이즈/정규화)**을 고정하고 모델명·버전 기록. (전처리 차이로 점수 변동 방지) citeturn0search3turn0search14  
- **배치 게이팅은 반드시 z‑score 기반**(프롬프트간 원시점수 스케일 차이를 흡수).  
- **노드/모델 업데이트 시** 기존 베이스라인·임계 메타데이터와 **버전 스냅샷**을 같이 저장해, 필요 시 **재평가** 가능하게.

# 6) 워크플로우 예시(요지)
1. `Prompt → Sampler → Image`  
2. `Image + Text → CLIPScore Node` (OpenCLIP 체크포인트 지정) citeturn0search1turn0search2  
3. `z = (score−μ_prompt)/σ_prompt`  
4. `z > threshold`면 **통과 저장**, 아니면 폐기/리롤

# 7) 자주 묻는 질문
- **왜 프롬프트별(z‑score)인가요?**  
  프롬프트마다 CLIPScore의 **원시 분포가 다르기 때문**이에요. z‑score로 표준화하면 프롬프트 간 비교가 안전해집니다. citeturn0search4
- **어떤 CLIP 모델을 쓰죠?**  
  재현성 위해 **하나를 고정**하세요(예: `CLIP-ViT-H-14 laion2B`). 나중에 바꿀 땐 **새로 캘리브레이션**이 필요합니다. citeturn0search7

## 1) ✅ 멀티 세션 = “병렬 작업”이 아니라 “격리된 작업 슬롯”
Auto-Claude의 핵심은 **여러 에이전트**가 아니라 **서로 안 망가뜨리게 격리하는 방식**이에요.

### 우리에게 적용 포인트
- **Git worktree(또는 브랜치)로 에이전트별 작업공간 분리**
- 각 에이전트는 **딱 1개의 목표/PR**만 담당
- 머지는 **Release Captain(=나) 규칙**으로만

### 왜 좋냐
- 충돌/오염/중간파일/실험 코드 섞임 → 디버깅 지옥을 “구조적으로” 차단

---

## 2) ✅ 칸반/보드 = “상태 머신”으로 강제
UI가 중요한 게 아니라 **상태 정의가 중요**합니다.

### 우리에게 적용 포인트 (보드 상태 표준화)
- `BACKLOG → SPEC_READY → EXECUTING → PR_READY → RELEASE_CHECK_PASS → MERGED`
- “완료”의 정의를 상태로 박아버리기

### 핵심 규칙
- `SPEC_READY` 아니면 executor(Claude Code)는 **절대 코드 못 만짐**
- `RELEASE_CHECK_PASS` 아니면 **절대 머지 못 함**

---

## 3) ✅ “메모리 레이어” = 우리 방식으로는 “SSOT + 자동 가드”
Auto-Claude식 세션 메모리도 좋지만, 선생님은 이미 더 강한 원칙이 있어요:

> 같은 실수 2번이면 `./dev check`로 승격  
> 릴리즈 영향 사건이면 `release-check`에 즉시 가드 추가

### 우리에게 적용 포인트
- 메모리는 “대화 기록”이 아니라  
  **(1) ./dev 체크 (2) Docs SSOT 5줄 (3) 회귀 테스트**로만 인정

```text
[ROLE]
You are Executor (Claude Code). Do NOT decide scope. Follow spec strictly. Prefer reducing debugging probability.

[GOAL]
Implement multi-session safe workflow in this repo:
- Agent work isolation using git worktree (or equivalent) per task
- Status-machine gates: BACKLOG → SPEC_READY → EXECUTING → PR_READY → RELEASE_CHECK_PASS → MERGED
- Enforce: no code changes unless SPEC_READY

[CONSTRAINTS]
- Single entrypoints: ./dev and .\dev.ps1 only
- Python must be 3.12.x; add strict doctor checks with exit codes: 1 for Python!=3.12, 2 for other strict failures
- release-check must print: Policy + python --version + first python path, fail-fast on dirty tree
- Tag immutability: never force-update tags
- Evidence required: last 20 lines of release-check + git status

[DELIVERABLES]
1) PATCH LIST (file-by-file changes)
2) READY-TO-PASTE CONTENT (exact patches)
3) CHECKS (commands to run + expected outputs)

[IMPLEMENTATION]
- Add ./dev command: agent:new <task_id> to create worktree under .worktrees/<task_id>
- Add ./dev command: agent:run <task_id> <command> to run within that worktree
- Add ./dev command: state:set <task_id> <state> and persist state in .worktrees/<task_id>/.task.json
- Add ./dev command: gate:assert <task_id> <required_state> to block execution if state mismatches
- Integrate gate into acceptance/release-check paths so code changes cannot be merged unless RELEASE_CHECK_PASS

[STOP CONDITION]
Return only PATCH LIST / READY-TO-PASTE CONTENT / CHECKS and nothing else.
```

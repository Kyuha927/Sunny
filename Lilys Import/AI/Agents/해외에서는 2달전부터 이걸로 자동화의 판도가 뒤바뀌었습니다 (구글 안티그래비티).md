기존의 수동적인 자동화 툴(Make, Zapier) 시대를 넘어, 이제는 **AI 에이전트 워크플로우**가 자동화의 판도를 바꾸고 있습니다. 이 콘텐츠는 구글의 **안티그래비티**를 활용하여, 사용자가 원하는 목표만 말하면 AI가 스스로 계획, 실행, 수정까지 해주는 새로운 자동화 구축 방법을 단계별로 공개합니다. 복잡한 설정과 코딩 없이도 **RSS 크롤링부터 AI 요약, 이메일 리포트 발송**까지 완벽하게 자동화하는 실질적인 노하우를 얻어, AI 시대의 경쟁에서 앞서나갈 수 있는 구체적인 적용 방법을 배울 수 있습니다.

## 1. 자동화 패러다임의 변화: 기존 방식에서 에이전트 워크플로우로

### 1.1. 기존 자동화 방식의 한계와 새로운 시대의 도래

1. **기존 자동화 방식**: 지금까지 자동화는 **Make, Zapier, n8n**과 같은 도구를 사용하여 사용자가 직접 손으로 설계하고 만들어야 했다.
2. **새로운 시대의 도래**: 이제 자동화의 판도가 뒤바뀌고 있으며, **에이전트 워크플로우**라는 새로운 개념이 등장했다.
3. **에이전트 워크플로우의 정의**: 사용자가 **무엇을 이루고 싶은지 말만 하면**, AI가 스스로 **계획하고, 실행하고, 수정까지** 해주는 시대가 되었다.
4. **콘텐츠 목표**: 본 영상에서는 일반 자동화 시대가 끝나가는 이유와 에이전트 워크플로우를 만드는 방법을 공개한다.
5. **기대 효과**: 이 내용을 통해 AI 시대에 경쟁에서 앞서 나갈 수 있을 것이다.

### 1.2. 기존 n8n 워크플로우 예시와 변화의 배경

1. **기존 n8n 워크플로우 구성**: 특정 시간에 뉴스를 크롤링하고, 24시간 이내의 개시물만 필터링한 후, AI가 요약하고, 최종적으로 이메일로 리포트를 받는 구조였다.
2. **과거 구현 방식**: 이 모든 로직을 과거에는 직접 하나하나씩 생각하며 수동으로 짰었다. (n8n 빌더나 Claude Code와 같은 개념이 대중화되기 전)
3. **Claude Code의 등장**: Claude Code가 등장하면서 워크플로우 구축을 자동화하려는 시도가 나타나기 시작했다.
4. **AntiGravity의 등장과 판도 변화**: **AntiGravity**가 등장한 이후 상황이 완전히 뒤바뀌었다.
5. **해외 유튜버들의 동향**: 닉사라이브(Nixalib), 잭로보츠(JackRobots), 닉프로(NickPro)와 같은 해외 AI 메이저 유튜버들은 n8n의 비중을 줄이고 AntiGravity의 비중을 크게 늘리고 있다.
6. **현재의 흐름**: AntiGravity를 통해 **에이전트 워크플로우**를 만드는 단계로 넘어가게 되었다.
7. **오늘의 목표**: n8n 워크플로우를 AntiGravity로 어떻게 대체할 수 있는지, 에이전트 워크플로우를 어떻게 만드는지 보여줄 예정이다.

## 2. 에이전트 워크플로우 구축을 위한 준비 및 설정

### 2.1. 실습 목표 및 사전 안내

1. **무료 배포 안내**: 기존에 만든 n8n 워크플로우 약 20개를 무료로 배포하고 있으니 구독과 좋아요 후 아래 링크의 카톡방에 참여하여 받아가라는 안내가 있었다.
2. **구축할 워크플로우 개요**: **초이 님의 개시물(쓰레드)을 모니터링**하는 워크플로우를 구축할 예정이다.
3. **모니터링 대상**: AI 뉴스를 깊게 다루는 '초이 님'의 글을 빠르게 받아보기 위함이다.

### 2.2. 구축할 에이전트 워크플로우의 구체적인 목표

1. **목표**: 초이 님의 쓰레드를 해킹(모니터링)하고 싶다.
2. **단계별 목표**:
    1. 초이 님의 쓰레드를 쭉 모은다.
    2. 24시간 이내에 올린 게시물만 가져온다.
    3. 해당 게시물의 내용을 요약하고 적용 방안을 도출한다.
    4. 이메일로 리포트를 받아본다.
3. **사용 도구**: 이 모든 과정을 **AntiGravity**를 통해 진행할 것이다.

### 2.3. AntiGravity 기본 설정 (확장 프로그램 및 자동 실행)

1. **폴더 생성**: AntiGravity를 다운로드 및 기본 설정 완료 후, 작업 폴더를 생성한다. (예: `26121 스트레드 초이`)
2. **필수 확장 프로그램 설치 (Python)**:
    1. 왼쪽 바에서 **익스텐션** 메뉴를 클릭한다.
    2. **파이썬(Python)**을 검색하여 설치해야 한다.
    3. 에이전트 워크플로우는 파이썬을 기반으로 작동하므로 설치가 필수이다.
3. **터미널 자동 실행 설정**:
    1. 오른쪽 위 **톱니바퀴 버튼**을 눌러 **Open AntiGravity User Setting**으로 들어간다.
    2. **터미널 커맨드 오토 익스큐션(Terminal Command Auto Execution)** 설정을 찾는다.
    3. 이 설정을 **Always Proceed**로 변경해야 한다.
    4. **이유**: 이 설정을 변경하지 않으면, AntiGravity가 진행할 때마다 수동으로 "예(Yes)"라고 보고해야 하는 번거로움이 발생하기 때문이다.

## 3. 에이전트 지침서(Agent MD) 이해 및 프로젝트 구조 설정

### 3.1. 에이전트 지침서(Agent MD) 준비

1. **지침서 확보**: 에이전트를 만들기 위한 지침서(Agent Instruction)가 필요하며, 릭사라이브(Nixalib) 선생님이 공유한 파일을 사용한다.
2. **파일 생성 및 저장**:
    1. AntiGravity에서 왼쪽 아래 **New File**을 클릭한다.
    2. 파일명을 **agent.md**로 지정하고, 공유받은 내용을 복사하여 붙여넣기 한 후 **Ctrl+S**로 저장한다.
3. **Agent MD의 역할**: 이 파일은 **에이전트의 운영 지침**이며, 마크다운(MD) 파일 형태로 에이전트에게 지시를 내리는 역할을 한다.

### 3.2. 에이전트의 3단계 레이어 구조 이해

에이전트는 다음 세 단계의 층(레이어)으로 구성되어 동작한다.

1. **1단계: 다이렉티브 파일 (Directive File)**
    1. **역할**: 사용자가 "이러이러한 워크플로우를 만들어 줘"라고 명령하면, 이 단계에서 AI가 **목표, 필요한 입력, 사용할 스크립트** 등 모든 케이스를 정의한다.
    2. **결과**: 정의된 케이스를 바탕으로 **중간급 직원의 매뉴얼 수준**의 파일들이 이 폴더 안에 생성된다. 이 폴더가 핵심이라고 볼 수 있다.

2. **2단계: 오케스트레이션 지침 (Orchestration Instruction)**
    1. **역할**: 실시간으로 워크플로우를 만들 때 대화를 가장 많이 나누는 레이어이다.
    2. **기능**: 다이렉티브 파일에서 생성한 폴더를 읽고, **실행 도구를 어떤 순서로 호출할지 결정**하며, 에러를 처리하고 필요하면 사용자에게 질문하는 역할을 한다.
    3. **단계**: 실행 방법을 조정하고 계획을 세우는 단계이다.

3. **3단계: 실행 (Execution)**
    1. **역할**: 이전에 다운로드 받은 파이썬 파일을 기반으로 **실제 실행 방법**과 API 토큰 저장 방식 등을 결정하는 도구이다.

4. **운영 원칙**:
    1. 도구부터 확인하고, 문제가 생기면 스스로 판단하고 치유한다.
    2. **다이렉티브 파일은 살아있는 문서**이다. (실시간 업데이트)
    3. **자동 수정 기능**: 과거 n8n에서는 API를 바꾸고 싶으면 수동으로 수정해야 했지만, 다이렉티브 파일은 AI에게 "API를 바꾸고 싶다"고 질문하면 AI가 **자동으로 해당 파일에 들어가 내용을 수정**해 준다.

### 3.3. 프로젝트 구조 설정 및 확인

1. **Agent MD 파일 불러오기**: AntiGravity에서 `agent.md` 파일을 끌어오거나, 골뱅이(@) 버튼으로 검색하여 선택한다.
2. **모드 설정**: 모드를 **플래닝 모드(Planning Mode)**로 변경한다. (패스트 모드도 있으나, 구조가 복잡해지면 와리가리 될 수 있으므로 계획부터 세우는 것을 추천한다.)
3. **구조 설정 명령**: 에이전트에게 "야, 먼저 이 파일을 읽고 **프로젝트 구조를 설정**해 줘"라고 명령한다.
4. **자동 실행 확인**: 터미널 자동 실행 설정 덕분에 에이전트가 알아서 `agent.md` 파일을 읽고 프로젝트 구조 설정을 진행한다.
    * **생성된 작업**: 태스크 생성, 프로젝트 구조 수립, 디렉토리 파일 생성, 기본 파일 생성, 설정 완료 및 작성 등이 진행된다.
5. **AI 미사용 확인**: 이 과정은 **오직 AntiGravity와만 대화**하며 진행하며, GPT와 같은 외부 AI는 사용하지 않는다.
6. **파일 누락 확인 및 수정**:
    1. 구조 설정 완료 후, `temp`, `execution`, `directory`, `directive` 파일 등이 생성되어야 하는데 보이지 않는 경우, 캡처 후 "없는데"라고 질문한다.
    2. 에이전트가 알아서 수정하여 필요한 파일들이 생성된다.

## 4. 에이전트에게 목표 부여 및 필요한 정보 요청

### 4.1. 목표 재설정 및 계획 요청

1. **새로운 목표**: 기존 n8n에서 만들었던 **초이 님의 쓰레드 모니터링 및 이메일 리포트** 기능을 AntiGravity로 직접 만들어 볼 것이다.
2. **구체적인 명령**: 에이전트에게 다음과 같이 명령한다.
    * "쓰레드에서 초이라는 사람의 게시물을 RSS로 들고 와서 24시간 필터링을 거쳐 24시간 이내 게시물만 가져오게 설정하고, 해당 내용을 읽고 요약하고 적용할 점을 도출하여 내 이메일로 리포트를 보내주는 워크플로우를 만들고 싶어."
3. **계획 요청**: "먼저 **플래닝 모드**로 바꿔주고, 필요한 사항이 무엇인지 말해 줬으면 좋겠어."라고 요청한다.
4. **에이전트의 응답**: 에이전트는 생각을 한 후, **세 가지 정보**가 필요하다고 응답한다.

### 4.2. 에이전트가 요청한 필수 정보

에이전트는 SOP 파일(표준 매뉴얼 지침)을 찾아 다음 세 가지 정보가 필요하다고 제시했다.

1. **쓰레드 RSS URL** 필요.
2. **Gemini API 키** 필요.
3. **이메일 발신 설정** 필요.

사용자는 이메일 설정에 대해 "구글 OAuth 정보를 줄게"라고 응답하며 콘텍스트를 제공한다.

## 5. RSS 피드 설정 (쓰레드 URL 확보)

### 5.1. RSS 피드 생성 과정

1. **RSS 피드 도구 사용**: **RSS 피드**라는 도구를 이용할 것이다. (RSS 앱 검색 필요)
2. **새 피드 생성**: 로그인 후 **New Feed**를 생성한다.
3. **초이 님 프로필 RSS 복사**: 초이 님의 프로필에 접속하여 RSS 주소를 복사한다.
4. **RSS에 붙여넣기**: RSS 도구로 돌아와 복사한 주소를 붙여넣고 **Generate**를 누르면 초이 님의 RSS가 생성된다.
5. **URL 확보**: 생성된 RSS 피드 URL을 복사하여 AntiGravity에 제공한다.

## 6. Gemini API 키 설정

1. **Google AI Studio 접속**: Google AI Studio에 접속하여 **Get API Key**를 클릭한다.
2. **API 키 생성**: **Create API Key**를 클릭하고, 테스트용으로 키를 생성한다.
3. **키 제공**: 생성된 키를 복사하여 AntiGravity에 Gemini 키로 제공한다.

## 7. Google OAuth 설정 (이메일 발신용)

이메일 발신을 위해 Google OAuth ID와 비밀번호를 설정하는 과정이다.

### 7.1. Google Cloud Console 프로젝트 생성 및 OAuth 동의 화면 구성

1. **Google Cloud Console 접속**: Google Cloud Console을 검색하여 접속한다.
2. **새 프로젝트 생성**: 오른쪽 상단에서 **새 프로젝트**를 클릭하고 테스트용 프로젝트를 생성한다.
3. **API 및 서비스 접속**: 왼쪽 탐색 메뉴에서 **API 및 서비스**로 들어온다.
4. **OAuth 동의 화면 설정**:
    1. **OAuth 동의 화면**으로 이동하여 **시작하기**를 누른다.
    2. 앱 이름은 '테스트'로 진행하고, 사용자 지원 이메일 및 개발자 연락처 이메일을 입력한다.
    3. 사용자 인증은 **외부**로 진행하고, 다음을 눌러 계속 진행한다.
    4. (참고: 구글 연결 부분이 답답하면 별도 카드를 참고하라는 안내가 있었다.)
5. **OAuth 클라이언트 생성**:
    1. 측정 항목에서 **OAuth 클라이언트 만들기**를 클릭한다.
    2. 애플리케이션 유형은 **웹 애플리케이션**을 선택하고 이름을 '테스트'로 지정한다.
    3. **승인된 리디렉션 URI**는 이따가 설정할 것이므로 일단 건너뛴다.
    4. 만들기를 클릭하면 **클라이언트 ID**가 생성된다.

### 7.2. 클라이언트 ID 및 보안 비밀번호 확보

1. **클라이언트 ID 복사**: 생성된 클라이언트 ID를 복사하여 AntiGravity에 입력한다.
2. **클라이언트 보안 비밀번호 확보**:
    1. 왼쪽 메뉴에서 **보안 비밀번호**를 클릭한다.
    2. **클라이언트 보안 비밀번호 복사**를 클릭하여 비밀번호를 복사한다.
3. **AntiGravity에 입력**: 복사한 클라이언트 ID와 비밀번호를 AntiGravity에 입력한다.

### 7.3. Gmail API 활성화 및 범위 설정

1. **Gmail API 활성화**:
    1. 왼쪽 점 세 개 메뉴를 클릭하여 **API 및 서비스 > 라이브러리**로 이동한다.
    2. **Gmail**을 검색하여 **Gmail API**를 찾아 **사용**을 클릭한다.
2. **OAuth 동의 화면으로 복귀**: 다시 **OAuth 동의 화면**으로 돌아온다.
3. **데이터 액세스 범위 설정**:
    1. **데이터 액세스** 탭으로 이동한다.
    2. **범위 추가 또는 삭제**를 클릭하고, 범위를 **전체(행 전체 100개로 나누고 전체)**로 설정한 후 업데이트 및 저장을 진행한다.
    4. 브랜딩, 대상, 앱 정보 등은 이미 설정되어 있거나 테스트 중이므로 추가 설정은 필요 없다.
    5. 테스트 사용자 부분에서 **외부**로 설정된 것을 확인한다.

### 7.4. 정보 제공 후 워크플로우 생성 시작

1. **정보 제공**: AntiGravity로 돌아와 설정한 정보를 제공하며 "이제 만들어 줘"라고 요청한다.
2. **모드 변경**: **플래닝 모드**에서 **패스트 모드**로 변경한다.
3. **워크플로우 생성**: 정보를 받은 에이전트가 알아서 워크플로우를 생성하기 시작한다.
    * 사용자는 손을 떼고 있으며, 에이전트가 알아서 파일을 만들고 정보를 저장한다.

## 8. 워크플로우 실행 및 초기 문제 해결

### 8.1. 초기 실행 및 Python 라이브러리 설치

1. **프로젝트 확인**: 에이전트가 생성한 프로젝트 구조를 확인하면, 크리덴셜(Credentials) 폴더에 구글 크리덴셜 정보 등이 저장된 것을 볼 수 있다.
2. **라이브러리 설치 진행**: 첫 번째로 **파이썬 라이브러리 설치**가 진행된다.
3. **이메일 발송 시 안내**: 이메일 발송 스크립트를 처음 실행할 때 구글 계정 인증을 위해 웹으로 열릴 것이라는 안내가 나온다.

### 8.2. 스크립트 실행 및 Gemini 버전 오류 해결

1. **실행 명령**: 에이전트에게 "완료가 되었으면 실행해 줘"라고 명령한다.
2. **자동 실행**: 에이전트가 터미널을 열고 알아서 실행을 시도한다.
3. **RSS 필터링 확인**: 터미널에서 실행 시, 24시간 이내에 포스트가 2개 있다는 결과가 나오며 정상적으로 데이터를 가져온다.
4. **Gemini 버전 오류 발생**: 두 번째 스크립트 실행 시 에러가 발생한다.
    * **에러 내용**: `gemini 1.5 flash` 버전이 사용되었다고 표시된다.
    * **원인 파악**: 현재 1.5 Flash 버전은 지원되지 않는 것으로 파악된다.
5. **버전 수정 명령**: 에러 메시지를 복사하여 에이전트에게 "Gemini 1.5가 지원 안 하는 걸로 아는데, 3.0으로 바꿔주겠니?"라고 명령한다.
6. **수정 및 재실행**: 에이전트가 수정을 완료한 후, 다시 스크립트를 실행한다.
7. **정상 작동 확인**:
    * 포스트를 정상적으로 가져온다.
    * Gemini 2.0이 내용을 요약하고 콘텐츠를 생성한다.

## 9. Google OAuth 인증 및 최종 실행

### 9.1. 이메일 발송 시 발생하는 인증 문제 해결

1. **인증 문제 발생**: 이메일을 보내는 과정에서 브라우저 창이 열리지만 **액세스가 차단**되었다는 문제가 발생한다.
2. **문제 원인 파악**: 로컬 포트(Localhost) 문제로 보이며, 이는 **승인된 리디렉션 URI**가 누락되었기 때문이다.
3. **URI 추가**:
    1. Google Cloud Console의 OAuth 클라이언트 설정으로 돌아간다.
    2. **승인된 리디렉션 URI** 부분에 `http://localhost:8080` 주소를 복사하여 추가하고 저장한다.
4. **재인증**: 다시 실행하면 브라우저가 열리고 계정 선택 창이 뜬다. 본 계정을 선택하고, **확인되지 않은 앱** 경고를 무시하고 계속 진행한다.
5. **인증 완료 확인**: AntiGravity에 "구글 인증도 끝났어. 전부 다 끝난 거지?"라고 질문하여 확인한다.

### 9.2. 최종 워크플로우 실행 및 리포트 확인

1. **최종 실행 명령**: "지금까지 만든 워크플로우를 한번 실행해 줘"라고 명령한다.
2. **실행 완료**: "적시 완료가 되었다"는 메시지가 뜬다.
3. **이메일 리포트 확인**: 수신된 이메일을 확인하면 요약 부분이 나타난다.
    * **내용**: 전체 요약, 주요 내용, 인사이트 포스트 1번부터의 내용, 그리고 **적용할 점** 리포트가 포함되어 있다.

## 10. 리포트 가독성 개선 및 최종 결과 확인

### 10.1. 리포트 디자인 개선 요청

1. **가독성 문제 제기**: 현재 리포트가 너무 가독성이 떨어진다고 지적한다.
2. **개선 명령**: "가독성이 좋게 **HTML과 CSS를 구성**해서 미니멀한 디자인으로 가독성을 최우선으로 생각해서 다시 구성을 하고 이메일을 보내줘"라고 명령한다.
3. **결과 확인**: 에이전트가 다시 구성을 하고 이메일을 보내주었으며, 리포트가 **이쁘게** 나오게 된 것을 확인할 수 있다.

### 10.2. 최종 결과 검토

1. **내용 재확인**: 디자인은 개선되었으나, Gemini 요약 과정에서 몇 개 내용이 생략된 것을 확인한다.
2. **최종 리포트 내용**: 게시물 요약, 인사이트, 적용할 점 등이 포함된 리포트가 정상적으로 도착했음을 확인한다.
3. **실시간 확인**: 클릭해보면 8시간 전에 있었던 게시물이 정상적으로 표시된다.
4. **결론**: AntiGravity를 활용한 에이전트 워크플로우는 **미래의 자동화(Vibe Automation)**일 수 있다.

## 11. 에이전트 워크플로우의 장점 및 미래 전망

### 11.1. 에이전트 워크플로우의 의의

1. **팀원 구축**: 많은 사람들이 Claude 스킬과 에이전트를 활용하여 자신만의 팀원을 구축하고 있다.
2. **AntiGravity의 역할**: 이제 이 기능이 AntiGravity 내부에서도 가능해졌다.
3. **포맷의 일관성**: Agent MD 파일은 Claude MD나 Gemini MD와 동일한 포맷으로 동시 다발적으로 적용된다.
4. **에이전트 워크플로우의 장점 (vs n8n)**:
    * n8n은 기존에 사용자의 서버에서 직접 하나하나씩 구현해야 했다.
    * 에이전트 워크플로우는 **내 컴퓨터 안에서 직접적으로 구성**할 수 있다는 점이 큰 차이점이며, 이는 **자산화 개념**에 더 가깝다.

### 11.2. 향후 계획 및 마무리

1. **향후 계획**: 앞으로 에이전트 워크플로우를 몇 개 더 만들어 볼 예정이다.
2. **참고 자료**: 닉 선생님이 쓰레드에 계속 올리는 워크플로우들을 참고하여 훔쳐볼 계획이다.
3. **공유 예정**: 앞으로 에이전트 워크플로우나 집중하고 있는 **보이스 에이전트**에 관한 노하우를 계속 공유할 예정이다.
4. **종료**: 영상은 여기서 마무리된다.

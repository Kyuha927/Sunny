AI의 **'할루시네이션(헛소리)'**이 단순한 버그가 아닌, **초강력 자동 완성 엔진**이라는 LRM의 구조적 특성에서 비롯된 필연적 현상임을 명확히 설명합니다. 이 콘텐츠는 GPT, Gemini, Claude 등 주요 모델들이 할루시네이션을 줄이기 위해 적용하는 최신 기술과 평가 방식의 변화를 심층 분석하며, 독자들이 **'모른다고 인정하는 능력'**을 핵심 지표로 삼는 시대에 맞춰 **실제 프롬프트 설계 시 적용 가능한 6가지 꿀팁**을 구체적으로 제시하여 AI 활용의 신뢰도를 즉각적으로 높일 수 있도록 돕습니다.

## 1. AI 할루시네이션의 이해와 최신 기술 동향

### 1.1. 할루시네이션 문제의 대두와 정의

1. **AI 활용 리스크 증가**: 잭이 AI를 이용해 수집한 판례들이 사실이 아닌 사례로 국내외에서 발생하면서 AI 활용에 대한 리스크가 부각되고 있다.
2. **할루시네이션 재조명**: AI의 성능 개선에도 불구하고, AI가 그럴듯하게 헛소리를 하는 현상인 **할루시네이션(Hallucination)** 이슈가 다시 주목받고 있다.
3. **할루시네이션의 정의**: 사실이 아닌 내용을 사실인 것처럼 그럴듯하게 말하는 현상이다.
4. **문제점**: AI에게 정보를 찾거나 도움을 구할 때 잘못된 정보가 전달될 수 있으며, 특히 **자신만만하게 틀리는** 경향 때문에 사용자들이 크게 불만을 느낀다.
5. **예시**: 연구자의 박사 논문 제목을 물었을 때, 모델이 '모르겠다'고 말하는 대신 실제로는 존재하지 않는 제목 세 개를 만들어 제시하는 경우가 발생한다.
6. **의도성 부재**: 겉보기에는 AI가 사기치거나 의도적으로 거짓말을 하는 것처럼 보이지만, 모델 입장에서는 전혀 그런 의도가 없다.

### 1.2. 할루시네이션의 구조적 원인: LRM의 본질

1. **LRM의 본질**: 현대 **대규모 언어 모델(LRM)**은 진실을 말하는 엔진이 아니라 **초강력 자동 완성 엔진**이기 때문이다.
2. **작동 방식**: LRM은 정답을 찾는 기계가 아니라 **다음에 나올 법한 단어를 맞추는 기계**이다.
3. **학습 방식**: LM은 사실 여부를 직접 배우지 않고, "이런 문맥 다음에는 이런 문장이 자주 나오더라"와 같은 **통계적 패턴**을 학습한다.
4. **학습 단계의 특징**: 학습 단계에서는 다음 단어 예측만 수행하며, "이것은 거짓이다"와 같은 **진실/거짓에 대한 레이블이 거의 없다**.
5. **결과**: 모델은 진실과 거짓을 구분하는 대신 **말이 되는지** 여부만 배우게 된다.

### 1.3. 평가 및 보상 구조의 문제점

1. **기존 평가 방식**: 모델을 평가할 때 보통 **정답률(Accuracy)**만 보며, '모르겠다'고 대답한 것은 보통 0점 처리된다.
2. **찍는 행위의 유도**: 반대로 찍어서 맞추면 점수를 받기 때문에, 모델 입장에서는 **'모르겠다'고 말하는 것보다 대충 찍는 것이 더 유리한 구조**이다.
3. **과거 모델의 특징**: OpenAI에 따르면, 과거 모델(예: GPT-4 mini)은 정확도는 높았으나 **할루시네이션 비율이 높고** '모르겠다'고 말하는 비율이 거의 없었다.
4. **최신 모델의 학습 방향**: GPT-5 계열 모델은 정확도는 비슷하거나 약간 낮더라도, 모를 때는 **아예 모르겠다고 말하도록 학습**되어 할루시네이션 비율이 낮게 설계되었다는 것이 OpenAI의 주장이다.
5. **핵심 메시지**: 모델을 점수 매기는 방식 자체가 모델에게 **찍으라고 가르치고 있다**.
6. **구조적 부작용**: 할루시네이션은 버그로 인한 예외 현상이라기보다는, LRM의 **학습 방식과 평가 방식이 합쳐지면서 구조적으로 유도되는 부작용**에 가깝다.

## 2. 할루시네이션 감소를 위한 기술적 접근 방식

각 회사들이 적용하는 기술은 크게 **모델 훈련 단계, 시스템 아키텍처 레벨, 제품 레벨**의 세 층위로 나누어 적용된다.

### 2.1. 모델 훈련 레벨 기술

1. **데이터 필터링**: 고품질 데이터의 비중을 높인다.
2. **보상 설계**: 강화 학습과 같은 훈련을 통해 **'모를 때 모른다고 말하는 것'**을 점수에 반영한다.
3. **검증형 훈련**: **체인 오브 소트(Chain-of-Thought)** 방식으로, 생각 과정을 먼저 쓰고 그것을 검증한 뒤 최종 답을 내도록 훈련한다.

### 2.2. 시스템 아키텍처 레벨 기술

1. **검색 증강 생성(RAG)**: 모델이 자신의 지식만 쓰지 않고 외부 문서나 웹에 물어보도록 설계한다. (출처를 달아주는 기술)
2. **툴 활용**: 계산기, 코드 실행, 웹 검색 API 등을 직접 활용하여 AI가 추측 대신 **직접 답을 구하고 검산**하게 만든다.
3. **멀티스텝 에이전트**: 한 번에 답을 내지 않고 **계획 → 검색 → 검증 → 수정 → 최종 답** 순서로 나누어 처리하는 방식을 적용한다.

### 2.3. 제품 UX 레벨 기술

1. **전제 설정**: "이 모델은 틀릴 수 있다"는 전제를 깔고, **링크, 소스 인용, 강조 표시** 등을 통해 사람이 검증하기 쉽게 만든다.
2. **자동/반자동 팩트 체킹**: 법률, 의료 등 특정 도메인에서는 팩트 체킹 기능을 고려한다.
3. **UX 장려**: 모델이 '모르겠다' 또는 '정보가 부족하다'고 말하는 것을 UX 차원에서 장려한다.

## 3. 주요 AI 모델별 할루시네이션 대응 현황

### 3.1. OpenAI의 접근 방식

1. **평가 방식 인정 및 수정**: OpenAI는 연구를 통해 기존의 정확도 중심 평가 방식이 '찍는 모델'에 유리했음을 인정했다.
2. **새로운 평가 방식**: **정답, 오답, 기권** 세 가지를 분리하여 보고, **오답(뻥)**에 더 큰 페널티를 주고 **기권**에는 부분 점수 또는 페널티 없음을 설계한다.
3. **이론적 진전**: 할루시네이션이 통계적으로 왜 발생하는지 설명 가능해졌다고 언급한다.
4. **GPT-5.2 성과**: 2025년 12월 11일 공개된 GPT-5.2 시스템 카드에 따르면, 브라우징 기능을 켠 상태에서 5개 사실 지리 도메인에서 **할루시네이션 비율이 1% 미만**이다.
5. **속임수 감소**: 의도적인 날조/속임수(출처 꾸미기, 모르는 척하기) 비율이 GPT-5.1의 7.7%에서 GPT-5.2에서 **1.6%**로 감소했다고 밝혔다.

### 3.2. Google Gemini의 현황

1. **Gemini 3 Pro 소개**: 2025년 11월에 공개된 플래그십 모델로, 가장 강력한 멀티모달 추론 모델이다.
2. **아키텍처**: **스파스 MoE(Mixture of Experts)** 기반으로, 입력에 따라 일부 전문가(Expert)만 활성화하여 효율성과 용량을 높인다.
3. **성능과 할루시네이션의 불균형**: 정확도는 매우 높였으나 할루시네이션은 여전히 높다.
4. **AA OmniSense 벤치마크 결과**: Gemini 3 Pro는 정확도 53%로 1위를 차지했으나, **잘못된 응답 중 88%가 할루시네이션**으로 분류되었다. 즉, 아예 대답을 안 하는 경우보다 틀린 답을 자신 있게 내놓는 경우가 훨씬 많다.
5. **학습 데이터 및 튜닝**: 웹 문서, 코드, 이미지, 오디오, 동영상 등을 포함한 초대형 멀티모델 데이터셋으로 기본 학습 후, 인스트럭션 튜닝, RLHF, 멀티스텝 추론 데이터로 추가 튜닝한다.
6. **위험 감소 단계**: 품질/안전 필터링, 중복 제거 후 학습하며, **컨디셔널 프리트레이닝, Supervised Fine-Tuning, 비평 모델을 활용한 강화 학습**을 거친다.
7. **최종 안전 장치**: 제품 단계에서 **세이프티 필터링**을 한 겹 더 적용한다.
8. **공개 정보 부족**: 사용하는 기술 스택은 OpenAI와 유사하나, '모를 땐 기권하라'는 보상 설계에 대한 구체적인 디테일은 공개되지 않았으며, 모델 카드에서도 할루시네이션 수치를 명시하지 않았다.

### 3.3. Anthropic Claude의 접근 방식

1. **안전성 우선**: Anthropic은 처음부터 정확도보다는 **위험을 덜 만드는 안전한 모델**에 초점을 맞춘 회사이다.
2. **UX 및 지침 중심 전략**: 할루시네이션 대응 방식이 OpenAI나 Google보다 **사용자 지침(프롬프트) 및 제품 UX**와 더 밀접하게 연결되어 있다.
3. **기본 전략 (Claude Docs 기준)**:
    1. **모른다고 말할 수 있게 허용**: 시스템 메시지에서 정보가 부족하거나 확신이 없으면 '모르겠다'고 답해도 된다고 명시하도록 권장한다.
    2. **직접 인용 강제**: 긴 문서를 분석할 때 원문에서 관련 문장을 직접 인용해 온 후, 그것을 기반으로 요약/분석하도록 프롬프트를 설계한다.
    3. **출처 강제**: 응답의 각 주장에 대해 뒷받침하는 문장을 다시 찾아오게 하고, 인용이 안 되면 그 주장을 철회하게 한다.
4. **고급 기법**: **Chain-of-Thought 검증, Best-of-N 샘플링, 반복 검증 프롬프트** 등을 사용한다.
5. **프롬프트 및 도구 설계 강조**: 모델 자체를 바꾸는 것 외에도, 모델에게 어떤 역할을 맡기고 어떤 행동을 허용/금지할 것인지를 **프롬프트와 도구 설계**로 명시하는 데 힘을 쓴다.
6. **OmniSense 벤치마크 결과**: Claude 4.5 Sonnet은 정확도는 31%로 낮지만 **할루시네이션 비율이 매우 낮아** '지식 많고 신뢰성 높은 모델' 카테고리 1위에 올랐다. 이는 모를 때는 모른다고 말하는 경향이 강하고, 찍어서 헛소리하는 비율이 상대적으로 적음을 의미한다.

### 3.4. XAI Grok의 현황

1. **정보 제한**: XAI는 공개 문서가 상대적으로 적어 내부 RL 구조 등을 파악하기 어렵다.
2. **OmniSense 벤치마크 결과**: Grok-4는 정확도 40%로 높은 편이나, **할루시네이션 비율은 64% 수준**으로 Gemini 3 Pro(88%)보다는 낮지만 찍는 경향이 존재한다.
3. **공식 전략**: 실시간 X(트위터) 데이터와 웹 데이터를 활용하여 **지식의 최신성**을 확보하고, 모델 구조를 **강한 추론/코딩 능력** 쪽으로 튜닝하여 생각하는 모델을 지향한다.
4. **세부 기술 공개 부족**: 할루시네이션을 줄이는 세부 기술에 대해서는 OpenAI나 Anthropic처럼 구체적인 논문이나 시스템 카드가 공개된 수준은 아니다.

## 4. 할루시네이션 감소를 위한 공통 방향성 및 프롬프트 꿀팁

### 4.1. 주요 기업들의 수렴된 방향성

1. **'더 큰 모델 = 덜 헛소리' 공식 파괴**: OmniSense 벤치마크 결과, 파라미터 수가 크고 정확도가 높다고 해서 할루시네이션이 줄어들지 않는다.
2. **겸손한 모델의 중요성**: 지식은 많지만 무조건 말부터 하는 스타일과, 지식은 적더라도 모르면 모른다고 말하는 스타일이 공존하며, **겸손한 모델을 만드는 기술이 중요**해졌다.
3. **평가 보상 구조 변경**: OpenAI는 기권에 부분 크레딧을 주는 방향을 주장하고, Anthropic은 **'모른다고 말하게 만드는 것'**을 롤(Role)로 권장한다.
4. **블랙박스에서 에이전트/툴 기반 구조로 이동**: 계획, 검색, 검증, 수정, 최종 답과 같은 **멀티스텝 흐름**이 증가하고 있다.
5. **역할 분담**: 계산기는 계산을, 검색 엔진은 검색을 담당하고, 모델은 **텍스트 해석, 판단, 요약** 역할에 집중하는 방향이다.
6. **평가 방식 변화**: OmniIndex처럼 **틀리면 강하게 페널티를 주고 기권은 페널티를 주지 않는 스코어링** 방식이 증가하는 추세이다.
7. **핵심 지표 변화**: 앞으로의 핵심 지표는 모델이 **무엇을 아는가**가 아니라 **무엇을 모른다고 인정할 수 있는가**가 될 것이다.

### 4.2. 프롬프트 설계로 할루시네이션 줄이는 실전 꿀팁

완전히 없앨 수는 없지만, 현업에서 체감할 정도로 줄일 수 있는 6가지 팁이다.

1. **모르는 내용에 대한 명확한 지시**: 모르는 내용을 절대 지어내지 말고, **"해당 정보는 제공된 자료나 제 지식 범위를 벗어납니다"**라고 말하도록 지시한다.
2. **추측 명시 강제**: 추측이 필요한 경우, **"추측입니다"**라고 먼저 명시하도록 지시하면, 확신에 찬 헛소리가 '추측/가정'으로 라벨링된 답으로 바뀐다.
3. **근거 먼저, 결론 나중 구조 강제**: 이 구조를 강제하면 모델이 상상 후 포장하는 패턴이 줄고, **"근거가 빈약하다"**는 자기 피드백이 붙을 가능성이 커진다.
4. **출처/근거 요구 기본값 설정**: 근거 출처나 정확도 표시를 요청하면, 모델이 불필요한 디테일을 꾸며낼 때 **"정확도 낮음"**이라고 스스로 표시하는 경우가 늘어난다.
5. **범위 좁히기 및 구체화**: 광범위하고 모호한 질문은 모델에게 상상력을 발휘하라는 신호를 주므로, **시간 범위나 도메인을 극단적으로 좁혀서 구체적으로 질문**해야 한다. 구체적일수록 모델은 패턴 회상 모드로 가고 창작 모드는 줄어든다.
6. **체크리스트 기반 응답 요구**: 체크리스트를 직접 작성하여 하나씩 확인하며 답하도록 요구하면, 모델이 답변할 때 **스스로 한 번 더 검열**하게 만드는 메타 인스트럭션을 제공하는 효과가 있다.
7. **두 단계로 묻기 (생성기/비평가 분리)**:
    1. **1차 프롬프트**: 일단 초안을 작성하게 하고 할루시네이션이 나와도 상관없다고 명시한다.
    2. **2차 프롬프트**: 방금 쓴 초안을 **비판적으로 검토**해 달라고 요청한다.
    * **효과**: 같은 모델을 1차 생성기, 2차 비평가로 돌리면 최종 답변의 헛소리 강도가 꽤 줄어든다.

### 4.3. 결론 및 시사점

1. **AI 활용의 새로운 시대**: AI는 똑똑해지고 있지만 너무나도 당당하게 아무 말이나 던지기 때문에, 모델별 특성을 잘 알고 **프롬프트 방식을 잘 알아두는 것**이 필요한 시대가 되었다.

코딩 지식 없이도 **내 업무를 대신 처리해 주는 맞춤형 AI 팀원**을 만드는 구체적인 방법을 알려드립니다. 논문 번역부터 블로그 작성까지, **5단계 워크플로우**를 따라 하면 AI가 스스로 복잡한 작업을 자동화하고, 피드백을 통해 사람처럼 성장하는 시스템을 구축할 수 있습니다.

## 1. Claude Code 소개 및 설치
<mark>Claude Code는 컴퓨터에서 직접 파일을 생성/수정/실행하는 '일해주는 팀원' AI이며, 비개발자도 5단계 워크플로우로 맞춤형 에이전트를 만들 수 있다.</mark>

### 1.1. Claude Code의 개념
1. **기존 LLM(Claude, ChatGPT 등)**: 채팅창에서 질문/답변, 파일 읽기 등 조언하는 친구 역할에 머무른다.
2. **Claude Code**: 사용자의 컴퓨터에 접근 권한을 가지고 파일을 직접 만들고, 수정하고, 실행까지 수행한다.
   1. 이는 AI가 직접 일해주는 **나의 팀원** 역할을 수행함을 의미한다.

### 1.2. Claude Code 설치 및 환경 설정
1. **사용 환경**: **VS Code**라는 코드 에디터 상에서 사용할 것을 권장한다.
   1. VS Code는 게임기에 해당하며, Claude Code는 게임 팩에 비유된다.
   2. VS Code 대신 Cursor나 Obsidian을 사용할 수도 있으나, VS Code가 가장 빠르고 안정적이다.
2. **VS Code 기본 설정**:
   1. 구글/네이버에서 검색하여 **Visual Studio Code**를 설치하고 기본값으로 세팅한다.
   2. 화면을 라이트 모드로 바꾸고 **Korean Language Pack**을 설치하면 더 친숙하게 사용할 수 있다.
3. **VS Code 확장 프로그램 설치 (쉬운 방법)**:
   1. VS Code 확장 프로그램 메뉴에서 **Claude Code**를 검색하여 **Anthropic**이 만든 공식 확장 프로그램을 설치한다.
   2. 설치 후 보이지 않으면 VS Code를 재시작하여 사용한다.
4. **계정 및 권한 설정**:
   1. **Claude 유료 계정**으로 로그인해야 한다.
   2. 설정에서 `allow dangerously skip permissions` 옵션을 켜는 것을 권장하며, 이는 에이전트에게 더 많은 권한을 부여하는 것이다.
5. **터미널 설치 방법 (선택 사항)**:
   1. 터미널 사용이 익숙하지 않다면 확장 프로그램만으로도 충분하다.
   2. **Mac**: Claude Code 사이트의 명령어를 복사/붙여넣기 하면 설치 완료된다.
   3. **Windows**: 먼저 **WSL**을 설치해야 하며, 이후 Claude Code 사이트 명령어로 설치한다.
6. **실행 및 권한 부여**:
   1. VS Code 터미널에서 `Claude`를 입력하면 Claude Code가 실행된다.
   2. 에이전트에게 더 많은 권한을 부여하기 위해 `Claude --dangerously skip for missions` 명령어를 사용하는 것을 권장한다.
7. **터미널 실행 오류 해결**:
   1. `Claude` 명령어 실행이 안 될 경우, 시스템 환경 변수 편집에서 **PATH** 메뉴를 편집하여 셋업 노트의 파일 경로를 추가해야 한다.
8. **추가 권장 설치**:
   1. **Python**과 **Node.js** 설치를 권장하며, 이는 Claude Code가 엑셀 처리나 웹사이트 제작 시 필요한 엔진 역할을 한다.

## 2. 나만의 AI 에이전트 구축 5단계 워크플로우
<mark>나만의 AI 에이전트를 만드는 과정은 프로젝트 생성, 설계서 작성, 설계 검토, 세팅, 실행 및 개선의 5단계로 구성되며, 특히 설계서 작성이 가장 중요하다.</mark>

### 2.1. 5단계 개요 및 예시 소개
1. **5단계 워크플로우**:
   1. 프로젝트 생성
   2. 에이전트 설계서 작성
   3. 에이전트 설계 검토
   4. 에이전트 세팅
   5. 실행과 개선
2. **예시 작업**:
   1. **논문 번역 에이전트**: 영문 PDF를 한국어 PDF로 번역하며, 원문의 그림, 표, 다이어그램 위치는 그대로 유지한다.
   2. 복잡한 PDF 분석, 이미지 추출, 번역, 조합 등의 다단계 작업은 코딩 에이전트가 아니면 어렵다.

### 2.2. 1단계: 프로젝트 생성
1. **프로젝트 폴더 설정**:
   1. VS Code 탐색기에서 **폴더 열기**를 통해 폴더를 지정한다.
   2. 폴더 단위는 가상 회사나 팀 단위가 아닌, **각 작업 단위** (예: 논문 번역, 유튜브 리서치)로 설정하는 것이 좋다.
2. **병렬 작업**:
   1. 파일 세 창을 눌러 여러 VS Code 창을 띄워 병렬 작업한다.
3. **경험적 권장 사항**:
   1. 현재 수준에서는 **업무 단위로 폴더를 설정**해야 에이전트가 혼선 없이 일을 잘 수행한다.
   2. 조직 단위로 세팅하는 것은 현 수준에서 비효율적일 수 있다.
4. **실행**:
   1. 원하는 폴더(예: 논문 번역 빈 폴더)를 만들고, 오른쪽 사이드바에서 Claude Code 확장 프로그램을 실행한다.

### 2.3. 2단계: 에이전트 설계서 작성
1. **설계서의 중요성**:
   1. 좋은 설계도가 건축물을 잘 짓듯이, 에이전트 설계서 정리가 결과물 퀄리티에 매우 중요하다.
   2. 이 부분이 에이전트 제작에서 가장 중요하며, 상세한 절차 설명 여부에 따라 결과물 퀄리티가 크게 차이 난다.
2. **설계서 작성 준비**:
   1. 생각을 정리할 때는 Claude.ai 웹사이트에서 진행하는 것이 편하며, 맞춤형 지침(Custom Instructions)을 활용할 수 있다.
   2. 작성 지침 문서는 영상 설명란과 고정 댓글에 링크로 제공된다.
3. **설계서에 포함되어야 할 3가지 핵심 요소**:
   1. **What**: 작업의 상세 절차 (무엇을 할 것인가)
   2. **Why**: 작업을 수행하는 의도 (왜 할 것인가)
   3. **How**: 작업 수행 방법 (어떤 도구, API 사용, 에이전트 간 협업 방식 등)
4. **설계서 작성 지침 및 결과**:
   1. 작성된 지침을 기반으로 Claude Project에서 실행하면, 클로드가 질문을 통해 설계를 구체화한다.
   2. 설계서에서 **에이전트 처리 영역**과 **코드 스크립트 처리 영역**을 분리하여 지정하는 것이 중요하다.
      * 모든 작업을 스크립트로 처리하게 두면 번역 퀄리티 등이 낮아질 수 있으므로, 의사 결정이나 비정형 데이터 생성 시에는 **LRM(에이전트) 능력**을 활용하도록 지정해야 한다.
   3. 전체 워크플로우 중간중간에 **휴먼 리뷰 단계(Human In The Loop)**를 포함하는 것이 좋다.
      * 휴먼 리뷰 단계가 있으면 자동화만 했을 때보다 오히려 퀄리티가 높으며, 이는 Claude Code가 Make나 Zapier 같은 노코드 툴보다 유용한 이유 중 하나이다.
5. **설계서 검토 및 피드백**:
   1. 설계서 완성 후, 병렬 처리 조건 등 세부 사항에 대해 피드백을 주어 수정할 수 있다.
   2. 완성된 설계서는 파일로 다운로드 가능하다.

### 2.4. 3단계: 에이전트 설계 검토 (Plan Mode)
1. **Plan Mode 전환**:
   1. 설계서를 VS Code 프로젝트 폴더에 넣고, Claude Code 대화창에서 **Shift+Tab**을 누르거나 하단 버튼을 클릭하여 **Plan Mode**로 전환한다.
2. **Plan Mode의 목적**:
   1. Claude Code가 임의로 파일을 생성/수정하지 않고 파일을 읽기만 하여 작업 계획을 세우게 한다.
   2. 새로운 모델에서 한 번 더 검토하여 설계서를 탄탄하게 하고, 코딩 전 전체 그림을 파악하여 방향이 틀어지는 것을 줄인다.
3. **협업 검토 프롬프트 활용**:
   1. Anthropic 엔지니어가 공유한 **Plan Mode 프롬프트**를 활용하여 AI와 인간이 협업하며 구현 계획을 검토한다.
   2. 프롬프트 실행 시 **골뱅이(@)**를 눌러 설계 문서를 참조시킨다.
   3. 이 과정에서 **User Question** 도구를 통해 인간의 판단이 필요한 부분에 대해 객관식 질문을 받고 답변하며 계획을 구체화한다.
4. **다음 단계 준비**:
   1. 인터뷰 과정을 통해 탄탄한 설계서가 완성되면, 컨텍스트 누적으로 에이전트가 멍청해지는 것을 방지하기 위해 **Clear** 후 **New Conversation**으로 새 창에서 다음 단계를 진행한다.

### 2.5. 4단계: 에이전트 세팅
1. **세팅 요청**:
   1. 구체화된 설계서를 기반으로 에이전트 시스템을 알아서 설계하도록 요청한다.
   2. 업데이트된 설계서를 **골뱅이(@)**로 멘션하며 "이 설계서 기반으로 네가 알아서 세팅해라"고 요청한다.
2. **효과적인 에이전트 동작을 위한 필수 요소**:
   1. 내부 **폴더 구조**가 잘 체계화되어 있어야 한다.
   2. 프로젝트 관련 기본 가이드 문서인 **`Claude.md`**가 존재하고 핵심 내용이 간결하게 정리되어 있어야 한다.
   3. 동작에 맞게 **스킬(Skill)**과 **서브 에이전트(Sub-Agent)**가 잘 설정되어야 한다.
3. **스킬과 서브 에이전트**:
   1. **스킬**: 레시피처럼 정해진 절차를 그대로 따라 요리하는 것.
   2. **서브 에이전트**: 셰프처럼 상황에 맞게 자율적으로 판단하며 요리하는 것.
4. **세팅 결과 확인**:
   1. 요청 시 Claude Code가 폴더 구조, `Claude.md`, 스킬 및 서브 에이전트를 알아서 세팅한다.
   2. 인풋 폴더에 논문을 넣으면 아웃풋 폴더에 결과물이 생성될 것이다.
   3. `Claude` 폴더 내에 스킬, 에이전트, 커맨드 등이 세팅된다.
5. **세부 코드 검토에 대한 태도**:
   1. 세팅된 프롬프트나 코드를 인간이 한 줄 한 줄 검토하기는 어렵다.
   2. 맹종이 아니라, 일단 **실제로 실행해 보면서(Try & Error)** 잘 안 되는 부분을 고치라고 피드백하는 것이 가장 효과적이다.

### 2.6. 5단계: 실행과 개선 (피드백을 통한 성장)
1. **에이전트 실행 (논문 번역 예시)**:
   1. 컨텍스트를 클리어하고, 에이전트에게 맨션 후 논문 번역을 지시한다.
   2. 결과물은 원문 순서, 수식, 테이블, 다이어그램을 유지하며 자연스럽고 전문 용어 병용이 일관성 있게 잘 번역되었다.
   3. 복잡한 형식적 완결성을 갖춘 PDF를 자동화된 시스템으로 만들어낸 것이 중요하다.
2. **중간 결과물 확인**:
   1. 번역 중간 과정에서 생성된 테이블 이미지나 번역 파일 등 중간 결과물이 많이 남는 것은 복잡한 일 처리를 위한 자연스럽고 좋은 현상이다.
3. **피드백을 통한 성장**:
   1. LLM 특성상 최초 결과가 마음에 들지 않을 수 있으며, 이럴 때는 **사산지석의 계기**로 삼아야 한다.
   2. 아쉬운 점을 피드백하여 에이전트 파일과 스크립트에도 반영하도록 요청하면, 다음 작업 시 문제가 재현되지 않고 개선된 결과가 나온다.
   3. 이는 피드백을 받은 주니어 사원이 성장하듯 **에이전트가 사람처럼 성장**하는 것이다.
4. **지속적인 개선 습관화**:
   1. 에이전트를 계속 실행하며 피드백을 주고, 요구 사항을 에이전트 파일에 반영하는 것을 습관화해야 한다.
   2. 한 번 세팅해 두면, 다음 유사 작업 시 인풋 폴더에 파일만 넣어주면 과정이 자동화되어 안정적인 결과물을 계속 얻을 수 있다.

## 3. 블로그 작성 에이전트 구축 예시
<mark>블로그 작성 에이전트는 유튜브 링크를 기반으로 인사이트를 추출하고 글감을 도출하여 글을 작성하는 2단계 파이프라인으로 구성되며, 인간의 선별 과정이 퀄리티를 높인다.</mark>

### 3.1. 블로그 에이전트의 필요성 및 1단계 (프로젝트 생성)
1. **실제 활용 사례**:
   1. 발표자는 실제로 이 에이전트를 활용하여 회사 블로그를 운영하고 있으며, 방문자 수가 AI 에이전트 도입 후 400명대에서 1만 명 수준으로 회복되었다.
2. **프로젝트 생성**:
   1. '블로그 작성' 폴더를 생성한다.
3. **터미널 실행 방식 선택**:
   1. 이번에는 VS Code 확장 프로그램 대신 터미널에서 Claude Code를 실행하여 여러 에이전트를 동시에 띄워 공동 작업을 시연한다.

### 3.2. 2단계: 에이전트 설계서 작성 및 핵심 원칙
1. **설계서 작성 과정**:
   1. 마찬가지로 Claude Project에서 AI와 함께 설계서를 작성하며, 발표자 역시 다른 LLM과의 대화와 피드백을 통해 생각을 정리했다.
2. **블로그 에이전트의 구조**:
   1. 양질의 콘텐츠를 위해 **콘텐츠 팀**처럼 에이전트 간 협업 구조를 구성했다.
   2. **유튜브 큐리에이션 파이프라인**과 **블로그 작성 파이프라인** 두 파트로 나누어 설계했다.
3. **인간 개입의 중요성 (큐리에이션)**:
   1. 에이전트에게 인터넷 리서치를 맡기면 아이디어나 인사이트가 희미해지는 경향이 있다.
   2. **인간이 양질의 유튜브를 선별하는 과정**에 개입해야 좋은 인사이트가 필터링되며, 이를 기반으로 글을 써야 최종 결과물이 좋다.
4. **설계의 핵심**:
   1. 업무 단계별 수행 방식, 에이전트 팀 구조, 사용할 기술적 도구 등이 설계의 핵심이다.
   2. 이는 안목지의 영역이지만, LLM과 대화하며 구체화하면 훌륭한 설계서가 나올 수 있다.
5. **기술 도구 선정 (YT-DLP)**:
   1. 설계서 작성 중, 유튜브 자막 추출 도구에 대해 질문이 나오면 **YT-DLP** 사용을 선택한다.
   2. YT-DLP는 무료로 유튜브 관련 내용과 지표를 가져오는 도구이며, Claude Code가 알아서 구현해 준다.
   3. 이러한 경험(시행착오)이 쌓여야 AI를 더 잘 활용할 수 있다.
6. **에이전트 영역 분리 원칙**:
   1. **코드 스크립트**: 정확하고 빠르지만 경직적이다.
   2. **LRM 에이전트**: 판단이 필요하고 변동성에 유연하게 대처해야 하는 영역을 담당하도록 업무 영역을 분리하는 것이 인간의 역할이다.

### 3.3. 3단계 (설계 검토) 및 4단계 (에이전트 세팅)
1. **설계 검토 (Plan Mode)**:
   1. 논문 번역 때와 마찬가지로 설계서를 넣고 Plan Mode로 전환하여 AI와 협업하며 설계서를 업데이트하고 탄탄하게 만든다.
2. **에이전트 세팅**:
   1. 준비된 설계서를 기반으로 에이전트 세팅을 요청하면, Claude Code가 폴더 구조, `Claude.md`, 스킬 및 서브 에이전트를 세팅한다.
3. **세팅 결과 확인**:
   1. 폴더 구조, 필요한 에이전트, 스킬, **스타일 가이드**까지 잘 정리되어 세팅된다.
4. **코드 검토 태도**:
   1. 세부 프롬프트나 코드를 직접 검토하기보다, **실제로 해보면서** 잘 안 되는 부분을 고치라고 피드백하는 것이 효과적이다.
   2. 이를 위해서는 좋은 결과물에 대한 **성공 기준(상)**을 가지고 있어야 AI에게 좋은 피드백을 줄 수 있다.

### 3.4. 5단계: 실행, 피드백, 그리고 에이전트 성장
1. **실행 및 초기 결과**:
   1. 에이전트는 유튜브 링크를 받아 인사이트를 뽑고 글감을 도출한 뒤, 이를 엮어 글을 쓰는 2단계 파이프라인으로 작동한다.
   2. 크리에이터/강사에 대한 비판 콘텐츠 영상들을 인풋으로 사용하여 글을 작성해 본다.
2. **작업 지시 및 동시 실행**:
   1. 큐레이터에게 유튜브 링크를 전달하여 요약, 인사이트 추출, 글감 정리를 시킨다.
   2. 터미널에서 여러 에이전트를 띄워 세 가지 영상을 동시에 큐리에이션 시킨다.
3. **피드백을 통한 개선 (1차)**:
   1. 초기 요약 결과에 대해 파일명 수정, 썸네일 이미지 및 원본 링크 추가 등의 피드백을 주자, 에이전트가 이를 반영하여 개선한다.
4. **글 작성 및 2차 개선 (서브 에이전트 추가)**:
   1. 피드백이 반영된 자료를 기반으로 글을 작성한다.
   2. 글에 **사파(삽화)**를 추가하기 위해, **비주얼 에디터**라는 서브 에이전트를 추가하도록 지시한다.
      * 이 서브 에이전트는 나노바나(Nanobana) API를 이용하거나 웹에서 스크린샷을 찍어 MD 파일에 이미지를 추가하도록 설계된다.
   3. Claude Code는 지시만 하면 스스로 구현 방법을 찾아 코드를 작성하고 반영한다.
   4. 작업 중 막히면 **Claude Code에게 먼저 물어보는 것**이 빠르며, 이를 통해 요구 사항이 반영된 더 강력한 에이전트 시스템으로 성장시킬 수 있다.
   5. 최종 결과물로 에이전트가 사파를 그리고 스크린샷을 스스로 찍어 완성한 결과물을 얻는다.
   6. 이는 AI와 인간이 **휴먼 인 더 루프**로 협력하여 퀄리티 있는 결과물을 만들어내는 방식이다.

## 4. 결론 및 활용 제언
<mark>Claude Code는 코딩 에이전트를 넘어선 궁극의 범용 에이전트이며, 성공적인 활용은 코딩 기술보다 업무에 대한 정확한 메타인지와 언어 전달 능력에 달려있다.</mark>

### 4.1. Claude Code의 중요성 및 활용 원칙
1. **현재 시점의 중요성**:
   1. 현재는 ChatGPT보다 **Claude Code나 Codex**를 배워야 할 시점이며, 이는 모든 업무에 적용 가능한 궁극의 범용 에이전트이다.
2. **성공적인 사용의 핵심**:
   1. 코딩 기술이나 도구 이해가 아닌, **내 업무에 대한 정확한 메타인지**와 이것을 **언어로 잘 전달하는 능력**이 가장 중요하다.
3. **고질적 문제 해결**:
   1. 할루시네이션이나 낮은 퀄리티 문제는 나만의 에이전트를 세팅하면 거의 해결 가능하다.
   2. 할루시네이션이 문제라면 더 정확한 정보를 찾을 도구를 쥐여주는 방식으로 AI의 문제를 주도적으로 해결할 수 있다.
4. **초기 시도 권장**:
   1. 우선 **나만의 에이전틱한 워크플로우를 만들어 보는 시도**가 매우 중요하다.
   2. 초보자는 다른 플러그인 도구(Open Code, SuperCL 등)에 종속되지 않도록 **순정 Claude Code로 바닥부터 시도**해 보는 것을 강조한다.
   5. 매일 하는 작업에 AI를 어떻게 적용할지 고민하는 것이 필요하다.

### 4.2. 비용 및 향후 계획
1. **비용 관련**:
   1. 자유로운 사용을 위해서는 **Claude Max 플랜(월 약 15만 원)**이 사실상 필수적이며, 발표자는 월 200불 플랜을 사용 중이다.
   2. 비용이 부담된다면 **Codex나 AntiGravity**는 월 3만 원 또는 무료 수준에서도 운용이 가능하다.
2. **향후 계획**:
   1. 에이전트 설계는 기술보다 업무 이해와 창의적 접근이 중요하므로, 다양한 사람들과 교류하고 워크플로우를 공유하기 위해 **모임이나 코칭 세션**을 진행할 계획이다.
   2. 독자들의 경험과 생각을 댓글로 많이 남겨달라고 요청한다.

기존 코딩 도구의 한계를 뛰어넘고 싶다면, **완벽하게 커스터마이징 가능한 오픈소스 AI 코딩 도구**인 Pi를 만나보세요. Pi는 당신의 필요에 맞춰 시스템 프롬프트부터 모델 선택까지 모든 것을 제어할 수 있게 해주며, **클라우드 코드의 제약을 벗어나 진정한 엔지니어링의 자유**를 경험하게 해 줄 것입니다.

## 1. Pi 코딩 에이전트: Claude Code의 유일한 진정한 경쟁자
기존 코딩 도구의 한계를 뛰어넘는 완벽하게 커스터마이징 가능한 오픈소스 AI 코딩 도구인 Pi를 소개하며, Claude Code의 대안으로서 그 가능성을 탐구한다.

### 1.1. Claude Code의 한계와 Pi의 등장 배경
1.  **기존 도구의 한계**: 엔지니어는 사용하는 도구에 의해 사고방식이 제한되며, 현재 도구가 무엇을 불가능하게 만드는지 인지해야 한다.
2.  **Claude Code의 성공과 한계**:
    *   Claude Code는 에이전트 코딩 도구로서 소프트웨어 엔지니어링에 큰 변화를 가져왔으며, 초기 사용자들에게 큰 보상을 안겨주었다.
    *   하지만 성공적인 제품은 이윤 극대화를 위해 사용자 만족도보다 수익을 우선시하는 경향이 있으며, 이는 기존 사용자층(중급-고급 엔지니어)을 넘어 대중을 대상으로 하게 만든다.
    *   Anthropic은 비공개 회사이므로 자체적인 결정을 내릴 수 있다.
3.  **Pi의 등장**: 이러한 한계를 극복하고 진정한 엔지니어링의 자유를 경험하기 위해 오픈소스, 비정형, 커스터마이징 가능한 대안으로 Pi가 등장했다.

### 1.2. Pi의 핵심 철학: 오픈소스와 커스터마이징
1.  **Pi의 차별점**:
    *   **오픈소스 및 커스터마이징**: Pi는 Claude Code와 달리 오픈소스이며 핵심까지 커스터마이징 가능하다.
    *   **디자인 철학**: Claude Code는 즉시 사용 가능한 훌륭한 기본 설정을 제공하지만, Pi는 "필요하지 않으면 만들지 않는다"는 철학으로 불필요한 기능을 배제한다.
2.  **Claude Code vs. Pi 비교**:
    *   **안전성**: Claude Code는 5가지 기본 모드를 제공하지만, Pi는 기본적으로 모든 것에 접근 가능하며 사용자가 직접 안전 기능을 구축해야 한다. 이는 엔지니어에게 더 많은 제어권을 제공한다.
    *   **시스템 프롬프트**: Claude Code는 10,000 토큰의 상세한 시스템 프롬프트를 제공하지만, Pi는 200 토큰으로 모델이 스스로 생각하고 문제를 해결하도록 한다.
    *   **관찰 가능성**: Claude Code는 많은 기능이 추상화되어 있지만, Pi는 최대한 많은 정보를 사용자에게 투명하게 제공한다.
    *   **모델 선택**: Claude Code는 자체 클라우드 모델 사용을 권장하지만, Pi는 사용자가 원하는 어떤 모델이든 자유롭게 선택할 수 있다.
3.  **엔지니어에게 미치는 영향**:
    *   **폐쇄 소스 vs. 오픈소스**: Pi는 오픈소스로서 사용자가 기능을 비활성화하거나, 덮어쓰거나, 특정 버전을 고정할 수 있는 자유를 제공한다.
    *   **강력한 의견 vs. 유연성**: Claude Code는 강력한 기본 설정을 가지고 있어 변경이 어렵지만, Pi는 사용자가 원할 때 언제든지 롤백하거나 수정할 수 있다.
    *   **프로그래밍 지원**: 두 도구 모두 프로그래밍 지원을 제공하며, 이는 에이전트 코딩을 넘어 제품 개발 및 터미널 환경 탈출에 필수적이다.
4.  **결론**: Pi는 커스터마이징과 확장성을 추구하는 고급 엔지니어에게 적합하며, Claude Code는 즉시 사용 가능한 최고의 에이전트 코딩 도구이다.

### 1.3. Pi 에이전트의 기본 기능 및 커스터마이징
1.  **기본 Pi 에이전트 하네스**:
    *   기본 Pi 실행 시 터미널 인터페이스와 간단한 에이전트 루프가 나타난다.
    *   생각 과정이 항상 노출되며, Claude Code와 유사한 상태 표시줄(푸터)이 있다.
    *   표준화된 기능(포크 트리, 로그인, 새 세션 시작 등)을 제공한다.
2.  **커스터마이징: Pi를 나만의 것으로 만들기**:
    *   **"나만의 Pi" 만들기**: 사용자는 Pi를 자신만의 방식으로 커스터마이징할 수 있다.
    *   **순수 집중 모드 (Pure Focus)**:
        *   `pi-e`와 확장을 사용하여 화면에 다른 정보 없이 오직 사용자와 모델 간의 대화만 남길 수 있다.
        *   이는 사용자가 흐름을 유지하고 집중하는 데 도움을 준다.
    *   **커스텀 푸터 (Custom Footer)**:
        *   확장을 스택하여 모델 정보, 컨텍스트 창 크기 등을 표시하는 커스텀 푸터를 만들 수 있다.
        *   Claude Code에서도 푸터 커스터마이징이 가능하지만, Pi는 더 나아가 다양한 기능을 제공한다.
    *   **컴포넌트 로딩 위치 지정**:
        *   명령어, 스킬, 에이전트 등의 컴포넌트를 로드할 위치를 지정할 수 있다.
        *   이를 통해 사용자는 자신의 에이전트 코딩 도구를 구성하는 핵심 요소를 어디서 로드할지 결정할 수 있다.
3.  **위젯 (Widgets)**:
    *   **목적 기반 위젯**: 에이전트 부팅 시 목적을 질문하고, 이를 기본 시스템 프롬프트에 추가하여 에이전트의 전역적인 방향성을 설정할 수 있다.
    *   **UI 요소**: 위젯은 터미널 세션 동안 유지되는 UI 조각으로, 목적과 같은 정보를 지속적으로 표시할 수 있다.
    *   **TypeScript 확장**: 위젯은 TypeScript 확장으로 작성되며, 나중에 자세히 다룰 예정이다.
4.  **도구 카운터 (Tool Counter)**:
    *   새로운 푸터와 함께 에이전트가 실행하는 도구를 기록하는 기능을 추가할 수 있다.
    *   토큰 사용량(입력/출력)도 표시하여 에이전트의 활동을 추적한다.

### 1.4. Pi의 고급 커스터마이징 및 기능
1.  **테마 사이클러 (Theme Cycler)**:
    *   다양한 테마를 순환하며 UI의 시각적 스타일을 변경할 수 있다.
    *   이는 모델이나 컨텍스트와 무관하게 에이전트 하네스 레벨에서 작동하는 기능이다.
2.  **서브 에이전트 지원 구축 **:
    *   **기본 부재**: Pi는 기본적으로 서브 에이전트 지원이 없으므로 사용자가 직접 구축해야 한다.
    *   **구현**: `pure focus` 확장과 함께 서브 에이전트 지원을 추가하여, `/sub` 명령어로 서브 에이전트를 실행하고 결과를 UI에 지속적으로 표시할 수 있다.
    *   **다중 서브 에이전트 실행**: 여러 서브 에이전트를 동시에 실행하고, 각 에이전트의 진행 상황을 추적하며, 필요에 따라 제거하거나 확장할 수 있다.
    *   **활용**: 엔지니어링 작업, 일회성 작업, 테스트, 검토, 문서화 등 다양한 작업에 맞춤형 서브 에이전트 시스템을 구축할 수 있다.
3.  **"Till Done" 확장 **:
    *   **작동 방식**: 에이전트가 특정 작업을 완료할 때까지 다른 작업을 차단하고, 작업 목록을 관리하며, 완료 시까지 반복 실행하도록 한다.
    *   **커스텀 규칙**: 사용자는 에이전트의 행동에 대한 커스텀 규칙을 정의할 수 있다.
    *   **예시**:
        *   `ls` 명령 실행을 차단하고, 먼저 할 일 목록에 항목을 추가하도록 강제한다.
        *   코드베이스의 파일 구조를 트리 형태로 매핑하는 `tree.mmd` 파일을 생성한다.
        *   TypeScript 파일별로 요약 정보를 추가하는 작업을 위해 할 일 목록을 생성하고, 각 파일에 대한 작업을 완료한다.
    *   **모델 성능 보완**: 낮은 지능의 모델(예: Haiku)을 사용하더라도 하네스 제어를 통해 오류를 보완하고 효율적인 작업을 수행할 수 있다.
    *   **장점**: 인루프 에이전트 코딩에 유용하며, 에이전트의 행동을 제어하고 결정론적 요소를 추가할 수 있다.

### 1.5. Pi와 Claude Code의 상세 비교
1.  **에이전트 하네스 비교**:
    *   **오픈소스 vs. 폐쇄소스**: Pi는 오픈소스, Claude Code는 폐쇄소스이다.
    *   **컨텍스트 창**: Pi는 200 토큰, Claude Code는 10,000 토큰을 제공한다.
    *   **기본 도구**: Pi는 읽기, 쓰기, bash 등 4개의 기본 도구를 제공하며, Claude Code는 더 많은 기본 도구를 제공한다.
    *   **기본 권한**: Pi는 기본적으로 YOLO 모드(모든 권한 허용)로 실행된다.
    *   **훅 (Hooks)**: Pi는 Claude Code보다 더 많은 플러그인 지점을 제공하여 에이전트의 라이프사이클에 대한 더 많은 제어를 가능하게 한다.
    *   **모드**: Pi에는 명확한 모드가 없으며 YOLO 모드로 작동한다. Claude Code는 다양한 모드를 제공한다.
    *   **커스터마이징**: Pi는 거의 모든 것을 커스터마이징할 수 있는 반면, Claude Code는 제한적인 커스터마이징만 가능하다.
    *   **모델 지원**: Pi는 거의 모든 모델을 지원하지만, Claude Code는 자체 모델 사용을 권장한다.
    *   **로그인**: Pi는 다양한 API 키 및 구독 플랜을 지원한다.
    *   **비용/라이선스**: Pi는 BYO(Bring Your Own) 방식이며, Claude Code는 구독 기반이다.
    *   **비용 관련 문제**: Claude Code는 자체 플랜 사용을 제한하며, API 키 또는 전용 플랜만 허용한다.
2.  **컨텍스트 엔지니어링 및 프롬프트 엔지니어링**:
    *   **메모리 파일**: Claude Code는 `cloud.md`, Pi는 `agents.md`를 기본 메모리 파일로 사용한다.
    *   **스킬 및 명령어**: 두 도구 모두 스킬과 명령어를 지원하며, 이는 업계 표준이 되었다.
3.  **고급 기능 비교**:
    *   **서브 에이전트**: Claude Code는 `task` 도구를 통해 네이티브 서브 에이전트 지원을 제공하지만, Pi는 사용자가 직접 구축해야 한다.
    *   **작업 목록/할 일**: Claude Code는 내장된 작업 목록을 제공하지만, Pi는 사용자가 직접 구현해야 한다.
    *   **멀티 에이전트 기능**: Claude Code는 에이전트 팀을 배포하고 통신하는 멀티 에이전트 기능을 제공한다. Pi는 기본적으로 제공하지 않지만, 사용자가 직접 구축할 수 있다.
    *   **시스템 프롬프트**: 두 도구 모두 시스템 프롬프트 커스터마이징이 가능하다.
    *   **압축 기능**: 컨텍스트 창이 부족할 때 사용되는 압축 기능은 두 도구 모두 지원한다.
    *   **프로그래밍 및 SDK**: 두 도구 모두 프로그래밍 모드를 지원하지만, Pi는 진정한 커스터마이징을 위해 TypeScript SDK를 제공한다. Claude Code는 SDK 지원에서 더 우수하다.
    *   **내보내기 기능**: 두 도구 모두 내보내기 기능을 지원한다.
    *   **비용**: 프로그래밍 모드 사용 시 Claude Code와 Pi 모두 API 키 또는 모델 제공업체 플랜을 사용해야 한다.

### 1.6. Pi의 티어 2 기능: 멀티 에이전트 오케스트레이션
1.  **에이전트 팀 (Agent Team)**:
    *   **개념**: 여러 에이전트가 협력하여 작업을 수행하는 팀을 구성할 수 있다.
    *   **예시**: 스카우트, 플래너, 빌더, 리뷰어, 문서화 담당자, 레드팀 등으로 구성된 에이전트 팀을 통해 복잡한 작업을 처리한다.
    *   **작동 방식**: 주 에이전트가 직접 작업을 수행하는 대신, 팀 에이전트에게 작업을 위임한다. 예를 들어, 스카우트 에이전트가 TS 파일을 찾으면, 플래너 에이전트가 계획을 세우고 빌더 에이전트가 파일을 수정한다.
    *   **특징**:
        *   주 에이전트는 팀 에이전트로부터 정보를 받아 작업을 진행한다.
        *   여러 에이전트가 협력하여 단일 목표를 달성한다.
        *   스카우트 에이전트가 정보를 찾고, 빌더 에이전트가 해당 정보를 바탕으로 작업을 수행하는 방식으로 작동한다.
2.  **에이전트 팀 선택 및 구성**:
    *   `/agent team` 명령어를 통해 미리 정의된 에이전트 팀을 선택할 수 있다.
    *   `teams.yaml` 파일을 통해 사용자 정의 에이전트 팀을 구성할 수 있다.
3.  **시스템 선택 (System Select)**:
    *   **기능**: 특정 에이전트의 시스템 프롬프트를 선택하여 에이전트의 역할을 변경할 수 있다.
    *   **예시**: 브라우저 에이전트로 전환하여 웹사이트를 탐색하고 정보를 요약하는 작업을 수행한다.
    *   **확장성**: 여러 확장을 스택하여 에이전트의 기능을 더욱 확장할 수 있다.
4.  **손상 제어 (Damage Control)**:
    *   **목적**: 에이전트가 위험한 작업(예: `rm -rf`)을 수행하는 것을 방지하기 위해 훅을 사용하여 특정 명령어를 차단한다.
5.  **에이전트 체인/파이프라인 (Agent Chain/Pipeline)**:
    *   **개념**: 여러 에이전트를 순차적으로 연결하여 복잡한 워크플로우를 구축한다.
    *   **예시**: 세 개의 스카우트 에이전트를 체인으로 연결하여 이전 에이전트의 출력을 바탕으로 정보를 수집한다.
    *   **활용**: 계획, 빌드, 검토 단계를 거치는 에이전트 팀을 체인으로 구성하여 복잡한 작업을 자동화한다.
    *   **장점**: 에이전트의 컴퓨팅 능력을 확장하고, 전문화된 에이전트를 활용하여 차별화된 결과를 얻을 수 있다.

### 1.7. Pi의 개발자 및 커뮤니티
1.  **개발자**: Pi는 Mario Zechner에 의해 개발되었으며, 그는 오픈소스 커뮤니티에 기여하는 영향력 있는 엔지니어이다.
2.  **Openclaw와의 관계**: Pi는 Openclaw(이전 Maltbot, Clawbot)를 구동하는 에이전트 코딩 도구이다.
3.  **MCP 지원 부재**: Pi는 MCP(Multi-Command Processing) 지원이 없지만, 스크립트나 CLI를 통해 스킬을 호출할 수 있다.
4.  **도구 재정의 (Tool Override)**: 기본 도구(편집, 쓰기, bash 등)를 재정의할 수 있다.
5.  **도구 관찰 가능성**: 두 도구 모두 도구 관찰 가능성을 제공한다.

### 1.8. Pi의 커스터마이징 가능성과 Claude Code와의 비교
1.  **멀티 에이전트 오케스트레이션**:
    *   Pi는 에이전트 팀과 에이전트 체인/파이프라인을 구축할 수 있는 기능을 제공한다. Claude Code는 에이전트 팀은 지원하지만, 에이전트 체인/파이프라인은 지원하지 않는다.
    *   Pi는 사용자가 직접 멀티 에이전트 기능을 구축할 수 있는 유연성을 제공한다.
2.  **이벤트 및 훅**:
    *   두 도구 모두 다양한 이벤트를 지원하며, Pi는 더 많은 훅을 제공하여 세밀한 제어를 가능하게 한다.
3.  **커스터마이징 비교**:
    *   **Pi의 강점**:
        *   시스템 프롬프트 커스터마이징
        *   25개 이상의 훅 사용
        *   푸터(상태 표시줄) 업데이트
        *   테마 변경
        *   모든 모델 선택 가능
        *   CLI 플래그 전달
        *   프로그래밍 모드뿐만 아니라 인루프 에이전트 코딩 도구 내에서 도구 등록
        *   커스텀 키 바인딩 등록
        *   기본적으로 YOLO 모드 권한
    *   **Claude Code의 한계**: 스킬 또는 MCP를 사용해야 하며, Pi만큼의 유연성을 제공하지 않는다.
4.  **메시지 큐잉**: 두 도구 모두 메시지 큐잉 기능을 지원한다.
5.  **메타 에이전트 (Meta Agent)**:
    *   **개념**: 에이전트가 다른 에이전트를 구축하는 수준의 메타 레벨에서 작업한다.
    *   **예시**: Pi의 기능을 여러 에이전트 전문가로 분해하고, 메타 에이전트가 이들을 조합하여 새로운 Pi 에이전트를 생성한다.
    *   **장점**: 전문화된 에이전트를 활용하여 복잡한 솔루션을 빠르게 구축하고, 에이전트 코딩의 미래를 보여준다.
    *   **특화의 중요성**: SAS 공격에 대비하기 위해 전문화된 솔루션을 구축하는 것이 중요하며, 이는 도구의 한계를 극복하는 데서 시작된다.
6.  **Pi 코드베이스 및 확장**:
    *   Pi의 커스터마이징은 주로 확장(extensions) 디렉토리에서 이루어진다.
    *   확장은 새로운 명령어 등록, 도구 등록, 훅(on input, on agent end, on tool call 등) 활용을 통해 구현된다.
7.  **엔지니어링 vs. 바이브 코딩**:
    *   에이전트가 무엇을 하는지 아는 것이 엔지니어링이며, 모르는 것은 바이브 코딩이다.
    *   엔지니어는 에이전트의 행동을 이해하고 제어해야 한다.

### 1.9. 전략 및 결론: Pi와 Claude Code의 활용 방안
1.  **Claude Code의 강점**:
    *   **엔터프라이즈 플랫폼 채택**: 대규모 기업이나 팀에서는 Claude Code를 사용하는 것이 필수적이다.
    *   **안정성**: 변경 사항으로 인해 깨지지 않는 안정적인 에이전트가 필요할 때 Claude Code가 유리할 수 있다.
    *   **기본 기능**: 즉시 사용 가능한 기능과 간단한 커스터마이징이 필요할 때 적합하다.
2.  **Pi의 강점**:
    *   **완전한 제어**: 에이전트 하네스, 시스템 프롬프트, 도구, 이벤트 루프 등에 대한 완전한 제어를 원할 때 사용한다.
    *   **모델 자유도**: 어떤 모델이든 자유롭게 사용할 수 있다.
    *   **Claude Code 헤지**: Claude Code에 대한 종속성을 줄이고자 할 때 유용하다.
    *   **잠금 방지**: 특정 도구에 종속되지 않고자 할 때 선택한다.
    *   **최대 커스터마이징**: 최고의 커스터마이징 유연성을 원할 때 Pi를 선택한다.
    *   **고급 사용자**: 기본 기능을 마스터하고 에이전트의 한계를 넘어서고 싶을 때 적합하다.
3.  **전략**:
    *   **"And" 접근 방식**: Claude Code와 Pi를 상호 배타적으로 선택하기보다, 두 도구를 함께 활용하는 전략을 권장한다.
    *   **주요 도구와 헤지**: 리더인 Claude Code에 집중하되, 오픈소스이자 고도로 커스터마이징 가능한 Pi로 헤지한다.
    *   **비율**: 현재 80% Claude Code, 20% Pi를 사용하여 실험적인 차세대 에이전트 코딩에 활용한다.
    *   **목적에 맞는 도구 사용**: 각 작업에 가장 적합한 도구를 적절한 비용으로 사용한다.
4.  **에이전트 코딩 경로**:
    *   기본 에이전트에서 시작하여 컨텍스트 및 프롬프트 엔지니어링을 통해 개선하고, 에이전트를 커스터마이징하며, 오케스트레이터 에이전트를 사용하여 전문화된 에이전트를 제어한다.
5.  **결론**:
    *   Pi는 제어, 심층 커스터마이징, 실험적인 차세대 에이전트 코딩에 이상적이다.
    *   엔지니어는 도구에 의해 제한되므로, 다양한 도구를 실험하고 자신만의 솔루션을 구축해야 한다.
    *   현재는 "슬롭의 시대"이자 "에이전트의 시대"이며, 전문화가 중요하다.
    *   에이전트 코딩 도구 자체를 커스터마이징하는 것이 핵심 아이디어이다.
    *   궁극적으로는 코드베이스가 스스로 실행되는 강력한 에이전트 팀을 구축하는 것을 목표로 한다.
    *   현재 승자는 없으며, 실험자, 사상가, 빌더만이 앞서 나갈 것이다.

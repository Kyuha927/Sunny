유니티 개발자가 **클로드 코드(CLI 툴)**를 활용하여 작업 효율을 극대화하는 실질적인 방법을 제시합니다. 단순히 코드를 생성하는 것을 넘어, **소스 코드 기반의 심층 학습**을 통해 복잡한 개념을 이해하고, **UXML/USS를 활용한 UI 자동 생성** 및 **데이터 참조 자동화** 등 반복적이고 귀찮은 수작업을 AI에게 맡기는 구체적인 적용 사례를 배울 수 있습니다. 이 콘텐츠는 AI를 단순한 코딩 도구가 아닌, **개발 프로세스 전반을 혁신하는 강력한 파트너**로 활용하는 방법을 알려주어 개발 생산성을 비약적으로 높여줄 것입니다.

## 1. AI(CLI 툴) 활용을 위한 개발 환경 준비 및 기본 원칙

### 1.1. Git을 활용한 변경 사항 관리 원칙

1. **Git 설정의 중요성**: 항상 AI(CLI 툴) 사용 시 **Git을 세팅**해야 한다고 생각하는 것이 중요함 .
2. **변경 사항 확인 및 이해**: 수정한 파일들의 모든 변경 사항(Changes)을 **전부 읽어보고** , 모든 변경 사항이 **완전히 이해**되었을 때만 커밋을 진행함 .
3. **방향 상실 방지**: 변경 사항을 파악하지 못한 상태에서 작동된 후 문제가 생기면 **되돌릴 수 없게** 되므로, 모든 변경 사항을 꼼꼼히 확인하는 과정이 필수적임 .
4. **변경 사항 분리 및 비교**: 필요시 변경 사항을 분리하여  두 개로 띄워놓고 **비교**하면서 이해한 후 커밋함 .

### 1.2. AI(CLI 툴) 활용 목적 및 기본 접근

1. **영상 제작 목적**: 본 영상에서는 AI(클로드 코드)를 **유니티에서 어떻게 잘 사용할 수 있을지**에 대한 생각을 담아 공유함 .
2. **가장 기본적인 활용**: 단순히 "이런 거 만들어 줘"와 같은 **코딩 명령**으로 AI를 사용할 수 있음 .
3. **학습을 위한 활용**: 코딩 외에도 **특정 개념을 공부**할 때 AI를 활용할 수 있음 .

### 1.3. CLI 툴을 활용한 소스 코드 기반 심층 학습

1. **소스 코드 기반 설명 요청**: 예를 들어, 특정 기술(예: 피시넷의 클라이언트 사이드 프리딕션)에 대해 설명해 달라고 요청할 수 있음 .
2. **도큐먼트 한계 극복**: 웹사이트 도큐먼트의 설명이 부족하더라도, CLI 툴은 **소스 코드를 직접 찾아 읽고** 설명을 제공할 수 있음 .
3. **상호작용을 통한 이해 증진**: AI의 설명을 기반으로 "이것이 저것이라는 거지?"와 같이 **반문**하고, 답변을 통해 이해가 될 때까지 질문과 답변을 반복하는 과정이 도큐먼트만 보는 것보다 훨씬 유용함 .
4. **CLI 툴 사용 권장**: HPT나 퍼플렉시티 등에서 웹 검색도 좋지만, 코드를 짤 때 모르는 것이 있다면 **CLI 툴을 꼭 사용**하라고 권장함 .
5. **소스 코드 단에서의 이해**: 꼬리에 꼬리를 무는 질문을 통해 **소스 코드 단에서 이해**할 수 있도록 읽어오는 AI의 힘이 매우 크며, AI가 설명에 능숙하여 이 점이 좋음 .
6. **작업 확인**: AI가 소스 코드를 직접 확인하고 답변하는 것이 더 정확함 .
7. **토큰 사용**: 이 과정에서 꽤 많은 토큰을 사용했음을 확인 .

### 1.4. AI의 답변 내용 및 학습 효과

1. **답변 내용 예시**: AI는 작동 방식, 서버 구성, 안전성 등에 대한 설명을 제공하며, 예제와 같은 특징(예: N계 입력을 매번 재전송하는 시스템)을 언급함 .
2. **후속 질문의 유용성**: 답변 후 "그래서 뭐가 뭐라는 거지?"라고 물으면 맞는지 아닌지, 혹은 어떤 것에 가까운지 피드백을 받아 **공부할 때 유용**함 .
3. **개인적 활용 사례**: 발표자 본인도 리눅스 영상 등을 올릴 때 궁금한 점을 직접 소스 코드를 받아 물어보며 **도움을 많이 받음** .
4. **매뉴얼 대비 장점**: 딱딱한 매뉴얼 문서와 달리, AI는 **대화체로 천천히 차근차근** 알려줄 수 있다는 장점이 있음 .

## 2. UI 툴킷을 활용한 UI 자동 생성 및 참조 자동화

### 2.1. UI 툴킷(UXML/USS)을 이용한 UI 생성

1. **기존 UI 작업 방식**: 기존에는 패널을 만들고 버튼 등을 **수동으로 하나하나** 만들어야 했음 .
2. **UXML/USS의 특성**: UI 툴킷의 UXML과 USS는 **HTML과 CSS와 유사**하며 텍스트로 되어 있어 AI가 바로 생성 가능함 .
3. **AI를 통한 UI 생성**: AI에게 UI 툴킷을 이용하여 UI를 만들어 달라고 요청하면 **자동으로 생성**되어 훨씬 수월해짐 .
4. **반복 작업 자동화**: 생성된 UI 코드를 `.md` 파일 등에 기입해 두면, 앞으로 UI를 만들 때 AI가 **직접 코드를 짜주도록** 할 수 있음 .
5. **스타일링 및 결과물**: 텍스트 기반이므로 이미지 삽입이나 CSS를 이용한 **다양한 스타일 적용이 용이**하며, 기존 유니티 UI보다 나은 결과물을 간단하게 뽑아낼 수 있음 .
6. **UI 생성 확인**: AI가 생성한 UI 코드를 확인 .

### 2.2. UI 툴킷 기반 작업의 장점과 AI 활용 용이성

1. **스타일 적용**: 원하는 스타일(예: 기존에 쓰던 스타일)을 지정하여 UI를 만들 수 있으며, 설정 UI, 게임 테마 옵션 등 **추가 작업도 쉽게** 가능함 .
2. **인스펙터 작업 회피**: UI 툴킷은 텍스트 기반이므로, 인스펙터에서 **직접 끌어다 놓을 필요 없이**  클래스 이름(USS)을 이용해 쿼리(Query)를 돌려 버튼 등을 할당하거나 구독할 수 있음 .
3. **AI 활용 용이성**: 파일 형태로 되어 있어 AI가 사용하기가 **매우 쉬움** .
4. **결론**: UI를 **굉장히 쉽게** 처리할 수 있으며, 이는 UI 툴킷의 장점이기도 함 .

## 3. ScriptableObject 및 데이터 참조 자동화

### 3.1. 텍스트 기반 데이터 참조 찾기 및 자동화

1. **참조 찾기의 번거로움**: ScriptableObject(SO)나 `.asset` 등으로 끝나는 데이터들의 **참조를 찾는 작업은 매우 귀찮음** .
2. **참고 기반 작업 요청**: 발표자는 주로 잘 된 작업물(참조가 잘 된 것들)을 AI에게 **참고하여 다음 작업을 진행**하도록 요청하는 방식을 선호함 .
3. **데이터 형식**: 몬스터 데이터 등은 **YAML 형식의 텍스트 데이터**로 이루어져 있음 .
4. **GUID와 텍스트 데이터**: 애니메이션 할당 등은 메타 파일에 있는 **GUID를 찾아서 넣는 것**일 뿐이며, 결국 텍스트로 되어 있으므로 AI가 읽을 수 있음 .
5. **AI의 학습 및 적용**: AI가 이 텍스트 데이터를 읽고 학습한 후, 스테이지 2의 데이터를 예시로 들어 FBX를 찾고 애니메이션을 할당하는 작업을 진행함 .
6. **파일 경로 기반 작업**: 직접 폴더 경로를 지정하여 애니메이터를 읽으라고 하면 잘 읽어올 것이며, 유니티 파일(`.asset` 등)은 내부적으로 **YAML 형식의 텍스트 데이터**임 .

### 3.2. 텍스트 기반 작업의 이점 및 가이드라인 생성

1. **웹 검색과의 차이**: 로컬 컴퓨터에서 AI가 직접 파일을 읽어 작업하는 것은 웹사이트에서 검색하여 복사 붙여넣기 하는 것과는 **차원이 다른 수준**임 .
2. **작업 가이드라인 생성**: 작업 후, 애니메이션 에셋 위치, 데이터 위치 등을 설명하는 **작업 가이드라인을 AI에게 만들도록** 요청할 수 있음 .
3. **반복 작업 효율화**: 이 가이드라인을 기반으로 다음 작업들을 수월하게 할당할 수 있으며, **같은 문제로 고생하는 것을 방지**할 수 있음 .
4. **참조 확인**: 작업 후 실제로 참조가 제대로 되었는지 확인하면, 다른 참조되지 않은 항목들도 **한 번 해결하면 나머지 전체에 순식간에 적용**할 수 있음 .
5. **GUI 작업의 자동화**: 마우스로 끌어놓아야 하는 GUI 작업조차도 내부적으로 **YAML 형식의 텍스트 데이터**로 되어 있어 AI가 수정하여 자동으로 끌어다 놓는 작업이 가능함 .
6. **개인 가이드 폴더**: 발표자는 다른 프로젝트에서 클로드 전용 가이드 폴더를 만들어 문제가 생겼을 때 **보고 바로 적용**할 수 있도록 구현해 두었음 .

## 4. 로컬라이제이션(다국어 지원) 작업 자동화

### 4.1. 로컬라이제이션 설정 파일 분석 및 데이터 구조

1. **로컬라이제이션 패키지 활용**: 로컬라이제이션 패키지 내에서 **언어 지원 작업**을 할 수 있음 .
2. **설정값 분석**: 설정 파일들을 보면 내부적으로 **값을 텍스트로 써 놓은 형태**임 .
3. **테이블 구조**: AI에게 설정값 추가를 요청하면, 테이블이 생성되며 영어(EN)와 한국어(KR)의 ID와 로컬라이제이션 값이 매칭되어 있는 것을 볼 수 있음 .
4. **YAML 형식 확인**: 이 모든 것이 결국 **YAML 형식의 데이터**로 되어 있음을 확인할 수 있음 .

### 4.2. 다국어 번역 및 UI 적용 자동화

1. **테이블 추가 확인**: 요청 후 로컬라이제이션 테이블에 항목이 추가된 것을 확인 .
2. **키값 및 언어 추가**: 공유(Shared) 테이블에 키를 추가하고 EN, KR에 같은 ID 값으로 항목을 추가하면 UI에 보이게 됨 .
3. **추가 언어 번역**: 이미 영어와 한국어 작업이 되어 있다면, **일본어나 중국어 등의 칸을 만들고** , 지금까지 작업한 것을 기반으로 AI에게 **자연스럽게 번역하여 테이블에 추가**해 달라고 요청하면 번역 작업이 수월해짐 .
4. **UI 적용**: 로컬라이제이션 설정을 UI에 적용해 달라고 요청하면 그 부분도 수월하게 진행 가능함 .

## 5. AI(CLI 툴) 활용의 총평 및 공유 제안

### 5.1. Git 및 기타 작업 활용

1. **Git 활용**: Git 관련 작업은 AI가 **당연히 잘 처리**함 .
2. **핵심 메시지**: 내부적으로 데이터 에셋들이 **YAML 형태의 텍스트 데이터**로 되어 있으며, 터미널 상에서 돌아가는 CLI 툴 기반 AI들이 이러한 **불필요하고 귀찮은 작업들을 모두 처리**할 수 있다는 것이 중요함 .

### 5.2. AI 활용 범위 확장 및 공유 제안

1. **단순 코드 작성을 넘어서**: AI를 단순히 "코드 작성해 줘"에서 그치지 않고, 다음과 같이 활용할 수 있음 :
    * 모르는 것을 **소스 코드를 직접 확인**하여 가이드 부탁.
    * **수작업으로 하던 작업**들을 AI에게 부탁.
    * 에셋들의 **참조를 직접 찾지 않고** 부탁.
2. **활용 범위 증대**: 이처럼 AI를 활용할 수 있는 범위가 훨씬 많아짐 .
3. **영상 공유 이유**: 주변에서 클로드와 같은 CLI 툴 기반 AI를 유니티에 활용하는 것을 본 적이 없어, **활용법을 공유**하여 다른 AI 사용자들에게 도움이 되고자 영상을 제작함 .

최신 LLM 전쟁 속에서 **프로젝트 비용을 획기적으로 줄이는 현실적인 방법**을 제시합니다. GPT나 Claude 대비 저렴한 API 가격으로 에이전트 코딩 효율을 극대화하는 **GLM-5 연동 및 실제 코딩 테스트 과정**을 통해 실용적인 가성비 코딩 전략을 즉시 적용할 수 있습니다.

## 1. 최신 LLM 모델 경쟁 현황 및 에이전트 코딩의 현실
<mark>최신 LLM 모델들이 경쟁하는 가운데, 에이전트 코딩 시 성능만큼이나 **비용 효율성**이 중요하다는 점을 강조한다.</mark>

### 1.1. 주요 LLM 모델 경쟁 구도
1. 현재 **GPT**와 **오퍼스(Claude)**가 양대 산맥으로 경쟁하고 있다.
2. GPT는 최근 **코덱스 5.3** 모델을 출시했으며, 오퍼스는 **4.6** 모델이 프론티어 모델 중 하나이다.
3. 수많은 벤치마크 결과가 나오고 있지만, 실제 프로젝트 진행 시에는 **가격**이 가장 중요하다.
4. 소프트웨어 원가를 낮추기 위해서는 성능이 좋은 모델만 고집할 수 없다.

### 1.2. 기존 모델들의 높은 비용 문제
1. **오퍼스 클로드 코드 플랜**의 경우, 최대 사용량(Max)이 보통 **100달러** 정도이나, 헤비 유저는 그 이상을 사용한다.
2. 특히 **맥스 20배 플랜**을 사용하는 경우, 2주 만에 한도를 소진할 수 있다.
3. 클로드 코드에 모델을 연결했을 때 **토큰 소비가 상당**하여 비용 부담이 크다.

### 1.3. GLM 모델의 등장과 가격 정책 변화
1. 이전에는 **GLM 4.7**을 강조했으나, 이제 **GLM 5**를 중심으로 진행할 것을 안내한다.
2. GLM 5의 **API 가격**을 확인한 결과, 이전에 330달러였던 것이 현재 **670달러**로 인상되었다.
3. 과거에는 첫 가입 시 50% 할인, 레퍼럴 코드 사용 시 추가 10% 할인이 제공되었다.
4. 현재는 상장 및 실적 압박 등으로 인해 **가격 할인 폭이 많이 낮아진** 상태이다.

## 2. GLM-5 모델의 성능 및 벤치마크 분석
<mark>벤치마크 점수보다는 **실제 프로그래밍 시나리오**에서의 성능과 비용 효율성이 중요하며, GLM-5가 특정 영역에서 강점을 보일 수 있다.</mark>

### 2.1. 벤치마크의 한계와 실제 성능
1. 벤치마크는 참고용일 뿐이며, **실제 프로그래밍 기능성**은 직접 경험해야 알 수 있다.
2. **GLM 4.5** 시점에도 웬만한 과제나 간단한 스크립트 작성에서 잘 작동했으며, 구조화된 주석을 제공하면 매우 우수했다.
3. 오퍼스 4.5 출시 이후 에이전트 코딩의 황제가 되었으나, **GLM 5**도 이에 필적하는 수준이다.
4. GLM 4.7도 오퍼스 4.5와 비빌 만한 수준이었으며, 레일즈 개발자들 사이에서도 충분히 따라왔다는 평가가 있었다.
5. 현재 GLM 5는 프론티어 모델 대비 SW 벤치마크 점수는 떨어지지만, **MCP 등 다른 벤치마크에서는 많이 따라오는 모습**을 보인다.

### 2.2. 벤치마크 조작 가능성과 실제 시나리오 중요성
1. 클로드 코드 창업자는 중국 LLM들이 벤치마크를 높이려고 노력한다고 언급한 바 있다.
2. 벤치마크 달성은 강화 학습을 통해 비교적 쉬울 수 있으며, 이는 폭스바겐의 테스트 모드와 유사하다.
3. **코드 리얼드 시나리오**에서는 GLM이 오퍼스보다 뛰어난 경우가 있음을 보여준다.
4. 다만, 이 데이터는 **GLM 개발사에서 제공**한 것이므로 자체 평가일 가능성이 높다.
5. 그럼에도 불구하고, 빌드 성공률 등에서 GLM이 더 높다고 주장하는 부분이 떨어진다는 것은 다른 배치에서는 성능이 더 낮을 확률이 높음을 시사한다.

### 2.3. 비용 효율성 비교 및 코딩 전략
1. **Money Balance Over Time** 그래프를 보면, 시간이 지날수록 클로드는 비용이 많이 든다.
2. 토큰 기준으로 비교하면 비용 차이는 비교할 수 없을 정도로 크며, 오픈콜 사용 시 수천만 원이 소요될 수 있다.
3. 소프트웨어 개발에 100만 원 이상을 쓰는 것은 수익 창출이 어렵기 때문에 **원가를 최대한 줄여야 한다**.
4. 따라서 구조화된 소프트웨어를 던져주고 나머지를 코딩시키는 것이 효율적이며, **GLM 5**는 코딩 플랜을 통해 충분히 사용할 수 있는 수준이다.

## 3. GLM-5 모델을 클로드 코드(Claude Code)에 연동하는 방법
<mark>GLM-5를 클로드 코드 환경에서 사용하기 위해서는 **API 키 설정**과 **클로드 코드 설정 파일 수정**이 필요하다.</mark>

### 3.1. 클로드 코드에서 GLM-5 연동 설정
1. GLM 5 동작 방식 확인을 위해 퀵스타트 매뉴얼을 참고할 수 있다.
2. 가장 중요한 것은 **클로드 코드에서 GLM을 어떻게 연동**하는지 확인하는 것이다.
3. **'클로드 코드 GLM 코딩 플랜'**을 검색하면 연동 방법이 나와 있으며, API 키를 발급받아야 한다.
4. API 키는 계정 설정에서 발급받을 수 있으며, 클로드 코드 플랜과 별개로 관리된다.
5. 클로드 코드를 실행한 후, **`ClaudeSetting.json`** 파일을 수정하여 모델을 **GLM 5.0**으로 지정하면 된다.
6. 이 설정을 통해 오퍼스 대신 GLM 5.0을 사용하도록 지정할 수 있다.

### 3.2. 커서(Cursor) 에디터에서 GLM-5 설정 실습
1. 윈도우 기반 환경에서 **커서(Cursor)** 에디터를 사용하여 GLM 5 설정을 진행한다.
2. 커서 설정(Preferences)의 **모델스(Models)** 탭에서 기존 모델 설정을 삭제한다.
3. **API 키스(API Keys)** 섹션에서 클로드 대신 **커서(Cursor)** 설정을 선택한다.
4. GLM 5 사용 시, 데디케이드 코딩 API 대신 제공된 다른 설정을 사용하라는 안내에 따라 진행한다.
5. **커스텀 모델(Custom Model)**을 추가하고 **GLM 5**로 이름을 지정하여 애드(Add)한다.
6. API 키를 입력하고, **오픈 AI(OpenAI) 설정을 오버라이드(Override)**하여 GLM 5로 세팅을 완료한다.

## 4. GLM-5 실전 테스트 및 사용 시 주의사항
<mark>GLM-5를 이용해 자바 예제를 생성하는 테스트를 진행했으며, 사용 시 **레이트 리미트**와 **동시성 제한**에 유의해야 한다.</mark>

### 4.1. GLM-5를 이용한 자바 예제 생성 테스트
1. **자바 언어 기반**으로 간단한 **큐(Queue), 스택(Stack), 트리 구조** 예제를 작성하도록 요청했다.
2. 각 예제는 별도 디렉터리를 구성하도록 지시했다.
3. 테스트 결과, **정상적으로 동작**하는 것을 확인했으며, 큐(Queue)와 덱(Deque) 구현이 잘 나왔다.
4. 스택 구현 시 키 파일, 노드 클래스, 요소 추가/삭제, 비어있을 때 처리 등이 모두 구현되었다.
5. 요청하지 않은 **이진 탐색 트리(Binary Search Tree)**까지 알아서 작성하는 등 정석적인 코드가 생성되었다.
6. 툴 콜링도 잘 되었으며, 데이터 확인을 위해 **리프레시**를 시도했으나 데이터가 실시간으로 반영되지 않는다는 메시지가 떴다.
7. 커서에서 프롬프트를 어떻게 날리는지 정확히 알 수는 없으나, 세팅된 **GLM 모델로 API 요청이 조립되어 전송**되는 것을 확인할 수 있었다.

### 4.2. 클로드 코드 사용 시 주의사항: 동시성 제한
1. 클로드 코드와 GLM을 함께 사용할 경우 **레이트 리미트**를 주의해야 한다.
2. **컨커런시 리미트(Concurrency Limit)**는 동시에 돌릴 수 있는 탭의 개수가 정해져 있음을 의미한다.
3. GLM 4.7의 경우 동시성 제한이 3으로 늘어났으나, GLM 5는 1로 설정되어 있어 한 번에 하나만 처리 가능하다.
4. 4.7을 사용하면 여러 작업을 동시에 시킬 수 있어 충분히 활용 가능하다.

### 4.3. 모델 품질 비교 및 마무리
1. GLM 4.7의 코드 퀄리티가 나쁘지 않으며, 클로드 오퍼스 4.5로 작성한다고 해서 항상 좋은 코드가 나오는 보장은 없다.
2. 특정 분야에서는 **코덱스**가 오히려 더 끈질기게 코드를 작성해 준다는 이야기도 있다.
3. 다음 영상에서는 GLM 5를 클로드 코드에 물려서 **하나의 프로젝트를 처음부터 끝까지 돌려본 후 사용량**을 보여줄 예정이다.
4. 맥스 플랜을 저렴할 때 구매한 사람들을 축하하며, 할인을 기다렸다가 구매하는 것을 추천한다.

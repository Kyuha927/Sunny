PC 앞에 없어도 **안티그래비티 AI 에이전트를 완벽하게 제어**할 수 있는 방법을 알려드립니다. 디스코드와 웹을 연동하여 **언제 어디서든 명령을 내리고 진행 상황을 실시간으로 확인**하며, 자동 승인 및 결과 알림까지 받을 수 있습니다. 복잡한 설정 없이 **간편하게 나만의 모바일 원격 제어 시스템을 구축**하는 방법을 배우세요.

## 1. 안티그래비티 모바일 원격 제어 프로그램 제작
PC 앞에 없어도 디스코드와 웹을 연동하여 안티그래비티 AI 에이전트를 모바일에서 제어하는 시스템을 구축하는 방법을 안내한다.

### 1.1. 프로그램 생성 및 기본 설정
1.  **안티그래비티 모바일 버전 프로그램 생성**
    *   핸드폰으로 안티그래비티봇에 명령어를 내리면 PC의 안티그래비티에 자동으로 명령이 들어가고, 진행 과정은 자동 승인되며 결과는 디스코드로 알림을 주는 모바일 버전을 제작한다.
    *   실습 폴더에 제공된 가이드를 안티그래비티에 넣어주고 요청서를 참고하여 프로그램을 생성한다.
2.  **환경 변수 설정 및 파일 생성 확인**
    *   환경 변수로 포트값과 모바일 패스워드를 지정하며, 이는 보안을 위해 본인 컴퓨터에 맞게 수정하는 것이 좋다.
    *   파일들이 생성되는 과정을 확인하고, 승인을 눌러 프로그램 생성을 완료한다.
3.  **프로그램 실행 및 초기 설정**
    *   `런닷배치` 파일을 실행하여 프로그램을 실행한다.
    *   배치 파일을 사용하면 가상 환경 생성 및 필수 패키지 설치를 한 번에 할 수 있다.
    *   필수 패키지 설치가 완료되면, 테일스케일 주소(핸드폰과 통신용)와 웹페이지 주소(PC에서 테스트용)를 확인할 수 있다.
    *   1초마다 시스템 상태를 점검하는 기능이 작동한다.

### 1.2. PC 웹 브라우저를 통한 원격 제어 테스트
1.  **PC 웹 브라우저 접속 및 명령어 입력**
    *   PC에서 웹 브라우저로 접속하여 "폴더 목록 보여줘"와 같은 명령어를 입력한다.
    *   입력된 명령어는 자동으로 안티그래비티에 전달되며, 권한이 필요한 버튼은 자동으로 승인된다.
2.  **결과 확인 및 라이브 뷰 기능**
    *   명령어 실행 결과가 웹 브라우저에 표시되는 것을 확인할 수 있다.
    *   `라이브 뷰` 기능을 통해 마우스 커서 위치를 확인할 수 있으나, PC에서 실행 시 위치가 겹치는 현상이 발생할 수 있다.
    *   이 과정을 통해 입력, 자동 승인, 결과값 확인까지 완료된다.

### 1.3. 테일스케일을 이용한 모바일 연동
1.  **테일스케일 소개 및 설치**
    *   복잡한 설정 없이 여러 기기를 하나의 가상 네트워크로 묶어주는 보안 VPN 서비스인 테일스케일을 소개한다.
    *   이전의 앵그록 대신 테일스케일을 사용하는 이유는 안티그래비티 모바일 라이브 뷰 기능 사용 시 패킷 소비로 인한 제한을 없애기 위함이며, 무료로 사용할 수 있다.
    *   테일스케일 웹사이트에서 윈도우용 파일을 다운로드하여 설치한다.
    *   설치 후 작업 표시줄에 생긴 테일스케일 아이콘을 통해 로그인하며, 구글 또는 기터 계정으로 가입 및 로그인이 가능하다.
    *   로그인 시 디바이스가 커넥트되고 IP 값을 확인할 수 있다.
2.  **모바일 테일스케일 앱 설치 및 연결**
    *   핸드폰의 플레이 스토어에서 테일스케일 앱을 검색하여 설치하고 실행한다.
    *   PC와 동일한 아이디로 로그인한 후, `커넥트` 버튼을 누르고 왼쪽 상단의 아이콘을 클릭하여 연결한다.
    *   서로 연결된 상태에서 PC에서 사용했던 런 파일의 주소와 비밀번호로 접속한다.
3.  **모바일에서 원격 제어 테스트**
    *   PC에서 보았던 화면을 모바일에서 동일하게 확인할 수 있다.
    *   모바일에서 "아무 텍스트 파일이나 생성해 줘"와 같은 명령어를 입력한다.
    *   명령어가 안티그래피티에 내려지고 자동으로 승인되며, 라이브 뷰에서 진행 상황을 확인할 수 있다.
    *   작업 완료 후 결과값이 답변으로 표시된다.
    *   이로써 웹 브라우저와 안티그래프티 PC의 연결 및 모바일 제어 테스트를 완료한다.

### 1.4. 디스코드를 이용한 모바일 원격 제어
1.  **디스코드 봇 생성 및 설정**
    *   웹 브라우저 연동에 추가로 디스코드를 통해서도 원격 제어가 가능하다.
    *   디스코드 연결을 위해 봇 토큰과 채널 아이디가 필요하다.
    *   디스코드 개발자 사이트에서 새로운 애플리케이션을 생성하고, "모바일 안티"와 같이 이름을 지정한다.
    *   `리셋 토큰`을 통해 토큰 값을 발급받아 저장하고, 세 가지 연결 승인 확인 후 `세이브 체인지`를 누른다.
    *   봇을 채널에 추가하기 위해 `어스 2`를 누르고 봇 기능을 선택한 후, `샌드 메시지`, `리드 메시지`, `뷰 채널`, `어태 파일` 권한을 부여한다.
    *   생성된 URL을 브라우저에 붙여넣어 서버를 선택하고 봇을 추가한다. 서버가 없다면 플러스 버튼을 눌러 새로 생성할 수 있다.
    *   생성된 봇은 오프라인 상태이며, 안티그래비티에게 연결을 요청해야 한다.
2.  **채널 아이디 확인 및 디스코드 패키지 설치**
    *   채널에서 링크 복사하기를 통해 채널 아이디를 얻는다.
    *   봇에게 토큰과 채널 아이디를 전달하며 디스코드 연결을 요청한다.
    *   디스코드 파이썬 패키지를 설치하고, 모든 과정을 승인한다.
3.  **디스코드를 통한 원격 제어 테스트**
    *   모든 연결이 완료되면, `런 배치` 파일을 다시 실행한다.
    *   모바일 화면에 "모바일 안티"가 로그인된 것을 확인할 수 있다.
    *   모바일에서 "텍스트 파일을 만들어 줘"와 같은 명령어를 입력한다.
    *   명령어가 안티 그래픽티 버전에 들어가 자동으로 승인되고, 결과값이 디스코드로 전송되는 것을 확인할 수 있다.
    *   이로써 디스코드까지 연결되는 것을 확인한다.

## 1. 유니티 라이브 2026년 2월 주요 내용 소개
<mark>유니티 6.3 LTS의 개정된 2D E-book과 새롭게 추가된 로우 레벨 물리 2D API에 대한 소개를 중심으로 진행됩니다.</mark>

### 1.1. 유니티 6.3 LTS 개정판 2D E-book 소개
1.  **새로운 2D E-book 출시 및 개편**
    *   기존 2D E-book이 유니티 6.3 LTS 버전에 맞춰 개정되었습니다.
    *   유니티에서 2D 개발에 필요한 전반적인 내용을 총망라하고 있습니다.
    *   블로그에서 개인 정보 입력 없이 무료로 다운로드 가능합니다.
2.  **E-book의 주요 내용**
    *   **2.5D 게임 개발**: 3D 오브젝트와 2D 배경을 믹스 매치하여 2D 게임을 개발하는 방법을 다룹니다.
    *   **기초 내용**: URP 설정, PSD 파일 임포트, 드로우 오더, 소팅 레인, 카메라 퍼스펙티브 등 2D 개발 기초를 설명합니다.
    *   **스프라이트**: 스프라이트 에디터, 스프라이트 마스크 개념을 다룹니다.
    *   **2D 타일맵**: 기본적인 내용부터 롤타일, 오토타일 등 고급 내용까지 포함합니다.
    *   **2D 애니메이션**: 스켈리티라 애니메이션, 스프라이트 애니메이션 등 다양한 애니메이션 기법을 다룹니다.
    *   **개정판 추가 내용**
        *   **2D 피직스**: 박스2D 엔진 기반의 2D 물리 개발에 대한 상세한 설명과 샘플 프로젝트를 제공합니다.
            *   다양한 콜라이더 타입(엣지, 박스, 서클 등)과 타일맵 콜라이더 컴포지션 기능을 설명합니다.
            *   컬리전 매트릭스를 통한 충돌 로직 및 성능 최적화 방법을 다룹니다.
            *   리지드 바디의 물리 속성 및 코드 처리 시 고려사항을 설명합니다.
        *   **2D 라이팅**: 그림자, 립 라이트, 시간의 흐름에 따른 빛의 변화 등 디테일한 2D 라이팅 기법을 소개합니다.
            *   텍스처로 그린 라이트, 디렉션 라이트, 스팟 라이트 등 다양한 라이트 종류를 설명합니다.
            *   에디티브, 멀티플라이, 섭트랙티브 라이팅 개념과 그림자 표현 방법을 다룹니다.
            *   세컨드리 텍스처(노멀 맵, 립 라이트 영역) 설정 방법을 설명합니다.
        *   **2D 비주얼 이펙트**: 비주얼 이펙트 관련 내용도 포함합니다.
    *   **데모 소개**
        *   **잼 헌터 매치**: 2D 라이팅, 포스트 프로세싱, 비주얼 이펙트, 스프라이트 라이팅 활용을 보여주는 데모입니다.
            *   타일맵을 활용한 매치 3 퍼즐 게임 로직 및 레벨 디자인을 살펴볼 수 있습니다.
            *   쉐이더 그래프를 이용한 커스텀 쉐이더 제작 및 활용 방법을 보여줍니다.
        *   **3D 오브젝트를 2D 세상에 렌더링 (Render 3D as 2D)**
            *   유니티 6의 핵심 기능으로, 3D 오브젝트를 2D 게임에 자연스럽게 통합하는 방법을 설명합니다.
            *   Z축 활용 및 소팅 레이어(Sorting Group)를 이용한 2D/3D 오브젝트 정렬 방법을 시연합니다.
            *   3D 메시 오브젝트에 2D 콜라이더를 적용하여 2D 물리 시스템과 충돌시키는 방법을 보여줍니다.
    *   **2D 최적화 팁**: 배칭, 라이팅, 쉐도우 등 성능 최적화 관련 내용을 추가했습니다.
        *   프레임 디버그를 통한 성능 분석 및 배칭 처리 과정을 설명합니다.
        *   라이팅, 배칭, 스프라이트 아틀라스 등 성능 디버깅 툴 활용법을 다룹니다.

### 1.2. 로우 레벨 물리 2D API 소개
1.  **로우 레벨 물리 2D API 개요**
    *   유니티 6.3 LTS에 도입된 새로운 기능으로, 저수준(Low Level)에서 물리 시스템을 직접 제어하여 성능을 극대화합니다.
    *   박스2D 엔진의 최신 버전(v3)을 도입하여 로우 레벨 제어가 가능해졌습니다.
    *   컴퓨터 쉐이더를 지원하는 플랫폼에서 사용 가능하며, URP, HDRP, 빌트인 렌더러 모두 지원합니다.
2.  **주요 특징**
    *   장면과 상관없이 독립적인 물리 시스템 구축 및 게임 오브젝트 적용이 가능합니다.
    *   물리 객체를 무한정, 그리고 한꺼번에 생성할 수 있습니다.
    *   최대 64개의 CPU 코어를 동시에 활용하여 빠른 연산이 가능합니다.
    *   기존 물리 시스템보다 훨씬 결정론적이어서 동일한 환경에서 일관된 결과를 얻을 수 있습니다.
    *   64개의 레이어를 지원합니다.
    *   잡 시스템(Job System) 및 구조체(Struct) 기반으로 DOTS(Data-Oriented Technology Stack)와 함께 활용 시 더욱 빠른 성능을 기대할 수 있습니다.
    *   **주의**: 기존 `Rigidbody2D` 및 `Collider2D`와는 상호작용이 불가능합니다.
3.  **시작 방법 및 설정**
    *   `UnityEngine.lowlevelphysics2d` 네임스페이스를 추가합니다.
    *   C# 스크립트를 준비하고, 해당 스크립트에 물리 월드를 생성합니다.
        *   **물리 월드 생성**: `PhysicsWorld` 변수를 선언하고, 기본 제공되는 디폴트 월드를 사용하거나 커스텀 월드를 직접 생성할 수 있습니다.
        *   **물리 월드 설정**: `PhysicsLowLevelSettings2D` 에셋을 통해 그래비티, 시뮬레이션 타입 등을 제어할 수 있습니다.
    *   **물리 기체(Physics Body) 생성**:
        *   `PhysicsBody` 변수를 선언하고, `CreateBody` 함수를 사용합니다.
        *   `PhysicsBodyDefinition`을 통해 기본적인 속성값을 설정하며, 인스펙터 창에서도 제어 가능합니다.
    *   **물리 기체의 모양(Shape) 생성**:
        *   `CreateShape` 함수를 호출하여 `Geometry` (모양)와 `PhysicsShapeDefinition` (표면, 물리 재질)을 설정합니다.
        *   `Geometry` 종류: Circle, Capsule, Polygon, Line, Chain Segment 등 5가지가 있습니다.
        *   `PhysicsShapeDefinition`은 `PhysicsMaterial2D`와 유사하며, 충돌 이벤트 콜백 설정도 가능합니다.
4.  **물리 기체와 유니티 오브젝트 연동**
    *   물리 기체를 화면에 보이게 하려면 트랜스폼과 연결해야 합니다.
    *   **트랜스폼 라이트 모드(Transform Light Mode)**: `OK`에서 `Current`로 설정해야 합니다.
    *   `PhysicsBody.transform.SetTransformObject()`를 사용하여 트랜스폼 오브젝트를 할당합니다.
    *   이를 통해 로우 레벨 물리 위치와 트랜스폼의 포지션, 로테이션이 연동됩니다.
5.  **성능 차이 및 장점**
    *   기존 방식은 게임 오브젝트, Rigidbody2D, Collider2D 컴포넌트가 필요하지만, 로우 레벨은 구조체 기반으로 내부적으로 간결하게 구현되어 처리 속도가 빠릅니다.
    *   박스2D 월드와 유니티 월드 간의 실시간 연결 비용이 제거되고, 엔진 자체적인 업데이트(병렬 처리 등)로 성능 이득이 있습니다.
    *   수천, 수만 개의 물리 객체를 생성해도 프레임 드랍 없이 높은 성능을 유지할 수 있습니다.
6.  **이벤트 처리**
    *   `PhysicsShapeDefinition`의 `contactEvents` 속성을 활성화하여 충돌 이벤트를 받을 수 있습니다.
    *   `onContactBegin2D`, `onContactEnd2D` (일반 충돌) 또는 `onTriggerBegin`, `onTriggerEnd` (트리거) 함수를 사용합니다.
7.  **멀티 스레딩 설정**
    *   물리 월드 생성 후 `SimulationWorkerCount`를 설정하여 멀티 스레딩 워커 수를 제어할 수 있습니다.
    *   최대 64개의 워커까지 설정 가능하며, 컴퓨터 사양에 따라 디폴트 값이 달라질 수 있습니다.
    *   런타임 중 변경은 성능에 악영향을 줄 수 있으므로, `Start` 또는 `Awake`에서 한 번 설정하는 것을 권장합니다.
8.  **활용 예시 및 가능성**
    *   하나의 스크립트에서 다수의 물리 기체를 생성하고, 그래픽 프리팹과 연동하여 동적인 게임 콘텐츠를 만들 수 있습니다.
    *   앵그리버드, 인형 뽑기 게임 등 대규모 물리 시뮬레이션이 필요한 게임 개발에 활용 가능합니다.
    *   유니티 테크놀로지에서 제공하는 다양한 로우 레벨 물리 예제 데모를 통해 실제 구현을 확인할 수 있습니다.
9.  **기존 시스템과의 비교 및 고려사항**
    *   로우 레벨 물리 2D는 **성능이 매우 중요할 때** 적합하며, 기존 방식은 **개발 편의성 및 유지보수**에 유리합니다.
    *   기존 `Rigidbody2D` 및 `Collider2D`와는 호환되지 않으므로, 게임 장르 및 콘텐츠에 따라 적용 여부를 결정해야 합니다.
    *   새로운 물리 월드를 사용하므로, 기존 게임 기획과 달라질 수 있어 기획자와의 긴밀한 협의가 필요합니다.

## 1. Claude 스킬: 반복적인 지시를 자동화하는 방법
Claude에게 반복적으로 설명해야 하는 지시사항을 '스킬'로 만들어 업무 효율성을 높이는 방법을 설명한다.

### 1.1. 스킬의 개념과 필요성
1.  **반복적인 설명의 비효율성**
    *   팀의 코딩 표준, PR 리뷰 방식, 커밋 메시지 형식 등 반복적인 지시사항은 Claude에게 매번 설명해야 한다.
2.  **스킬을 통한 문제 해결**
    *   **스킬**은 Claude에게 특정 작업을 한 번만 가르치면, 관련 상황에서 자동으로 해당 지식을 적용하게 하는 마크다운 파일이다.

### 1.2. 스킬의 작동 방식
1.  **에이전트 스킬의 정의**
    *   에이전트 스킬은 Claude가 더 정확하고 효율적으로 작업을 수행하도록 돕는 지침, 스크립트, 리소스 모음이다.
    *   Claude Code에서는 스킬을 `.md` 파일로 관리한다.
2.  **스킬의 활성화 과정**
    *   **설명(description)**은 Claude가 스킬을 사용할지 결정하는 기준이 된다.
    *   Claude는 사용자의 요청을 가능한 스킬 설명과 비교하여 일치하는 스킬을 활성화한다.
    *   예를 들어, PR 리뷰 요청 시 관련 스킬 설명을 찾아 활성화한다.

### 1.3. 스킬 저장 위치
1.  **개인 스킬**
    *   `home directory.cloud/skills`에 저장하며, 모든 프로젝트에서 개인의 선호도(커밋 메시지 스타일, 문서 형식, 코드 설명 방식 등)를 따른다.
2.  **프로젝트 스킬**
    *   저장소의 루트 디렉토리 내 `do.claw/skills`에 저장한다.
    *   저장소를 복제하는 모든 사용자가 이 스킬을 자동으로 얻게 된다.
    *   팀 표준(회사 브랜드 가이드라인, 웹 디자인 폰트 및 색상 등)을 저장하는 데 사용된다.

### 1.4. 스킬과 다른 사용자 정의 방식 비교
1.  **스킬의 고유성**
    *   스킬은 **자동으로 실행**되고 **작업에 특화**된다는 점에서 독특하다.
2.  **`Claude.md` 파일과의 차이점**
    *   `Claude.md` 파일은 모든 대화에 로드되어 항상 적용된다 (예: TypeScript strict mode 항상 사용).
3.  **스킬의 온디맨드 로딩**
    *   스킬은 요청과 일치할 때만 로드되며, 이름과 설명만 로드되어 컨텍스트 창을 채우지 않는다.
    *   예를 들어, PR 리뷰 체크리스트는 디버깅 중에는 필요 없다가 리뷰 요청 시에만 로드된다.
4.  **슬래시 명령어와의 차이점**
    *   슬래시 명령어는 사용자가 직접 입력해야 하지만, 스킬은 Claude가 상황을 인식하면 자동으로 적용된다.
    *   스킬은 특정 작업에 적용되는 전문 지식(코드 리뷰 표준, 커밋 메시지 형식, 조직의 브랜드 가이드라인 등)에 가장 적합하다.

### 1.5. 스킬 작성의 기준
1.  **반복 설명의 신호**
    *   Claude에게 같은 내용을 반복해서 설명하고 있다면, 이는 스킬로 만들어야 할 대상임을 의미한다.

Anthropic Agent SDK를 활용해 **나만의 강력한 AI 에이전트를 구축하는 모든 과정**을 담았습니다. 에이전트의 핵심 작동 방식부터 도구, 스킬, 메모리 시스템 설계까지, 실제 개발자가 겪은 시행착오와 해결책을 통해 <mark>복잡한 AI 에이전트 개발의 실질적인 노하우</mark>를 얻을 수 있습니다. 비용 문제와 배포의 한계점까지 솔직하게 다루어, AI 에이전트 개발을 고민하는 분들에게 현실적인 가이드라인을 제시합니다.

## 1. Anthropic Agent SDK를 활용한 AI 에이전트 구축 경험 및 핵심 기능
<mark>Anthropic Agent SDK를 사용하여 개인화된 AI 에이전트를 구축하고, 에이전트의 작동 방식, SDK의 차별점, 도구 및 스킬, 메모리 시스템 설계 방법을 상세히 설명한다.</mark>
### 1.1. 개인 맞춤형 AI 에이전트 'Luna L1' 구축 사례
1. **AI 에이전트 'Luna L1' 개발 및 기능 소개**
   1. 약 일주일간의 개발을 통해 iMessage 읽기/보내기, Slack 및 Gmail 검색, App Store Connect에서 데이터(리뷰, 빌드 상태) 추출 등의 기능을 수행하는 **맞춤형 AI 에이전트 'Luna L1'**을 구축했다.
   2. Luna L1은 ChatGPT와 유사한 인터페이스를 가지지만, Slack, Gmail, Notion 외에 iMessage, Chartmogul, App Store Connect 등 **다양한 도구와 연동**되어 훨씬 강력하다.
   3. 특히, 긴급 메시지 확인 시 단순히 최근 10개 이메일을 확인하는 것이 아니라, **도구를 통해 논리적으로 긴급성을 판단**하여 정확한 응답을 제공한다.
   4. 자체 **메모리 시스템**을 갖추고 있으며, 매일 아침 전날의 할 일 목록을 요약하는 등 **예약된 워크플로우**를 실행할 수 있다.
   5. 웹과 iOS에서 사용 가능하며, 긴급 상황 발생 시 **푸시 알림**을 보낼 수 있어 유용하다.
2. **AI 에이전트 배포의 한계점**
   1. 개발된 에이전트는 매일 사용하고 있으며 다른 사람들에게도 공개하고 싶었지만, **몇 가지 주요 제한 사항**으로 인해 배포가 어렵다는 것을 깨달았다.

### 1.2. AI 에이전트의 기본 작동 방식 및 기존 SDK의 한계
1. **AI 에이전트의 정의 및 핵심 구성 요소**
   1. AI 에이전트는 생각보다 간단하며, 다음 세 가지로 구성된다.
      1. **LLM(Large Language Model)**: Claude Sonnet 또는 GPT와 같은 대규모 언어 모델이다.
      2. **도구(Tools)**: LLM이 제어할 수 있는 외부 서비스 또는 기능이다.
      3. **루프(Loop)**: 에이전트가 작업을 완료했다고 판단할 때까지 도구를 실행하고 결과를 확인하는 반복 과정이다.
2. **에이전트의 작업 처리 흐름**
   1. 사용자로부터 작업을 받으면, 에이전트는 어떤 도구를 사용할지 **생각하고 실행**한다.
   2. 도구 실행 결과를 확인한 후, 작업이 완료되었는지, 추가 정보가 필요한지 판단하여 **루프를 반복**한다.
   3. 이는 본질적으로 LLM을 호출하고, 도구를 결정하고, 실행한 후 결과를 다시 입력하여 **반복하는 'while 루프'**와 같다.
3. **기존 에이전트 개발의 복잡성 및 AI SDK의 등장**
   1. 기본적인 에이전트 구현에도 **많은 상용구 코드**가 필요하며, 대화 기록 관리, 도구 호출 실행, 예외 처리 등 **다양한 문제**를 개발자가 직접 처리해야 한다.
   2. 이러한 복잡성을 해결하기 위해 **Vercel의 AI SDK**와 같은 라이브러리가 등장했다.
   3. AI SDK는 루프, 도구 호출, 메시지 대화 기록, 스트리밍 등 **반복적인 작업을 자동으로 처리**하여 개발자가 도구 정의와 최대 스텝 수 설정에만 집중할 수 있도록 돕는다.

### 1.3. Anthropic Agent SDK의 차별점 및 강력한 기능
1. **Claude Code 아키텍처 및 도구 접근성**
   1. Anthropic Agent SDK는 Vercel AI SDK와 유사하게 에이전트 생성을 지원하지만, **Claude Code와 동일한 아키텍처 및 도구**를 제공하여 훨씬 강력하다.
   2. Bash, 파일 읽기/편집, 검색(GP, Glob), 웹 검색 및 웹 스크래핑 등 **Claude Code가 사용하는 최적화된 기본 도구**에 접근할 수 있다.
   3. Claude Code가 소수의 도구에 집중하여 **도구의 품질이 매우 높다**는 가설이 있으며, SDK를 통해 이러한 도구를 바로 활용할 수 있다.
2. **자동 대화 컨텍스트 관리 및 압축**
   1. 대부분의 프레임워크에서는 개발자가 **메시지 배열을 수동으로 관리**해야 하지만, Agent SDK는 **세션 ID를 통해 대화 컨텍스트를 자동으로 관리**한다.
   2. 대화가 길어지면 **자동으로 이전 부분을 요약하여 토큰을 절약**하는 **압축(compaction)** 기능을 지원한다. 이는 Claude Code가 사용하는 방식이며, 장기 대화에 매우 유용하다.
   3. 개발자가 별도로 설정할 필요 없이 **자동으로 작동**하여, 기존 SDK에서 직접 구현해야 했던 번거로움을 없앤다.
3. **서브 에이전트 및 기타 고급 기능**
   1. **서브 에이전트 정의** 등 다양한 강력한 기능을 제공하며, 자세한 내용은 Agent SDK 문서를 통해 확인할 수 있다.
4. **Anthropic 구독 연동을 통한 비용 절감**
   1. Anthropic은 Agent SDK 사용자가 **기존 Claude Code 구독을 활용**하여 토큰 비용을 지불할 수 있도록 허용했다.
   2. 월 200달러의 Claude Code 플랜으로 약 2,000달러 상당의 API 토큰을 사용할 수 있어, **개인 개발자들의 실험 및 커스텀 에이전트 구축 비용을 크게 절감**할 수 있다.
   3. 단, 개발된 에이전트를 **다른 사용자에게 공개할 경우**에는 Claude Code 구독을 사용할 수 없으며, **API 과금 방식**으로 전환해야 한다.

### 1.4. Agent SDK 사용 시 고려사항 및 Convex 데이터베이스 활용
1. **대화 기록 저장 및 관리 책임**
   1. Agent SDK는 세션 및 대화 컨텍스트를 관리하지만, **대화 기록을 페이지에 렌더링하려면 개발자가 직접 저장**해야 한다.
   2. 세션은 약 30일 동안만 유지되므로, **데이터베이스에 대화 기록을 영구적으로 저장하고 관리**하는 것이 좋다.
   3. 이 프로젝트에서는 **Convex 데이터베이스**를 사용하여 대화 기록을 저장했다.
2. **메모리 시스템 구축의 필요성**
   1. SDK에 메모리 명령이 베타 버전으로 제공되지만, **기본적인 기능만 제공**하므로 **자체적인 메모리 시스템을 구축**하는 것이 좋다.
   2. 이 프로젝트에서는 **Convex**를 활용하여 자체 메모리 시스템을 구축했으며, 이는 아키텍처의 중요한 부분이다.
3. **Convex 데이터베이스의 장점**
   1. Convex는 **실시간 동기화** 기능을 기본으로 제공하여, 웹과 모바일 앱 간의 대화 동기화에 매우 유용하다.
   2. **인프라가 코드로 관리**되어 Claude Code와 연동하기 쉬웠으며, 데이터베이스 스키마를 별도로 관리할 필요 없이 프로젝트에 통합되어 있었다.
   3. **크론 잡(cron jobs) 및 함수**와 같은 유용한 내장 기능을 제공하여, 별도의 백엔드 설정 및 디버깅 없이 자동화된 작업을 쉽게 구현할 수 있었다.
   4. 예를 들어, 매일 아침 중요한 Slack 메시지를 확인하는 자동화 기능은 Convex의 크론 잡을 활용하여 구현되었다.
4. **Convex 활용 권장**
   1. Convex는 이 프로젝트에서 매우 만족스러웠으며, 앞으로의 프로젝트에서도 계속 사용할 예정이다.
   2. **무료 티어**를 제공하므로 관심 있는 개발자들에게 사용을 권장한다.

### 1.5. 에이전트의 도구(Tools) 설계 및 활용
1. **도구의 중요성 및 작동 방식**
   1. **도구**는 에이전트가 실제 작업을 수행할 수 있도록 하는 **가장 강력한 기능** 중 하나이다.
   2. Agent SDK에서 도구는 **MCP(Model Context Protocol)**를 통해 작동하며, 이는 에이전트가 외부 서비스와 통신하는 방식이다.
2. **도구 정의 구성 요소**
   1. **도구 이름(Tool name)**: 도구의 고유한 이름이다.
   2. **도구 설명(Description)**: 에이전트가 어떤 도구를 사용할지 결정하는 데 매우 중요하므로, 명확하게 정의해야 한다.
   3. **Zod 스키마(Zod schema)**: 입력 데이터의 형식(스키마)을 정의한다.
   4. **핸들러 함수(Handler function)**: 에이전트가 도구를 호출할 때 실제로 실행되는 핵심 로직이다.
3. **도구 번들링 및 SDK 통합**
   1. 정의된 도구는 **MCP 서버로 번들링**되어 쿼리에 전달된다. 이때 명명 규칙을 따라야 한다.
   2. 사용자 정의 도구 외에도 Bash, 파일 읽기/편집, 검색, 웹 검색 등 **강력한 내장 도구**를 `allowed tools` 배열에 이름으로 추가하여 사용할 수 있다.
   3. SDK는 도구 실행 루프, 대화 상태, 도구 결과 파싱 등을 **자동으로 처리**하므로, 개발자는 도구 자체만 정의하면 된다.

### 1.6. 에이전트의 스킬(Skills) 설계 및 활용
1. **스킬의 개념 및 장점**
   1. **스킬**은 에이전트에 **특정 기능을 부여**하는 방법으로, 컨텍스트를 불필요하게 늘리지 않고 **필요할 때만 로드**된다.
2. **스킬의 구성 및 파일 시스템 구조**
   1. Agent SDK에서 스킬은 코드 객체가 아니라 **파일 시스템의 폴더로 구성**되며, 특정 형식을 따라야 한다.
   2. 각 스킬은 자체 폴더를 가지며, 내부에 **`skill.md` 파일**이 포함된다.
   3. `skill.md` 파일은 **메타데이터를 위한 YAML 형식**과 **상세 지침을 위한 마크다운 콘텐츠**의 두 부분으로 구성된다.
3. **스킬의 자동 감지 및 로딩 (Progressive Disclosure)**
   1. 스킬은 `available tools`처럼 쿼리에 직접 전달되지 않고, **자동으로 감지(autodiscovered)**된다.
   2. 에이전트가 시작될 때 SDK는 스킬 폴더를 스캔하여 각 `skill.md` 파일에서 **이름과 설명(경량 메타데이터)을 읽어 시스템 프롬프트에 추가**한다.
   3. 사용자가 "Slack에서 긴급 메시지를 확인해 줘"와 같은 요청을 하면, 에이전트는 시스템 프롬프트의 설명을 보고 **관련 스킬을 인식한 후 해당 지침을 컨텍스트에 로드**한다.
   4. 이처럼 필요한 스킬만 로드하는 방식을 **점진적 공개(progressive disclosure)**라고 하며, 수십 개의 스킬이 설치되어도 컨텍스트 창에 큰 영향을 주지 않는다.
4. **스킬 설명의 중요성**
   1. 에이전트가 설명을 기반으로 스킬 사용 여부를 자동으로 판단하므로, **명확하고 구체적인 스킬 설명을 작성**하는 것이 매우 중요하다.
5. **스킬 활성화 방법**
   1. 스킬을 활성화하려면 `skill` 도구를 `allowed tools` 배열에 명시적으로 추가해야 한다.
   2. `sources` 및 `CWD` 매개변수를 구성하여 스킬 파일의 위치를 지정해야 한다.
   3. 프로젝트 내에서만 로드되는 **프로젝트 스킬**과 모든 프로젝트에서 로드되는 **사용자 스킬**을 설정할 수 있다.

### 1.7. 에이전트의 메모리 시스템 설계 및 구현
1. **메모리 아키텍처의 중요성**
   1. 에이전트의 메모리 아키텍처는 다양한 방식으로 설계될 수 있으며, 시행착오를 거쳐 최적의 시스템을 구축했다.
2. **Convex를 활용한 메모리 저장 및 분류**
   1. 모든 메모리는 **Convex 데이터베이스**에 저장되며, 중요도와 지속성에 따라 **세 가지 주요 범주**로 분류된다.
3. **세 가지 주요 메모리 유형**
   1. **세션 메모리(Session memory)**: 현재 대화 컨텍스트로, 새로운 채팅이나 대화가 로드될 때마다 함께 로드된다.
   2. **영구 메모리(Persistent memory)**: 사용자(나)에 대한 중요한 사실, 선호도, 프로젝트 정보 등 지속적으로 필요한 정보다 (예: "Chris는 생산성 앱을 만들고, Luna라는 개를 키운다").
   3. **아카이브 메모리(Archival memory)**: 참조 자료, 대량의 데이터(예: 다운로드한 YouTube 스크립트, 과거 프로젝트 문서) 등 모든 대화에 로드할 필요는 없지만 나중에 참조할 수 있는 정보다.
4. **능동적인 메모리 관리 시스템**
   1. 이 메모리 시스템의 핵심은 에이전트가 **능동적으로 메모리 시스템을 사용하고 최신 상태로 유지**하는 것이다.
   2. **'메모리 스킬' 파일**을 통해 에이전트가 언제 메모리를 저장해야 하는지 정의한다.
   3. 에이전트가 메모리 계층과 상호작용할 수 있도록 **사용자 정의 도구**를 구축했으며, 모든 메모리는 Convex에 저장된다.
   4. 시스템 프롬프트에 "요청하지 않아도 중요한 정보를 능동적으로 저장하라", "수정 사항을 알려줄 때마다 메모리를 저장하라"와 같은 **명시적인 지침**을 포함했다.
   5. 이러한 조합 덕분에 에이전트는 "이것을 기억해 줘"라고 명시적으로 지시하지 않아도 **중요한 정보를 자동으로 인식하고 저장**한다.
5. **기존 방식과의 차별점**
   1. 일반적으로는 대화 기록을 파싱하여 중요한 정보를 후처리로 저장하지만, 이 시스템은 **에이전트가 모든 것을 직접 처리**하게 한다.
6. **개인화된 경험 제공**
   1. 이 메모리 계층은 에이전트가 중요한 정보와 피드백을 기억하게 하여, ChatGPT와 같은 다른 모델에 비해 **훨씬 개인화된 느낌**을 준다.

## 2. AI 에이전트 배포의 현실적 한계 및 실용적 활용 방안
<mark>개인 맞춤형 AI 에이전트 배포 시 발생하는 높은 비용과 기술적 한계를 분석하고, B2B 시장에서의 실질적인 활용 가능성과 향후 기술 발전 방향을 제시한다.</mark>
### 2.1. 개인 에이전트 배포의 주요 한계점: 비용 및 기술적 제약
1. **높은 운영 비용**
   1. Agent SDK를 통해 메시지당 비용을 추적한 결과, 에이전트 사용 비용이 **매우 비싸다**는 것을 확인했다.
   2. 특히 Opus 4.6 모델을 사용하여 많은 도구 호출과 검색이 필요한 복잡한 메시지(예: 긴급 메시지 찾기)는 **건당 2~3달러**에 달했다.
   3. 일반 메시지도 건당 7~30센트 정도로, 현재 사용량 기준 **월 200~400달러**가 예상된다.
   4. 현재는 월 200달러 Claude Code 구독을 활용하여 비용을 절감하고 있지만, **다른 사용자에게 에이전트를 공개할 경우 API 과금 방식**으로 전환해야 한다.
   5. 사용자당 월 100달러의 비용을 가정하면, 안전하게 서비스를 제공하기 위해 **월 200달러 정도의 구독료**를 책정해야 한다.
   6. ChatGPT나 Claude가 월 20달러 또는 무료 플랜을 제공하는 상황에서, **소비자가 월 200달러를 지불할 가능성은 낮다**고 판단했다.
2. **로컬 접근성 상실**
   1. iMessage 통합과 같은 강력한 기능은 **로컬 머신(Mac)의 SQL 데이터베이스에 직접 접근**했기 때문에 가능했다.
   2. 에이전트를 서버에 배포하면 로컬 접근 권한을 잃게 되어 **iMessage와 같은 Mac 전용 기능들을 사용할 수 없게 된다.**
   3. 이러한 로컬 접근 기능들이 에이전트를 특별하게 만드는 요소였으므로, 서버 배포 시 **에이전트의 매력이 일부 감소**한다.
3. **인증 복잡성 및 보안 문제**
   1. 일부 도구는 API 키와 같은 **민감한 정보를 설정**해야 작동한다.
   2. 다른 사용자에게 배포할 경우, 이러한 민감한 정보를 안전하게 관리하고 인증하는 것이 **매우 복잡하고 안전하지 않다.**
   3. 일부 오픈 소스 래퍼들이 사용자에게 API 키를 직접 입력하도록 요구하는 경우가 있지만, 이는 **보안상 매우 우려되는 방식**이다.

### 2.2. AI 에이전트의 실용적인 활용 사례 및 미래 전망
1. **B2B 시장에서의 높은 잠재력**
   1. 현재로서는 소비자 시장에서 비용 효율성이 낮지만, **B2B 애플리케이션에서는 충분히 의미**가 있다.
   2. 기업은 더 높은 비용을 정당화할 수 있으며, **특정 비즈니스 문제 해결**에 에이전트를 활용할 수 있다.
   3. 예를 들어, 소프트웨어 에이전시 Aloa에서는 **HIPAA 규정 준수 에이전트**를 구축하여 코드베이스와 AWS 구성을 감사하고 문제를 식별하는 데 사용했다.
   4. 이 에이전트가 생성하는 보고서 비용은 50~100달러이지만, 이를 통해 **5,000~10,000달러 상당의 엔지니어링 시간을 절약**할 수 있어 충분히 가치 있다.
   5. 따라서, **비용 절감 효과가 명확한 비즈니스 사용 사례**에 맞춤형 에이전트를 적용하는 것이 가장 적합하다.
2. **향후 비용 절감 및 접근성 개선 전망**
   1. 소비자 측면에서 에이전트 비용은 **결국 하락할 것으로 예상**된다.
   2. Agent SDK는 Anthropic 모델 외에 **다른 LLM 모델**도 사용할 수 있으며, **로컬 LLM**과의 연동도 가능하다.
   3. 현재 로컬 LLM은 강력한 머신에서도 성능이 좋지 않지만, **기술 발전과 함께 개선될 것**으로 기대하며, 미래에는 소비자 사용 사례에서도 더 접근 가능해질 것이다.

### 2.3. AI 에이전트 배포 전략 및 고려사항
1. **배포의 필요성**
   1. 에이전트가 컴퓨터가 꺼져 있을 때도 작동하려면 **배포가 필수적**이다.
2. **VPS(가상 사설 서버) 활용 배포**
   1. 이 프로젝트에서는 **VPS(Virtual Private Server)**를 사용하여 에이전트를 배포했다.
   2. VPS는 에이전트가 파일을 쓰고, 프로그램과 도구에 접근하며, **24시간 내내 실행될 수 있는 샌드박스 환경**을 제공한다.
   3. HNER와 같은 저렴한 VPS를 사용하여 Anthropic 구독에 로그인하고 코드를 배포했다.
   4. 이 방식은 iMessage와 같은 Mac 전용 애플리케이션을 제외한 **대부분의 기능에 접근**할 수 있게 한다.
3. **로컬 머신과 VPS의 이중 연결 전략**
   1. 프론트엔드에서 **HNER VPS 또는 로컬 머신 중 하나를 선택**하여 연결할 수 있도록 설정했다.
   2. iMessage 및 Mac 전용 도구에 접근하기 위해 **가능하면 로컬 머신에 연결**하는 것을 선호한다.
   3. 로컬 머신이 꺼져 있을 때는 **HNER VPS로 전환**하여 에이전트를 계속 사용할 수 있도록 한다.
4. **Convex 데이터베이스를 통한 대화 기록 및 메모리 관리**
   1. 로컬 및 VPS 인스턴스 모두 동일한 대화 기록과 메모리에 접근할 수 있도록 **Convex와 같은 데이터베이스를 활용**하는 것이 중요하다.
5. **배포의 복잡성 및 향후 연구 계획**
   1. 에이전트 배포는 여전히 새로운 분야이며, **안전하고 적절한 배포 방식**에 대한 연구가 더 필요하다.
   2. 이로 인해 에이전트 공개에 대한 확신이 부족했으며, 향후 **배포에 대한 추가 연구와 실험**을 통해 관련 영상을 제작할 계획이다.

### 2.4. Agent SDK의 추가 기능 및 향후 계획
1. **다양한 고급 기능**

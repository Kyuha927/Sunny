# [서브에이전트] 제대로 쓰는 법? 클로드코드 말고 안티그래비티로

## 1. 에이전트 개념의 변화 및 분류

1. **에이전트 개념의 변화**: 에이전트의 개념이 시간이 지남에 따라 변화하고 있다.
2. **초기 에이전트의 형태**:
    1. 당초에는 LLM과 외부 툴(MCP, API 등)을 연결하는 **툴 콜링(Tool Calling)** 형태가 에이전트였다.
    2. 또한, Make나 Zapier처럼 자동화 노드를 연결하는 형태도 에이전트였다.
3. **최근 에이전트의 형태**: 최근에는 **서브 에이전트**나 **스킬스(Skills)**처럼 LLM 내부에 에이전트들이 연결된 구조가 나타나고 있다.
    1. **서브 에이전트**: LLM이 서브 에이전트라는 특수한 능력을 강화한 에이전트를 연결하는 형태로, 주로 **MD 파일**로 각 에이전트의 역할을 부여하는 형태이다.
    2. **스킬스**: 외부 툴이나 작은 기능들을 강화시킨 형태이며, MCP나 API도 포함될 수 있다.
4. **서브 에이전트 vs 스킬스 비교**:
    1. 서브 에이전트는 **조금 더 똑똑하고 전문적인 직원**의 역할을 수행한다.
    2. 스킬스는 **한 가지 일만 기계처럼 해내는** 형태이다.

## 2. 모든 업무를 포괄하는 네 가지 범주의 에이전트 구축

1. **모든 업무의 네 가지 범주**: 어떤 일이든 다음 네 가지 범주로 완성되며, 이 범주의 에이전트를 만들어 놓으면 모든 것이 완결된다.
    1. **사무/사무 분석**: 사무 및 분석 업무.
    2. **디자인 창작 설계**: 디자인, 창작, 설계 업무.
    3. **개발 IT 업무**: 개발 및 IT 관련 업무.
    4. **마케팅/비즈니스**: 마케팅 및 비즈니스 업무.
2. **클로드 코드를 활용한 서브 에이전트 사전 준비**:
    1. 서브 에이전트 제작은 매우 쉬우며, 클로드와 대화하며 만들 수 있다.
    2. 발표자는 클로드 데스크톱을 사용하여 위 네 가지 범주(분석/검색, 마케팅, 코딩, 설계/디자인 등)의 에이전트를 미리 **MD 파일 또는 YAML 파일**로 정리하여 만들어 두었다.

### 2.1. 다섯 번째 서브 에이전트 '내러티브 아키텍트' 생성

1. **새로운 에이전트 생성**: 미리 만들어 둔 네 가지 범주 외에 추가 에이전트를 생성하기 위해 슬래시(`/`)를 누르고 에이전트를 선택하여 **크리에이트 뉴 에이전트(Create New Agent)**를 선택한다.
2. **스토리텔링 에이전트 정의**: 이번에는 **스토리텔링 에이전트**를 만들기로 결정한다.
    1. 목표는 이야기를 재미있게 풀어내거나 짜임새 있게 말할 수 있는 에이전트를 만드는 것이다.
    2. 이 에이전트는 영화, 소설, 영상, 이미지, 심지어 UI에도 반영될 수 있는, 사람들에게 사랑받을 수 있는 스토리를 만들 수 있어야 한다.
3. **에이전트 설정 및 색상 지정**:
    1. 에이전트에 대한 역할, 다룰 수 있는 툴, 페르소나, 목표 등이 글로 정리되며, 코딩 없이 글로 정의하는 것이 간단하다.
    2. 에이전트의 기본은 **소개**이며, 색상 설정이 가능하다.
    3. 미리 만들어 둔 네 가지 에이전트와 구별하기 위해 다섯 번째 에이전트는 **보라색**으로 설정한다.
4. **생성된 다섯 가지 서브 에이전트**: 클로드 코드에서 에이전트들은 색상으로 구분 가능하다.
    1. 새로 생성된 **내러티브 아키텍트(Narrative Architect)** 에이전트가 추가되어 총 다섯 가지 서브 에이전트가 존재한다.
    2. 다섯 가지 에이전트 목록은 다음과 같다: 디자인 크리에이터, 비즈니스 리스트(분석), 풀스택 엔지니어(코딩), 마케팅, 그리고 내러티브 아키텍트이다.

## 3. 클로드 코드 환경에서의 서브 에이전트 협업 시연

1. **스킬스와 에이전트의 관계**: 스킬스는 LLM 내에 여러 툴이 포함된 형태가 아니라, 더 전문화된 에이전트로 볼 수 있다.
2. **내러티브 아키텍트 에이전트 활성화**: 새로 생성된 내러티브 아키텍트 에이전트에게 글쓰기를 지시한다.
3. **두 에이전트의 협업 워크플로우**:
    1. **비즈니스 애널리스트 에이전트**(빨간색)가 **검색**을 수행한다.
        1. 이 에이전트(빨간색)의 역할은 검색, 크롤링, 검색 정보 가공, 요약, 정리 등 **사무직** 역할이다.
    2. **내러티브 아키텍트 에이전트**(보라색)가 **글쓰기**를 수행한다.
        1. 이 에이전트(보라색)의 역할은 **작가** 역할이다.
4. **가동 상태**: 현재 클로드 코드에서 **작가 에이전트와 사무직 에이전트 두 명**을 가동시킨 상태이다.

## 4. 안티그래비티 환경으로의 에이전트 이식 및 비교 시작

1. **안티그래비티로 에이전트 등록**: 클로드 코드에서 만들어진 다섯 가지 에이전트를 안티그래비티에도 동일하게 등록하도록 지시한다.
2. **등록 진행 상황 비교**:
    1. 클로드 코드에서는 **빨간색 사무직 에이전트**만 작업을 하고 있으며, **작가 에이전트**는 아직 일을 시작하지 않았다.  (예술가이므로 늦게 출근한다는 비유)
    2. 안티그래비티에서는 클로드 코드에서 만든 다섯 가지 에이전트가 **워크플로우(Workflow)**라는 이름으로 가동되며 등록이 진행 중이다.
3. **안티그래비티 에이전트 확인**:
    1. 안티그래비티의 에이전트 폴더 내 워크플로 폴더에 클로드 코드에서 만든 다섯 개 에이전트(사무직, 디자이너, 개발자, 마케터, 작가)의 MD 파일이 등록되어 작동할 준비가 되었다.
4. **동일 프롬프트 실행**: 클로드 코드에 입력했던 동일한 프롬프트("최근 유행하는 드라마나 영화 등을 조사하여 글을 써 달라")를 안티그래비티에 입력하여 인식시킨다.
5. **동시 가동 및 작가 출근**:
    1. 클로드 코드에서는 여전히 사무직만 일하고 있다.
    2. 안티그래비티에서 프롬프트 입력 후 가동을 시키자, 클로드 코드에서도 **작가 에이전트가 출근**하며 가동되기 시작했다.

## 5. 클로드 코드 vs 안티그래비티 결과 비교: 속도와 정확성

1. **결과 비교 (시각적 확인)**:
    1. 클로드 코드에서는 보라색 작가 에이전트들이 가동되기 시작했다.
    2. 안티그래비티에서도 에이전트 가동 후 조사를 진행 중인데, **결과물이 매우 빠르게** 나왔다.
    3. 안티그래비티의 결과는 양은 많지 않지만 **완전히 최신 드라마** 이름과 배우 이름 등이 언급된다.
2. **안티그래비티의 정보 처리 과정**:
    1. 웹을 통해 먼저 검색을 했으며, 1월에 상영 중인 K드라마 콘텐츠 트렌드를 분석한 결과가 나왔다.
    2. 이 조사 결과를 바탕으로 내러티브 구조(어떤 이야기를 하면 좋을지)를 짜준다.
3. **안티그래비티의 시각화 강점 (나노바나 활용)**:
    1. 안티그래비티는 **나노바나 프로(Nanobana Pro)**가 달려있다는 강점이 있다.
    2. 분석된 내용을 한 장의 그림 안에 아홉 컷으로 나누어 나레이티브 구조를 **그림으로 시각화**하도록 요청한다.  (이는 클로드 코드가 할 수 없는 일이다.)
4. **속도 비교 결과**:
    1. 클로드 코드가 훨씬 빨리 시작했으나, 에이전트 등록 후 작업을 시켰을 때 **결과물은 안티그래비티에서 훨씬 빨리 나왔다.**
    2. 안티그래비티는 2026년 최신 유행 드라마를 잘 조사했으나, 나레이티브 양은 다소 적었다.
5. **안티그래비티 시각화 결과**:
    1. 안티그래비티는 요청대로 아홉 컷으로 그림을 그려주었는데, 최신 드라마 컨셉들을 짬뽕하여 하나의 컨셉을 잡아준 것이다.
    2. 그림의 요소는 오피스, 골동품 샵, 과거와 현대, 맥북과 종이, 구미호 등장, 마법, 사랑 등이 융합된 K드라마 컨셉이다.

## 6. 클로드 코드의 결과 지연 및 오류 확인

1. **클로드 코드의 느린 속도**: 클로드 코드는 매우 느리게 진행되고 있어 기다려야 하는 상황이다.
2. **안티그래비티의 플랫폼 구조**:
    1. 안티그래비티는 **IDE(통합 개발 환경)**, **에이전트 매니저(Agent Manager)**, 그리고 **안티그래비티 브라우저(Antigravity Browser)** 세 부분으로 구성되어 유동적으로 에이전트를 관리한다.
    2. **에이전트 매니저의 인박스**에서 에이전트들을 오케스트레이션(지휘)할 수 있다.
    3. **브라우저(크롬 익스텐션)**는 브라우저에서 확인, 크롤링 등의 역할을 수행한다.
    4. 안티그래비티는 서브 에이전트들을 **병렬 구조**로 여러 개 만들어 한꺼번에 일 시키기에 매우 좋다.
3. **클로드 코드 결과 확인**:
    1. 클로드 코드의 작가 에이전트 작업이 끝났다.
    2. 하지만 클로드 코드는 **2026년 1월 드라마가 아닌 2025년 1월(1년 전)** 드라마(예: 오징어 게임 언급)를 조사해왔다.
    3. 클로드 코드의 사무직들은 트렌디함이 떨어지는 반면, 안티그래비티는 완전히 최신 상영 중인 내용을 정리했다.
    4. 클로드 코드 작가 에이전트는 MD 파일 18줄을 써서 충실히 일했으나, 속도와 트렌드 반영 미흡으로 **종합도가 떨어진다**는 아쉬움이 있다.
4. **스킬스(Skills)의 비교**:
    1. 안티그래비티는 나노바나를 통해 시각화까지 갖는 장점이 있다.
    2. 클로드의 '어썸 스킬스(Awesome Skills)'에 대한 만족도는 높지 않아, 발표자는 필요한 스킬을 직접 만들어서 사용해 왔다.

## 7. 안티그래비티의 핵심 강점: 이미지 CAD 도면 자동 변환 스킬 시연

1. **스킬 구현 목표**: 발표자는 조형 작업을 하는 사람으로서, 그림(미드저니, 나노바나 등으로 그린 것)을 **캐드(CAD) 파일**로 바꾸고 싶었다.
2. **나노바나 정제의 중요성**:
    1. 핀터레스트에서 캡처한 그림을 바로 오픈(Open)하여 캐드로 바꾸면 **노이즈가 많고 복잡**해진다.
    2. 안티그래비티는 **나노바나**가 내장되어 있어, 이 그림을 캐드로 바꾸기 좋게 **한 번 정제**해 준다.
    3. 클로드 코드도 API 등을 활용해 가능하지만 쉽지 않고 비용이 든다.
3. **안티그래비티 스킬의 작동 방식**:
    1. 안티그래비티는 내장된 나노바나를 활용해 캡처한 그림을 깔끔하게 도면처럼 정제해 준다.
    2. 이 스킬은 **파이썬 코드로** 이루어져 있으며, 과정은 **1) 나노바나로 정제** 후 **2) 캐드로 변환**하는 단계로 진행된다.
4. **결과 확인 및 비교**:
    1. 안티그래비티에서 나온 결과물을 확인해보니 **정말 도면처럼** 나왔으며, 해치(Hatch)도 최소화되고 색깔도 빠졌다.
    2. 기존 방식은 AI 스튜디오 등에 그림을 가져가 도면처럼 블루프린트화 해달라고 요청하고 마음에 안 들면 다시 요청하는 반복 과정이 필요했다.

## 8. 에이전트 관리 환경 및 최종 비교

1. **에이전트 관리**:
    1. 이러한 스킬(CAD 변환 등)의 자동화는 스킬 내에서 구현되어 있다.
    2. 서브 에이전트나 스킬들은 **에이전트 매니저의 인박스**에서 관리되며, 어떤 것이 돌아가고 있고 멈춰야 하는지, 무엇이 끝났는지 체크 가능하다.
    3. **안티그래비티 IDE(본체)**에서는 익스텐션 사용, MCP 설정, 워크스페이스 파일 관리 등을 수행한다.
2. **최종 결과 확인**: 캐드 파일 생성이 완료되어 확인했으며, 핀터레스트 캡처 이미지 -> 나노바나 정제 -> 오픈을 통한 캐드 변환 과정이 스킬 하나로 묶여 실행된 것이다.
3. **서브 에이전트의 실행 방식 비교**:
    1. 기존에 만든 다섯 가지 서브 에이전트(사무직, 디자이너, 개발자, 마케터, 작가)는 클로드 코드나 안티그래비티에서 활동 가능하다.
    2. **클로드 코드**에서는 서브 에이전트가 **순차적으로 직렬 작업**을 하게 시켰다 (조사 후 작가 글쓰기).
    3. **병렬 실행 가능**: "너는 조사를 하고, 너는 다른 주제에 대해 글을 쓰고 나중에 합쳐"와 같이 **병렬로 작업 지시**도 가능하다.
4. **결론**: 발표자가 느끼기에 서브 에이전트나 스킬스 모두 **안티그래비티가 클로드 코드보다 훨씬 빠르고 효율적**이며, **나노바나**가 내장되어 있다는 점이 큰 장점으로 작용한다.

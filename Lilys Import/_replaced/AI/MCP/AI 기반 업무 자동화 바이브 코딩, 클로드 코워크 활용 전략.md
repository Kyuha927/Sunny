## 1. 클로드 코워크: AI 비서로 업무 혁신하기
<mark>클로드 코워크는 코딩 없이도 폴더 하나로 AI가 알아서 분석하고 보고서까지 작성해주는 혁신적인 도구이다.</mark>

### 1.1. 클로드 코워크의 등장 배경과 핵심 기능
1.  **클로드 코워크의 탄생 배경**
    *   기존 클로드 코드 도구는 개발자들이 코드를 짜고 파일을 다루는 데 사용되었으나, 개발자들이 이를 파일 정리, 데이터 분석, 문서 작성 등 일반 업무에도 활용하기 시작했다.
    *   이에 엔트로픽은 코딩을 모르는 일반인도 이러한 강력한 기능을 사용할 수 있도록 클로드 코워크를 개발했다.
2.  **클로드 코워크의 세 가지 핵심 기능**
    *   **폴더 기반 작업**: 특정 폴더를 클로드에게 열어주면 해당 폴더 내 파일들을 자유롭게 읽고 쓸 수 있다.
    *   **자율 실행형 AI 에이전트**: 목표를 주면 스스로 계획을 세우고 여러 단계를 거쳐 작업을 완료하는 **에이전틱 AI** 기능을 제공한다. 이는 기존 AI가 질문에 한 번만 답하는 구조와 다르다.
    *   **전문적인 산출물 생성**: 엑셀, 파워포인트, 워드 문서 등 업무에 바로 사용할 수 있는 수준의 결과물을 파일 형태로 제공하며, 비전공자도 쉽게 활용할 수 있다.

### 1.2. 클로드 코워크 설치 및 사용 방법
1.  **클로드 코워크 설치 및 진입**
    *   클로드 코워크는 **클로드 데스크탑**에서 사용할 수 있으며, 검색을 통해 다운로드 페이지에 접속하여 운영 체제에 맞게 설치한다.
    *   최신 업데이트(2월 중순)를 통해 윈도우에서도 사용이 가능해졌다.
    *   클로드 데스크탑 실행 후 상단 탭에서 '코워크'를 클릭하면 심플한 화면이 나타나며, 이곳에서 프롬프트를 입력하여 작업을 진행한다.
2.  **클로드 코워크의 작업 흐름**
    *   폴더를 추가하고 프롬프트를 작성한 후 '시작하기'를 누르면 AI가 스스로 계획을 세우고 실행한다.
    *   예시 프롬프트: "해당 폴더에 파일들을 유형별 날짜별로 정리해 줘" 또는 "회의 노트를 종합해서 월간 보고서를 작성해 줘".
3.  **실전 시나리오 1: 영수증 이미지로 경비 보고서 작성**
    *   작업할 폴더를 선택하고 이미지 영수증 데이터를 준비한다.
    *   프롬프트 입력: "해당 영수증 스크린샷 이미지로 경비 보고서 엑셀 만들어 줘. 날짜, 금액, 카테고리를 포함해서."
    *   AI가 계획을 세우고 진행 상황을 시각화하여 보여주며, 완료 후에는 기간과 날짜별 경비 내역이 포함된 엑셀 데이터가 생성된다.
4.  **실전 시나리오 2: 운영 비용 데이터 분석 및 보고서 작성**
    *   재무 데이터가 포함된 폴더를 선택한다.
    *   프롬프트 입력: "해당 운영 비용 데이터를 분석하고 카테고리별 비중과 월별 트렌드를 포함한 보고서를 만들어 줘."
    *   AI가 데이터를 바탕으로 계획을 세우고 실행하며, 종합 요약, 월별 트렌드, 세부 분석, 부서별 분석, 손익 비용 트렌드 등을 포함한 보고서가 생성된다.

### 1.3. 클로드 코워크의 추가 기능: 플러그인 및 인스트럭션
1.  **플러그인 기능**
    *   2026년 1월 30일 업데이트로 추가된 기능으로, 클로드에게 특정 직무의 전문성을 한 번에 주입하는 패키지이다.
    *   엔트로픽이 내부적으로 사용하는 11종의 플러그인이 오픈 소스로 공개되었으며, 바이오리서치, 파이낸스, 마케팅 등 다양한 직무에 활용 가능하다.
    *   각 플러그인에는 스킬, 커넥터, 서브 에이전트가 포함되어 있어 설치 즉시 해당 직무 전문가처럼 작동한다.
    *   **플러그인 크리에이트 기능**을 통해 나만의 커스텀 플러그인도 만들 수 있어, 회사 용어 및 프로세스에 맞춰 AI를 세팅하여 팀원처럼 협업할 수 있다.
2.  **글로벌 인스트럭션 및 폴더별 인스트럭션**
    *   윈도우 업데이트와 함께 추가된 기능으로, 매번 같은 말을 반복할 필요 없이 AI에게 일관된 지침을 제공할 수 있다.
    *   **글로벌 인스트럭션**: 클로드 설정에서 '협업' 탭의 '저녁 지침'에서 설정하며, 모든 코워크 작업에 적용되는 전반적인 지침을 설정한다. (예: "나는 한국의 마케팅 팀장이야. 보고서는 공식적인 톤으로 작성하고, 파일을 삭제하기 전에는 반드시 나에게 물어봐.")
    *   **폴더별 인스트럭션**: 특정 폴더에만 지침 규칙을 활성화하는 기능이다.
        *   설정 방법은 두 가지이다: 코워크 UI에서 직접 `clode.md` 파일을 생성하여 폴더 지침을 추가하거나, 프롬프트 입력창에 지침을 추가하는 방식이다.
    *   이 두 가지 인스트럭션을 조합하면 코워크가 사용자의 업무 스타일을 잘 이해하는 동료처럼 작동하게 된다.

### 1.4. 클로드 코워크가 일으키는 파장과 미래 전망
1.  **클로드 코워크의 영향력**
    *   **진입 장벽 파괴**: 기존 개발자 중심의 도구를 코딩을 모르는 일반인도 쉽게 사용할 수 있게 만들어 AI 에이전트 활용의 대중화를 이끌었다.
    *   **대화에서 실행으로 전환**: AI에게 방법을 묻는 시대에서 AI에게 일을 시키는 시대로 변화를 주도하고 있다.
    *   **SaaS의 존재 이유 위협**: 파일 정리, 경비 처리, 프로젝트 관리 툴 등 다양한 SaaS 기능이 하나의 AI 에이전트로 대체될 가능성을 열었다.
    *   아직 프리뷰 단계이지만, 향후 1~3년 후에는 업계 전반에 큰 변화를 가져올 것으로 예상된다.
2.  **클로드 코워크의 핵심 요약**
    *   클로드 코드의 강력한 에이전트 기능을 비개발자도 사용할 수 있도록 만든 도구이다.
    *   폴더를 연결하고 작업을 지시하면 AI가 스스로 계획을 세우고 실행하여 완벽한 산출물을 만들어낸다.
    *   플러그인과 인스트럭션을 조합하면 사실상 AI 동료를 채용한 것과 같은 효과를 얻을 수 있다.

3.  **구현:** 계획이 완전히 준비되면 AI에게 구현을 지시하고, 나는 감독자 역할로 전환하여 진행 상황을 모니터링.

## 1. AI 코딩 도구의 한계를 극복하는 개발자 중심 워크플로우
AI 코딩 도구의 복잡한 작업에서의 한계를 극복하고, 개발자가 주도권을 가지고 결과물의 완성도를 높이는 실전 워크플로우를 제시한다.

### 1.1. 기존 AI 코딩 방식의 문제점과 핵심 원칙
대부분의 AI 코딩 방식은 작업이 복잡해지면 결과물이 무너지는 한계를 가지며, 이를 극복하기 위한 핵심 원칙은 '계획 검토 및 승인'이다.

1.  **기존 AI 코딩 방식의 한계**
    *   프롬프트 입력, 플랫 모드 사용, 에러 수정 반복 등의 방식은 작업이 복잡해지면 결과물이 무너진다.
    *   랄프루프, MCP, 스킬, 팀 에이전트 등 다양한 시도도 부차적이며 복잡한 작업에서는 한계를 보인다.
    *   아직 한계를 경험하지 못했다면, 그 수준의 복잡도를 만나지 못했을 뿐이다.

2.  **핵심 원칙: '계획 검토 및 승인'**
    *   작성된 계획을 개발자가 직접 검토하고 승인하기 전까지 AI에게 코드를 쓰게 하지 않는다.
    *   이는 '기획과 코딩의 분리'를 의미하며, 가장 중요한 단 하나의 원칙이다.
    *   이 원칙을 통해 쓸데없는 삽질이 사라지고, 아키텍처 결정의 주도권이 개발자에게 남으며, 토큰 사용량은 줄이고 결과물은 향상된다.

### 1.2. 실전 워크플로우 단계별 상세 설명
AI 코딩 워크플로우는 코드 리서치, 계획 수립, 구현, 피드백 반복의 단계를 거치며, 각 단계별로 개발자의 명확한 개입이 중요하다.

1.  **1단계: 코드 리서치 및 이해**
    *   모든 의미 있는 작업은 코드 베이스를 깊이 읽는 것부터 시작한다.
    *   AI에게 관련 부분을 철저히 이해시키고, 발견한 내용을 마크다운 파일(`research.md`)에 작성하게 한다.
    *   **주의:** 채팅창에서의 단순 요약으로 끝나지 않도록 해야 한다.
    *   **프롬프트 예시:**
        *   "이 폴더를 깊이 읽고 어떻게 동작하는지 깊이 이해하고 모든 세부 사항을 파악해라. 끝나면 리서치의 상세 보고서를 작성해라."
        *   "알림 시스템을 매우 상세에 연구하고 알림이 어떻게 작동하는지 모든 것을 담은 리서치 MD를 작성해라."
    *   **핵심 팁:** '깊이', '매우 상세히', '세부 사항'과 같은 단어를 사용하여 AI가 대충 훑어보는 것을 방지한다.
    *   AI의 구조는 강력한 인풋이 중요하며, 사람의 뇌와 크게 다르지 않다.
    *   **가장 비싼 실패:** 주변 시스템을 망가뜨리는 구현 (기존 레이어 무시, ORM 미고려 마이그레이션, 로직 중복 API 등)
    *   리서치 단계는 이러한 비싼 실패를 방지하는 역할을 한다.

2.  **2단계: 계획 수립 및 검토**
    *   리서치 후, 별도의 마크다운 파일(`plan.md`)에 상세 구현 계획을 작성하게 한다.
    *   **프롬프트 예시:**
        *   "세기능 ETF 리밸런싱을 구현하는 상세 플랜 MD를 작성해라. 코드 스니펫도 포함."
        *   "목록에서 오프셋 페이징 대신 인풋 기반 페이징을 지원해야 함. 이를 위한 상세 플랜 MD를 작성해 줘. 변경 사항을 제한하기 전에 소스 파일을 읽고 실제 코드베이스를 기반으로 계획을 작성해."
    *   **주의:** AI 코딩 도구의 내장 플랫 모드는 사용하지 않는 것이 좋다.
    *   **자체 MD 파일 사용 이유:** 에디터 편집 용이, 인라인 메모 가능, 프로젝트 산출물로 남음, 세션 날아감 방지 등 작업 연속성 유지.
    *   **계획 수립 및 검토 흐름:**
        *   AI가 플랜 MD 작성
        *   개발자가 에디터에서 검토, 주석, 메모 추가
        *   AI에게 다시 보내 계획 업데이트
        *   만족 시 투두 리스트 요청
    *   **개발자의 메모:** 잘못된 가정 수정, 접근 방식 거부, 제약 조건 추가, 도메인 지식 제공 등 다양한 역할을 한다.
        *   예시: "이건 풋이 아니라 패치어야 해" , "여기 캐싱 필요 없어" , "패런트가 제시도 처리하니까 이 제시도 로직은 중복이야. 제거하고 그냥 실패하게 둬"
    *   메모 추가 후 AI에게 다시 보내 업데이트를 요청하며, **"아직 구현하지 마"**라고 명시적으로 지시해야 한다.
    *   이 사이클은 1번에서 수번 반복되며, 개발자가 괜찮다고 할 때까지 충분하지 않은 것이다.

3.  **3단계: 구현 및 피드백**
    *   계획이 완전히 준비되면 구현 명령을 내린다.
    *   **표준 구현 프롬프트:** "전부 구현해라. 작업이나 단계를 완료하면 계획 문서에서 완료로 표시해라. 모든 작업과 단계가 완료될 때까지 멈추지 마라. 너운 타입을 쓰지 마라. 지속적으로 타입 체크를 실행해서 새로운 문제를 만들지 마라."
    *   구현 단계는 기계적이며 창의적이지 않아야 한다.
    *   개발자는 설계자/아키텍트에서 감독자로 역할이 바뀐다.
    *   **프롬프트 예시:** "리밸런스 이벤트 함수를 구현 안 했잖아." , "설정 페이지를 메인 앱에 만들었는데 어드민 앱에 있어야 해. 옮겨."
    *   프론트엔드 작업 시 브라우저 테스트를 통해 빠른 수정을 요청한다.
    *   디자인적 문제는 스크린샷 첨부가 효율적이다.
    *   **잘못된 방향 시 팁:** 깃을 통째로 되돌리고 범위를 재설정하는 것이 점진적 수정보다 낫다.
    *   개발자는 항상 운전대를 잡고 있어야 하며, 결정권을 AI에게 넘기지 않는다.

### 1.3. 개발자 주도권 유지를 위한 전략
개발자는 AI에게 실행 권한만 부여하고, 무엇을 만들지에 대한 결정권은 항상 자신이 가져야 한다.

1.  **적극적인 방향 조정**
    *   대부분의 방향 조정은 플랜 MD 문서 위에서 이루어진다.
    *   **예시:**
        *   "좋은 건 취하고 나머진 버리기: 첫 번째 방법은 어싱크로 깔끔하게 가자. 괜히 복잡하게 만들 필요 없어. 세 번째는 읽기 쉽게 함수로 분리해 줘. 네 번째랑 다섯 번째는 빼드리는 노력 대비 얻는 게 없어."
        *   "지금 안 할 건 과감하게 쳐내기: 다운로드 기능은 계획에서 빼. 지금 안 만들 거야."

2.  **건드리면 안 되는 선 긋기**
    *   특정 함수의 시그니처는 절대 바꾸지 않도록 명시한다.
    *   라이브러리가 호출자에게 맞추는 것이 아니라, 호출자가 라이브러리에 맞춰야 함을 강조한다.

3.  **기술 선택은 개발자가 하기**
    *   AI가 제안하는 모델 대신 특정 모델을 사용하도록 지시한다.
    *   직접 만들기보다 라이브러리에 이미 있는 메서드를 사용하도록 유도한다.

### 1.4. 단일 세션 워크플로우와 핵심 요약
리서치, 기획, 구현 단계를 별도 세션으로 나누지 않고 하나의 긴 세션으로 진행하며, 이는 AI의 컨텍스트 유지 능력과 계획 문서의 중요성 때문이다.

1.  **단일 세션 진행의 이점**
    *   리서치, 기획, 구현을 별도 세션으로 나누지 않고 하나의 긴 세션 안에서 쭉 이어간다.
    *   컨텍스트 윈도우 성능 저하 우려에도 불구하고, AI는 리서치와 계획 수립을 통해 이해를 쌓아오므로 성능 저하를 체감하지 못한다.
    *   컨텍스트 윈도우가 꽉 차면 AI의 오토 컴팩션이 맥락을 유지해 준다.
    *   계획 문서는 연구적인 파일로서 원본 그대로 살아남아 컨텍스트 유지에 기여한다.

2.  **핵심 요약 및 원리**
    *   마법 같은 프롬프트, 정교한 시스템 인스트럭션, 영리한 해킹 없이 규율 있는 파이프라인을 따른다.
    *   **파이프라인의 역할:**
        *   리서치: 무지한 변경 방지
        *   계획: 잘못된 변경 방지
        *   주석 달기 사이클: 개발자 판단 주입
        *   구현 명령: 결정 완료 후 방해 없이 실행
    *   **궁극적인 핵심:** AI에게 코드를 잘 쓰게 만드는 것이 아니라, 코드를 쓰기 전에 '무엇을 써야 하는지'를 확실하게 만드는 것이다.

### 1.5. 실용적인 인간 주도 루핑 방법론
'쉐어드 뮤터블 스테이트 패턴'을 활용하여 문서에 직접 메모를 추가하고 반복적으로 업데이트하는 방식으로 개발자 주도 루핑을 실현한다.

1.  **메모 추가 및 업데이트 방식**
    *   **메모 위치:** 플랜 MD 파일에 직접 인라인으로 추가한다.
    *   **업데이트 과정:**
        *   AI에게 메모 추가했으니 반영하고 업데이트하라고 보낸다.
        *   "아직 구현하지 마"라고 명시한다.
        *   만족할 때까지 이 과정을 반복한다 (1번에서 6번 반복).
    *   채팅창에서 설명하는 대신, 문서의 정확한 위치를 가리키며 수정 사항을 직접 적는 것이 중요하다.

2.  **방법론의 명칭**
    *   이는 '쉐어드 뮤터블 스테이트 패턴'이며, 에이전트 코딩 워크플로우에서 가장 실용적인 인간 주도 루핑 방법론이다.

## 1. 클로드 코워크: 일상 업무 AI 자동화 마스터
<mark>클로드 코워크를 통해 파일 관리, 외부 앱 연동, 반복 작업 자동화 등 일상 업무를 AI로 손쉽게 자동화하는 방법을 배웁니다.</mark>

### 1.1. 클로드 코워크 소개 및 클로드 코드와의 비교
1.  **클로드 코워크는 일반인을 위한 클로드 코드**로, PC에 설치하여 클로드 코드의 거의 모든 기능을 쉬운 인터페이스로 활용할 수 있는 도구이다.
2.  클로드 코드는 설치가 어렵고 서브 에이전트나 스킬 개념 이해가 복잡하여 일반인에게는 클로드 코워크가 더 적합하다.
3.  클로드 코워크는 **PC 내에서 AI가 모든 업무를 수행**하는 도구로, 파일 분석, 생성, 자동화 및 브라우저 컨트롤이 가능하다.
4.  **커넥터**를 통해 Gmail, 캘린더, 노션 등 외부 앱과 연동하여 메일 분석, 자동 답장, 결과물 저장 등을 수행할 수 있다.
5.  클로드 코워크는 **일상 업무 자동화**에 유용하며, 클로드 코드는 커스텀 소프트웨어 구축이나 고도화된 자동화에 더 적합하다.

### 1.2. 클로드 코워크의 핵심 활용 사례
1.  **파일 관리**: 데스크탑 파일 정리, 인터넷 자료 분석 및 가져오기, 파일 생성 및 분석 등을 수행한다.
2.  **브라우저 활용**: 웹사이트 리서치, 문서 생성 등을 AI가 직접 수행한다.
3.  **외부 앱 연동**: 노션, Gmail, Slack 등 외부 도구와 연동하여 일상을 자동화한다.
4.  **스킬(Skill) 제작**: 반복적인 업무를 하나의 패키지로 만들어 자동으로 실행할 수 있도록 한다.
5.  **플러그인(Plugin) 제작**: 외부 앱 연동과 커스텀 스킬들을 조합하여 종합적인 자동화 패키지를 만든다.

### 1.3. 클로드 코워크 설치 및 기본 사용법
1.  **클로드 데스크탑 앱 설치**: '다운로드 클로드' 웹사이트에서 OS에 맞는 파일을 다운로드하여 설치한다.
    *   윈도우 사용자는 클로드 코드와의 충돌을 피하기 위해 별도 조치가 필요할 수 있다.
2.  **코워크 첫 화면**: 설치 후 코워크 화면에서 컴퓨터 내 모든 내용을 AI가 읽고 파일 생성 및 업무 수행이 가능하다.
3.  **단일 파일 컨트롤 (폴더 정리)**:
    *   '다른 폴더 선택'을 눌러 원하는 폴더를 지정한다.
    *   예시: "이 폴더에 있는 이미지 파일들을 이미지 폴더로 만들어서 다 넣어 줘" 명령으로 187개의 이미지 파일을 성공적으로 옮겼다.

### 1.4. 파일 요약 및 멀티 파일 지시
1.  **파일 요약**: 여러 파일이 담긴 폴더를 지정하여 내용을 요약하도록 요청할 수 있다.
    *   예시: '기부 강의 자료' 폴더의 내용을 요약하도록 지시하여 입격서, RFP, 서비스 자료 등을 파악했다.
    *   이는 난잡한 파일들을 한꺼번에 요약하여 쉽게 볼 수 있게 해준다.
2.  **멀티 파일 지시 (영수증 분석 및 엑셀 변환)**:
    *   영수증이 있는 폴더를 선택하고, 새로운 '엑셀' 폴더를 만들어 영수증들을 옮긴다.
    *   "이 폴더 안에 있는 영수증들을 분석하고 엑셀 파일로 만들어 줘" 명령으로 영수증 내용을 분석하여 비용까지 합산된 엑셀 파일을 생성했다.
    *   수기 작업 없이 영수증 분석 및 정리가 가능해 생산성이 매우 높아진다.

### 1.5. 웹 리서치 및 보고서 자동 생성
1.  **웹사이트 조사 및 보고서 제작**: 특정 웹사이트를 조사하여 PDF, DOCX, PPTX 파일로 보고서를 생성하도록 요청할 수 있다.
    *   예시: '빌더 조쉬'에 대해 조사하고 PDF, DOCX, PPTX 보고서를 제작하도록 명령했다.
    *   복잡한 테스크는 진행 상황을 보여주며, 병렬 수행 지시도 가능하다.
2.  **보고서 결과 확인**:
    *   생성된 DOCX 파일에서 인물 소개, 주요 활동 영역, 소셜 미디어 주소 등이 잘 조사된 것을 확인할 수 있다.
    *   PPTX 파일도 생성되었으나 디자인은 추가 수정이 필요할 수 있다.
    *   웹에서 조사한 내용을 컴퓨터에서 바로 보고서로 받아볼 수 있다는 점이 대단하다.

### 1.6. 커넥터 활용: 외부 앱 연동
1.  **커넥터 추가 및 관리**:
    *   '+' 버튼을 눌러 파일이나 커넥터를 추가할 수 있다.
    *   Gmail, Google Drive, Slack, Notion 등 다양한 외부 도구를 연동할 수 있다.
    *   '커넥터 둘러보기' 탭에서 추천 도구들을 확인하고 연동할 수 있다.
2.  **Gmail 연동**:
    *   Gmail을 연동하여 메일을 읽고 쓰는 작업이 가능하다.
    *   "내 Gmail에서 새로운 메일 도착했는지 알려 줘" 명령으로 읽지 않은 메일 5통을 확인했다.
    *   "모든 이메일의 대략적인 내용을 요약해서 알려 줘" 명령으로 메일 내용을 요약받았다.
    *   이메일 관련 작업으로 읽기, 검색, 요약 분석, 중요 메일 필터링 등이 가능하다.
3.  **Slack 연동**:
    *   Slack 커넥터를 사용하여 특정 채널의 대화록을 분석하고 PDF로 저장한 뒤 다시 Slack으로 보내는 작업을 수행한다.
    *   예시: "Slack 커넥터로 제너럴 채널의 최근 일주일 간 대화록을 분석하고 PDF로 저장한 뒤 다시 Slack으로 보내 줘"
    *   분석 결과 채널 대화 분석 리포트가 생성되며, 핵심 인사이트와 주요 공유 콘텐츠를 제공한다.
    *   생성된 리포트를 Notion에도 송부하여 회의록 등으로 저장할 수 있다.
4.  **기타 연동**: 일정 관리를 캘린더에 등록하거나, Google Drive 파일들을 불러와 작업 후 다시 업로드하는 등 생산성 향상이 가능하다.

### 1.7. 신규 기능: 예약 실행 (Scheduling)
1.  **예정됨 기능**: 매일 정해진 시간에 보고서 전달, 팀원에게 정보 공유 등 테스크를 자동으로 실행하는 기능이다 (유료 사용자 대상).
2.  **예약 작업 생성**:
    *   '새 작업'을 눌러 '데일리 AI'와 같은 작업을 생성한다.
    *   프롬프트는 "매일 새로운 AI 소식을 요약해서 알려 줘"로 설정한다.
    *   빈도는 '매일 아침 9시'로 설정한다.
3.  **예약 작업 테스트**: 생성된 작업을 테스트 실행하면 매일 AI 뉴스를 받아볼 수 있다.
    *   해외 및 국내 주요 AI 소식을 제공하며, 브리핑 뉴스, 보고서 제작, Slack 알림 자동화 등에 활용 가능하다.
4.  **커넥터와 연동한 예약 작업**:
    *   "내일 아침 9시에 새로운 AI 소식을 뉴스레터로 만들어서 나에게 Slack으로 보내 줘"와 같이 커넥터와 스킬을 연동하여 예약할 수 있다.
    *   Slack 연결이 필요하며, DM 또는 특정 채널로 수신하도록 설정할 수 있다.
    *   예약된 작업은 백그라운드에서 실행되어 매일 아침 Slack DM으로 AI 뉴스레터를 받아볼 수 있다.
    *   이는 일상 작업의 상당 부분을 자동화할 수 있는 강력한 기능이다.

### 1.8. 스킬(Skill) 활용: 반복 작업 모듈화
1.  **스킬의 개념**: 클로드 코드와 동일하게 반복적으로 사용하는 특정 작업을 하나의 도구로 묶는 것이다.
    *   묶음으로 쓰는 워크플로우를 자동으로 생성하여 커맨드 입력 하나로 실행할 수 있다.
2.  **스킬의 필요성**: AI는 매번 다른 결과를 줄 수 있어 일관된 품질 보장이 어렵지만, 스킬은 반복 작업을 모듈화하여 지식 패키지로 추가함으로써 일관된 결과물을 제공한다.
3.  **스킬 제작 예시**:
    *   "특정 URL을 넣으면 뉴스레터와 링크드인, 쓰레드 글을 한꺼번에 제작해 주는 스킬을 만들어 줘"라고 명령한다.
    *   출력 언어(한국어), 결과물 형태(마크다운 파일), 뉴스레터 스타일(전문적, 인사이트 중심) 등을 설정한다.
4.  **스킬 테스트 결과**:
    *   'URL2 컨텐트'라는 이름의 스킬이 완성되었다.
    *   URL 하나를 입력하면 뉴스레터, 링크드인 포스트, 쓰레드 글이 한국어로 동시에 생성된다.
    *   유튜브 URL의 경우 자막 추출 후 변환도 가능하다.
    *   결과물은 튜닝이 필요할 수 있으나, 명령을 잘 따른다.

### 1.9. 플러그인(Plugin) 제작: 종합 자동화 패키지
1.  **플러그인의 개념**: 스킬, 커넥터, 에이전트 등을 한데 묶은 자동화의 집합체이다.
    *   커넥터와 스킬을 동시에 사용하고 싶을 때 플러그인을 활용한다.
2.  **플러그인 관리 및 탐색**:
    *   플러그인 관리 화면에서 다운로드 받은 플러그인의 상세 속성을 볼 수 있다.
    *   '플러그인 탐색'을 통해 Anthropic에서 제공하는 공식 플러그인들을 확인할 수 있다.
    *   CS, 데이터 분석, 금융, 법무, 마케팅 등 다양한 분야에서 활용될 수 있다.
3.  **플러그인 제작 예시**:
    *   "URL 하나를 넣으면 슬랙과 노션에 자동으로 저장되고, 뉴스레터, 블로그, 링크드인, 쓰레드 등으로 한꺼번에 콘텐츠가 제작되는 형태로 제공하고 싶어"라고 명령한다.
    *   '리퍼포즈' 커맨드와 '디스트리뷰트' 커맨드가 생성된다.
4.  **플러그인 실행 및 결과**:
    *   생성된 플러그인을 사용하여 URL을 입력하면 콘텐츠가 제작된다.
    *   블로그 포스트, 링크드인 포스트, 쓰레드/X 포스트, 뉴스레터 등이 생성된다.
    *   생성된 콘텐츠를 '디스트리뷰트' 커맨드를 통해 슬랙이나 Gmail 등으로 전송할 수 있다.
    *   하나의 플러그인으로 여러 채널에 콘텐츠가 전송되는 것을 확인할 수 있다.
    *   피그마 등과 연동하면 슬라이드, PPT, Google 프레젠테이션 등 다양한 형태의 결과물 생성이 가능하다.

### 1.10. 마무리 및 향후 계획
1.  클로드 코워크는 파일 통제뿐만 아니라 스킬, 플러그인 형태로 자신만의 워크플로우를 설정하여 반복 작업을 자동화할 수 있는 최고의 도구이다.
2.  향후 시리즈로 일주일 전체를 자동화하는 내용도 다룰 예정이다.

## Source 4: AI 기반 업무 자동화: 바이브 코딩, 클로드 코워크 활용 전략

##### 📌 바이브 코딩에 최적화된 핵심 기술 스택 조합은 무엇인가?
> 프론트엔드는 <mark>넥스트 JS + 타입스크립트</mark>, 백엔드는 <mark>패스트 API + 파이덴틱</mark> 조합이 가장 효율적입니다.

##### 💡 이 조합이 바이브 코딩에 유리한 이유는?
- **넥스트 JS:** AI 학습 데이터가 풍부하고, 타입스크립트와 결합 시 AI가 코드를 정확히 이해합니다.
- **패스트 API:** 코드량이 적어 AI 컨텍스트 윈도우 관리에 유리하며, 파이썬 기반 AI 에이전트 생태계와 연동이 쉽습니다.

---

AI를 활용한 '바이브 코딩'의 효율을 극대화하고 싶다면, **AI가 가장 잘 이해하고 학습한 기술 스택**을 선택해야 합니다. 1년간의 삽질 끝에 증명된 최적의 조합인 **Next.js와 FastAPI에 '타입 힌트'를 빡세게 적용**하는 구체적인 방법을 알려드립니다. 이 조합을 모르면 AI에게 오히려 시간을 낭비하게 되니, 개발 속도를 10배 높일 실용적인 가이드로 활용하세요.

## 1. 바이브 코딩을 위한 최적의 기술 스택
<mark>AI 기반의 '바이브 코딩' 효율을 극대화하려면 AI가 가장 잘 학습한 기술 스택인 Next.js와 FastAPI에 타입 힌트를 적용해야 한다.</mark>
### 1.1. 바이브 코딩의 정의와 전제 조건
1. **바이브 코딩**은 코드를 직접 치는 대신 AI에게 요구하여 결과를 보면서 개발하는 방식이다.
2. 이는 단순히 ChatGPT를 복사 붙여넣기 하는 것과 다르며, **AI 에이전트**가 코드 베이스 전체를 이해하고 파일을 생성/수정하는 것을 의미한다.
3. 바이브 코딩은 아무 기술 스택에서나 잘 되는 것이 아니며, 성공을 위해서는 세 가지 조건이 필요하다.
   1. **AI가 잘 아는 프레임워크**를 사용해야 한다.
   2. **AI가 읽기 좋은 코드 구조**여야 한다.
   3. **핵심 코드가 컨텍스트 윈도우 안에 모두 포함**되어야 한다.
4. 이 조건을 무시하고 아무 스택이나 사용하면 바이브 코딩이 아니라 AI에게 삽질을 시키는 것이 된다.

### 1.2. 프론트엔드 최적 스택: Next.js
1. 프론트엔드 최적 스택은 **Next.js**이며, 고민할 필요가 없다.
2. 이는 **AI가 학습한 코드량**이 가장 많기 때문이다.
   1. Next.js는 2025년 스택 오버플로우 설문에서 웹 프레임워크 4위를 차지했으며, 월마트, 애플 등 18,000개 이상의 기업에서 사용 중이다.
   2. 이는 인터넷에 Next.js 코드가 넘쳐나 AI의 학습량이 압도적임을 의미한다.
   3. 리액트 생태계에서 렌더링 프레임워크 중 1위이며, AI에게 요청 시 바로 동작하는 코드를 생성할 가능성이 높다.
3. **타입이 있는 언어**에서 AI가 훨씬 강점을 보인다.
   1. 타입이 없으면 AI는 변수의 타입을 추론해야 하므로 코드가 부정확해진다.
   2. 타입이 있으면 AI는 함수 시그니처만 보고 확신을 가지고 코드를 작성하여 에러가 적다.
   3. 바이브 코딩 관점에서 **TypeScript**는 AI에게 지도를 주는 것과 같으며, 타입이 곧 문서이자 가이드 역할을 한다.
4. 결론적으로 **Next.js + TypeScript** 조합이 프론트엔드에서 최강이다.

### 1.3. 백엔드 스택 비교 및 FastAPI 선정 이유
1. **스프링부트**는 레퍼런스가 많고 안정적이지만, 바이브 코딩에서는 치명적인 약점이 있다.
   1. **코드량이 너무 많아** AI의 컨텍스트 윈도우가 자주 터진다.
   2. 같은 기능을 구현할 때 Next.js 대비 5주가 걸리는 등 생산성이 떨어진다.
   3. 배포 과정(도커 이미지 크기, 빌드 시간)도 복잡하고 오래 걸린다.
2. **루비 온 레일즈**는 코드량이 적고 파일 구조가 깔끔하지만, AI 에이전트 생태계에서 불리하다.
   1. 파이썬(LangChain, LangGraph)이나 TypeScript(Vercel Agent SDK) 진영과 달리, 루비에는 AI 에이전트 관련 라이브러리가 거의 없어 직접 구현해야 한다.
3. **TypeScript 백엔드**는 풀스택 통일 측면에서 유리하지만, ORM 생태계가 미성숙하다.
   1. **TypeORM**은 마이그레이션 시 대참사가 있었고 커뮤니티 지원이 부족했다.
   2. **Prisma**는 겉보기엔 좋으나, 실무에서 커넥션 풀 관리나 소프트/캐스케이드 딜리트 기능에 문제가 발생했다.
4. 최종 결론은 **파이썬의 FastAPI**이다.
   1. **코드량이 적어** AI가 전체 코드를 이해하기 쉽고 컨텍스트 윈도우 관리에 유리하다.
      * 장고로 3일 걸릴 작업을 6시간 만에 만들 수 있다.
   2. **성능이 우수**하다.
      * 벤치마크 기준 초당 15,000~20,000 요청 처리로, Flask(2,000~3,000 요청) 대비 5~10배 빠르다.
      * Node.js와 비교해도 I/O 바운드 작업에서 비슷한 수준의 처리량을 보인다.
   3. **배포가 매우 쉽다**.
      * 스프링부트처럼 무거운 파일 빌드 없이 유니콘 하나로 서버를 띄울 수 있다.
   4. **AI 에이전트 프레임워크가 대부분 파이썬 기반**이다.
      * LangChain, CrewAI 등 주요 프레임워크가 파이썬 중심이므로 백엔드에 AI 기능을 붙이려면 파이썬이 필수적이다.
5. TypeScript 진영을 사용하려면 Vercel Agent SDK를 고려할 수 있다.

## 2. FastAPI 사용 시 핵심 주의사항: 타입 힌트
<mark>FastAPI를 사용하더라도 파이썬에서 **타입 힌트**를 빡세게 적용하지 않으면 AI가 헤매게 되어 바이브 코딩 효율이 떨어진다.</mark>
### 2.1. 타입 힌트의 중요성
1. 파이썬은 타입 힌트가 선택 사항이지만, 이를 적용하지 않으면 AI가 함수의 입력과 출력을 추론해야 한다.
2. 타입이 없으면 AI는 딕셔너리(dict) 데이터를 받았을 때 내용물을 추측해야 한다.
3. 타입 힌트(예: `name: str, email: str, age: int`)를 사용하면 AI는 데이터 구조를 즉시 이해하고 확신을 가지고 코드를 짠다.
4. FastAPI는 **Pydantic** 라이브러리와 매우 잘 통합되어 요청 바디를 Pydantic 모델로 정의하면 자동 검증 및 API 문서 생성이 가능하다.
5. 바이브 코딩에서 타입은 AI에게 주는 **설명서**와 같으므로, 설명서가 좋을수록 AI의 작업 효율이 높아진다.

### 2.2. 최적 스택 세팅 방법 및 규율
1. **프론트엔드 세팅**: **Next.js + TypeScript**를 사용하며, `create-next-app` 실행 시 TypeScript 템플릿을 선택하면 기본 설정이 완료된다.
2. **백엔드 세팅**: **FastAPI + Pydantic + SQLModel 또는 SQLAlchemy**를 사용한다.
   1. **SQLModel**은 FastAPI 개발자가 만든 ORM으로, Pydantic과 통합되어 API 모델과 DB 모델을 타입 하나로 관리할 수 있다.
   2. AI 에이전트 연동 시 LangChain이나 LangGraph보다 Pydantic 연동 예제가 많아 편리하다.
3. **필수 규율**: **모든 모델의 타입을 빡세게 지정**해야 한다.
   1. 함수 파라미터와 리턴 타입에 타입 힌트를 달고, Pydantic 모델로 데이터 구조를 정의해야 한다.
   2. 이 규율을 지키지 않으면 바이브 코딩 효율이 절반 이하로 떨어진다.

## 3. 최종 요약 및 이벤트 안내
1. **최종 권장 조합**은 다음과 같다.
   1. 프론트엔드는 **Next.js**를 사용한다.
   2. 백엔드는 **FastAPI**를 사용한다.
   3. 파이썬을 사용하며 **타입을 굉장히 빡세게** 적용한다.
2. 바이브 코딩은 도구가 절반을 차지하며, 맞는 도구는 AI의 성능을 10배 높이지만, 안 맞는 도구는 오히려 개발 속도를 저해한다.
3. 구독자 이벤트로 댓글에 "전자책"을 남기면 **클로드 코드 완전 정복 가이드** 전자책을 제공한다.
